# 飞书机器人接入

飞书与企业微信共用一个渠道网关，由独立适配器处理平台差异。飞书只使用官方 SDK 的 WebSocket 长连接，服务器主动连接飞书，无需给机器人配置公网消息回调地址。服务器仍需能访问飞书的 HTTPS 和 WebSocket 服务；平台网关的登录白名单不参与飞书入站消息传输。

## 创建渠道

在 Console 的渠道页点击新建，下拉选择「飞书」，选择关联的 Agent 和会话用户。支持两种方式：

- **扫码创建**：由服务端调用飞书官方应用注册流程，展示飞书授权二维码。使用具备相应权限的飞书账号扫码，完成后保存渠道。App Secret 只在服务端接收和保存，查询接口不会返回原文。二维码不是分享给任意聊天用户的机器人入口。
- **手动关联**：在飞书开放平台创建企业自建应用、开启机器人能力，填写 App ID 和 App Secret。配置消息接收事件为长连接，并完成权限申请、版本发布和可用范围设置。

扫码并不绕过企业管理员审批、应用可用范围或发布要求。权限不足或应用尚未发布时，仍需在飞书管理侧完成配置。本轮不支持商店应用多租户安装、Lark 国际版和 HTTP 回调模式。

新二维码直接使用飞书 PersonalAgent 默认应用模板，预填应用名称，并增量申请应用身份权限 `contact:user.base:readonly`（获取用户基本信息），用于解析发送者姓名；不附加其他自定义权限、事件或描述。默认清单由飞书服务端维护；已添加的事件不代表所需权限已经获批。此配置不自动更新已有应用，也不代表已实现默认模板包含的所有业务能力。

扫码任务保存在当前 API 进程，最长保留十分钟；过期、取消、保存成功或进程关闭会清除临时凭据。仍沿用单 API worker、单渠道网关的部署约束，不需要新的任务表。未保存的扫码任务不跨进程重启恢复，重新扫码即可。授权成功后仍受有效期约束，页面到期会提示重新生成；重新生成先取消旧任务，再申请新二维码。

## 消息和身份

私聊按发送人区分会话，群聊按群区分会话；群内不同发送人共享该群的历史，各条消息保留独立发送人 ID。群聊要求明确 @ 机器人。群访问可通过 `settings.feishu.group_allowlist` 限制，空列表表示应用可见的群；这不扩大飞书应用自身的可用范围。

飞书的 open_id 用于稳定区分发送人。扩展设置「查询用户详情」默认关闭，保存并主动开启后，使用当前应用查询姓名，无需另外关联应用。已保存账户可点击「检测权限」读取应用身份的 `contact:user.base:readonly` 授权状态；检测不申请权限，也不实际查询某位用户。还需在飞书后台确认通讯录数据范围并发布生效。

聊天入站、渠道用户列表、详情与姓名搜索使用统一资料服务。飞书缓存位于同账号 SDK worker 内，成功姓名不按时间过期，最多 2,000 条，超出后淘汰最久未使用项；重启、凭据变更或 worker 重建后按需批量补查。不建立额外姓名表或 API 侧缓存。关闭查询、网关不可用或未取得姓名时显示原始 ID，不用 Runs／历史上下文中的旧姓名兜底。

统计仍从数据库按 ID 计算。普通列表只补当前页姓名，最多等待 3 秒；姓名搜索先对当前渠道、时间及筛选范围的全部候选用户解析资料，再匹配及分页，最多等待 10 秒。缺失资料时显示结果不完整并允许重试；不开查询只搜 ID。不会拉取整个企业通讯录，也不会更新历史正文。姓名只辅助展示，不替代 DeepFOS 的执行账号和权限。

消息记录分别保存 sender_id、sender_name、tenant_id、thread_id；已有会话绑定表继续记录私聊／群聊类型和来源。原始群与私聊会话不混用。

数据库 008 的四列是共用来源字段，不使用渠道前缀：

| 字段 | 共用含义 | 当前企微 | 当前飞书 |
| --- | --- | --- | --- |
| sender_name | 当前消息发送人姓名 | 关联应用查询成功后写入当轮姓名快照 | SDK 返回的姓名，无权限时为空 |
| tenant_id | 来源平台的企业／租户标识，不是 DeepFOS 租户 | 资料查询验证关联应用后记录其企业 ID；没有可信结果时留空 | 事件 tenant_key |
| thread_id | 来源平台的话题／线程标识 | 当前机器人消息不提供，留空 | SDK conversation.thread_id |
| source_metadata | 渠道特有的扩展来源事实 | wecom_application_id、wecom_userid（已确认的应用与成员映射） | lark_user_id、lark_union_id、lark_chat_id、lark_chat_type、lark_parent_id、lark_root_id、lark_sender_type |

只有渠道专属字段使用 `wecom_` / `lark_` 前缀，当前飞书专属内容写在 source_metadata 的 `lark_*` 键中，不新增重复列。公共列可以由后续适配器复用；当前企微缺失值不猜测、不伪造。以上字段仅用于来源追踪，不授予权限。

DeepFOS 应用及 API Key 的关联规则与企微相同。飞书凭据只用于飞书通信，不是访问财务数据的授权。业务执行继续使用渠道配置的 Agent、会话用户和已有 DeepFOS 权限链路。

## Agent 发送消息与附件

可信飞书渠道对话自动加载内置 `channel_message`，无需给 Agent 配置发送用 MCP。支持向本轮私聊或群发送文字、图片、文件，以及符合格式的已有音频、视频；不适合原生音视频展示的内容按普通文件发送。工具可以引用本轮消息并继承当前话题，不支持自行指定其他人或群。

媒体引用已授权的 `file_id`，可来自会话附件或沙箱生成文件；上传和 image_key/file_key 由适配器处理。生成文件仍需要 Agent 拥有相应生成能力，Message 本身不负责图片生成、语音识别或转码。图片和文件作为独立消息发送，普通回答继续使用原有流式卡片。

v0.14.8：也可用公开HTTP(S) `url`原样发送媒体，与`file_id`二选一；不落平台文件。
可信渠道Run启用PTC后可在`run_code`内调用同一`channel_message`；原生入口、会话目标和格式限制不变。

原生音视频现在通过公共媒体处理读取真实时长，并在官方文件上传接口传入 `duration`（毫秒）；视频额外提取首帧、上传图片，并在 media 消息中传入 `image_key`。高层 SDK 的 `upload_media()` 未暴露时长参数，因此音视频使用同一客户端的公开文件上传接口，不修改 SDK。网关需安装 FFmpeg/ffprobe，仅发送音视频时按需启动，普通文件不触发媒体解析。缺依赖或解析失败会明确报错，不伪造时长或空封面。历史已发送消息不回填。

多个内容按顺序投递。结果包含逐项成功／失败／未知状态，消息 ID 只在平台确认后返回；权限不足或结果未知不自动重发。普通 Console 对话和历史浏览不会因为 Agent 绑定了飞书而获得该工具。

本地测试租户已验证私聊和群聊图片／文件、原生音视频、引用及双渠道并发；真正话题内入站仍待租户补验。其他企业仍需验证自身权限，不能把本地结果视为所有应用权限已开通。

## 连接和运行

复用[渠道网关部署说明](wecom-channel.md)的 API＋Gateway 启动方式，同一网关可以同时运行企微和飞书适配器。

飞书连接测试只验证应用凭据和机器人能力，不另开一条收消息的 WebSocket，避免测试连接分走正在运行的消息。凭据验证成功不等于消息事件、群 @、附件与卡片权限均已完成，实际租户仍应逐项验证。

采用官方 `lark-channel-sdk` 和 `lark-oapi`，不自行实现飞书 WebSocket 协议。SDK 内部使用模块级长连接事件循环，网关为每个飞书账号启动受控 SDK 子进程，通过匿名管道通信，避免停用一个账号影响其他账号。子进程不对外监听端口，不是另一套渠道网关；业务调度、权限和数据库仍由原网关统一负责。SDK 的接收确认发生在异步处理入队阶段，因此进程恰好在 SDK 确认后、数据库接收记录写入前退出时存在短暂丢消息窗口。持久化消息 ID 用于业务去重，但不宣称传输严格一次投递。

## 数据库与回退

当前数据库 Head 为 010。经用户单独确认，009→010 删除 channel_message_operations 及其中发送回执，并增加 chat_sessions.source_type/source_id 两列；历史空来源按内部读取，见 [会话来源](session-sources.md)；008 的 channel_message_runs 来源字段、原有渠道配置、会话绑定、消息与附件不变。保留已发布 009 迁移，通过正常增量升级处理已部署环境；升级前备份数据库，API 完成升级后再启动新网关。

Message 不再维护独立发送记录，也不新增 Runs 字段或缓存替代；仅返回本次调用的逐项结果，不承诺跨请求、跨重启发送去重。

删除的旧回执不能通过代码回退恢复；不要把代码回退等同于数据库降级。已有飞书账号或新来源数据时，008→007 会拒绝降级，必须先明确处理相应配置与数据，不能为了降级静默丢弃。

## 验收边界

无需真实账号即可验证注册成功／拒绝／过期／取消、凭据保护、配置 CRUD、SDK 消息映射、持久化去重、群内多发送人、企微回归及 Console 操作。

真实账号仍需完成：扫码授权与企业审批、应用发布、私聊收发、群 @、断线重连、附件下载、卡片权限及频率限制、姓名读取权限。受控测试不代替这些租户验收。

## 扫码二维码与应用预填

先填写渠道名称再生成二维码，会将该次名称作为 `app_preset.name` 预填至飞书创建页；留空时使用 DeepAgent。名称按生成时快照生效，后续修改本地渠道名称不会重命名已经授权的飞书应用。

二维码编码飞书注册授权链接，使用 PersonalAgent 默认模板，附带本次应用名称预填与 `contact:user.base:readonly` 权限增量；不关闭默认模板，不附加其他权限、事件或描述。二维码不包含 App Secret，服务端在用户确认后轮询取得凭据。

默认权限与事件清单由飞书服务端维护，实际授权仍受应用发布、审批和可用范围约束；生成二维码不代表所有平台能力均已接入 DeepAgent。

依据：`services/feishu_registration.py` 与官方 [注册文档](https://github.com/larksuite/oapi-sdk-python/blob/v2_main/_autodocs/api-reference/registration.md)。
