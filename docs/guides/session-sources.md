# 会话创建来源

`chat_sessions.source_type/source_id` 是会话来源的唯一事实源。来源只在创建时写入，不因控制台续问、渠道改名、停用、解绑或删除而改变。

| 来源 | source_type | source_id |
| --- | --- | --- |
| Console / 普通 API | internal | NULL |
| 企微 | channel:wecom | 渠道账户 ID |
| 飞书 | channel:feishu | 渠道账户 ID |
| 钉钉 | channel:dingtalk | 渠道账户 ID |

`source_id` 表示来源实例，不预设未来所有来源都是渠道账户。旧记录的 NULL 来源读取为 internal，不自动识别历史、修改标题或写回数据库。普通客户端不能指定渠道来源。来源不授予消息发送或会话访问权限；可信网关、活动 Run、绑定和文件授权仍分别校验。

## 查询和统计

会话来源筛选先从主表确定范围，再从 Events 统计提问及模型请求。Runs 只补真实发送者；Binding 只指向当前路由会话。结构化创建事件可补充群/私聊对象，但不能反推来源类型。

渠道会话在 Console 续问也计入该渠道、群和会话的提问与用量；没有真实渠道发送者时列入“无渠道发送者”，不计入成员排名和渠道活跃用户。提问时间取 user/message Event，范围为 `[start,end)`。成员身份按渠道账号和稳定 ID，姓名使用当前统一资料服务，不读取历史姓名兜底。全站用户统计仍为平台用户。

普通列表先分页补姓名；姓名搜索在范围内全部候选 ID 解析后匹配分页。资料失败不改变统计数字。账户删除后保留主表来源和来源 ID，显示“账户已删除”。会话标题按存储事实显示，不根据来源或姓名重新拼接。

会话列表、详情、诊断和用量会话明细返回 `source_type/source_id`。适用查询支持同名筛选；原渠道专用 URL 继续使用 account_id 参数，内部映射到主表来源。无来源筛选的全站提问、请求和 Token 总数不受本次变更影响。

## 数据库 010

本次经明确确认，将两个可空列 `source_type VARCHAR(64)`、`source_id VARCHAR(255)` 合并到尚未发布的 010；不新增 011、表、索引或外键。010 原有删除独立回执表的行为保留。

009 正常升级执行新 010。已是旧 010 的开发库，在迁移入口检查物理结构并只补缺失列；结构不符时报错，不重建表、不修改版本标记。历史来源不回填，不改会话更新时间。同 Revision 不代表结构一致，配置备份/导入同时检查列结构。

本地和 Test 历史修复是项目外一次性操作，**不提供产品维护命令、不嵌入迁移和查询**。先预览有证据的记录，备份并停止写入后显式执行；只改空来源字段，保留历史正文、标题和时间戳。有歧义跳过。Test 在发布后另行安排，客户和 Alpha 无需该历史修复。

部署前备份物理数据库并停止旧 API/网关，再迁移并共同启动配套版本。生产 DDL 的锁与时长依数据库版本和数据规模评估，不以本地 SQLite 速度代替。010 删除过回执，不能无损降级；恢复需迁移前备份及匹配代码。
