# 三供应商文档可读格式适配与回归

日期：2026-10-03。本轮交付版本v0.12.10。格式适配和分页回归通过；MinerU本轮在线解析仍超时，按用户最新决定在Console置灰禁选后发布。真实金额映射存在模型波动，不能写成金额填报全部通过。

## 实现及边界

保持一个 `parse_document`，参数、返回字段、授权方式、供应商接口和配置不变。三家各自的协议适配器仍先生成原生 `ParsedDocument`，再由 `documents/adaptation.py` 生成固定模型可读投影。流程是：

```text
原生响应与下载产物 → 原生页面 → 整页格式适配一次
→ Run 缓存 readable.pages → Token 计量 → 24K/48K分页 → 工具返回
```

供应商原始响应、原生页面及布局信息留在私有缓存，模型不同时收到正文和同一正文的布局 JSON。分页只读取 `readable.pages`：先适配再计算预算，`char_offset/char_end/next_read` 全部指向固定适配内容。续读不会再次转换，也不会在切片后补写 Markdown 标记。原始页码、未知页边界、缺页和解析状态始终来自原生结果。

| 情形 | 实际处理 |
| --- | --- |
| 原有正文、Markdown、公式、链接、图片引用 | 保留文字和顺序；代码块、行内代码及转义标签受保护 |
| 矩形普通 HTML 表格 | 可可靠表示且不增加估算 Token 时转 Markdown，保留全部数据行、空单元格、换行、实体和字面标记 |
| 原生表头 | 仅第一行全为 `th` 时使用；没有表头则增加空标题行，不猜测第一行数据的角色 |
| 合并、嵌套、混合表头、行标题、脚注 | 保留紧凑 HTML 和 `rowspan/colspan`，不扁平化关系 |
| 链接、语义属性、强调、首尾空白或不能可靠表示的单元格 | 保留精简 HTML，避免 Markdown 渲染改变原义 |
| 展示属性 | 删除 style/class、尺寸、边框、对齐、间距等明确展示属性；保留语义属性 |
| 异常、未知片段 | 局部原样保留并计数；不让局部格式错误使整份文档失败 |
| 内嵌图片 | 不向模型返回 Base64，保留明确占位与原有说明；原数据仍在缓存，不增加图片下载或识别能力 |

不去重 OCR 正文，不补齐空白，不纠正日期、金额或识别错误，不增加租赁专用规则。没有新工具、配置、环境变量或数据库结构。CPU 适配在工作线程执行；取消会通知并等待本地适配工作结束，再释放 Run 缓存。同文件并发仍合并为一次解析和适配。

日志记录适配版本、耗时、表格/紧凑 HTML/Markdown/局部原样保留数量、前后字符及正文估算 Token；分页另记完整返回包装的 Token。适配统计使用事件专属白名单，保留原日志 8192 字节上限及会话、Run、调用关联，避免扩充字段使其他生命周期日志被丢弃。日志不记录正文、原生响应、Key、Base64 或签名地址。

已在回归中修复混合 `thead` 内 `th/td` 被统一升级、HTML 字面标记意外取得 Markdown 角色、相邻/嵌套强调分隔符粘连、GFM首尾空白被裁剪、未知未闭合声明触发解析断言等问题。无法可靠转 Markdown 的表格保留紧凑 HTML，节省 Token 不以损失内容为代价。最终离线重放标记 `offline-replay-v5`，全部480页正文Hash与v4相同，因此最终v4实际Agent轨迹仍与当前输入逐字符一致，无需再发模型请求。

## 实际 Agent 与租赁映射

使用本地已配置同一 `deepseek-flash`、1M窗口、48K读取预算及租赁 Demo 阶段提示词/Schema快照。相同固定参数，金标准只用于事后评判，不发送给模型。没有业务写入，不修改 Demo 或真实会话。

早期 A/B 共33运行、97模型请求：包含三家31页及6页原生/适配 core/rent、46页生产HTTP路径及复测、合法55+6配对。原始轨迹保留。后续实体和字面标记转义修复改变24页，早期 Agent 输入不能冒充最终正文。最终格式另做10运行、32请求、26工具调用，全部逐页 SHA 与最终适配产物匹配、逐字符全文覆盖通过。

| 最终格式场景 | 读取与业务检查 | 判断 |
| --- | --- | --- |
| 三家31页 core/rent，六阶段 | 全文覆盖；选定字段合63/63 | 本轮选定字段通过，不代表全文OCR准确率 |
| Paddle6页 rent | 一次读全；9/9映射槽位 | 本轮通过，但早期三次适配均漏结束日期，原生两次复测也漏；保留波动证据 |

46页原生首次 A/B 读7次仍跳过第23页尾部16,472字符，后续完整复测读6次；适配正文两次完整读取。首次原生输入714,070/输出2,690 Token，早期适配输入163,277/输出1,909 Token；这个对比含多轮上下文，且原生首次漏读，不能当作公平的全文成本基准。完整重放基准是 **48K六读→两读、实际分批返回231,797→81,672 Token**。

租金映射的年/月金额和结束日期差异属于独立业务风险。46页合同四档年/月金额均保留在原生及最终第3页，该页与早期实际工具返回Hash相同且被完整读到，不能归因为适配丢值。OCR事实、适配内容是否保留、模型提取和业务映射分别核对；不在产品适配器中猜测或修正金额，也不擦除失败输出。最终10运行输入802,045、输出20,254，共822,299 Token；早期33运行共2,781,628 Token，独立列示。
