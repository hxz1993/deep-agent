## L2 · 消除渲染瑕疵

```text
Use case: ui-mockup
Template: UI Screenshot System / UI 截图系统 (ui-screenshot-system; case 17, case 2, case 4).
生成一张精细、可落地的 DeepAgent 中文企业控制台设计效果图。真正的高保真网页 UI 截图，不是草图或海报。单张完整桌面屏幕，16:10 横向构图，高分辨率，平视无透视，无浏览器地址栏、无电脑边框、无外部题注。优先清晰准确的中文与数字字体，小文本也要锐利。逻辑视口约 1600×1000，视觉输出可放大。
共享产品外壳：左侧只有一条 176px 宽浅灰主导航，顶部简洁机器人线性图标和 DeepAgent。项目菜单“对话测试”“Agent”，设置分组含“Provider”“Skill”“MCP”“渠道”，底部区域分组标题“诊断中心”，下面两个同层级菜单“日志”“会话”，两者是独立入口，不能再有第三个“统计”或“排查”入口，也不能增加第二侧栏。底部小头像“管理员”。页面上角小标记“示例数据”。
视觉系统：适合长期工作的现代企业开发控制台，精致而克制。白色主表面，极浅灰导航，灰黑正文，淡灰细分隔，蓝紫 #635BFF 为选择与链接，绿色仅表示完成，橙色表示等待，红色表示失败。7px 控件圆角，32px 高紧凑控件，16px Lucide风格线性图标。页标题不超过20px，无巨大数字、无大面积饱和色或渐变、无拟物玻璃、无3D、无装饰插图。除可选择条目外不层层套卡片。图表轴、标签、数值必须严谨精细。
所有人物、会话与日志是虚构样例，绝不使用真实账号、凭证或真实长ID。跨用户诊断仅管理员只读。无新增、编辑、删除、发送、停止别人会话、重试执行、自动诊断按钮。手动刷新、搜索、筛选、复制ID与只读跳转可以出现。底部小字可用“示例数据 · 仅供设计评审”。不要将完成率称为答案正确率或满意度。
日志功能约束：主体是高密度的内容行，行高约28px，每行一条简短实际日志摘要，不能画成大表格，禁止表头网格、单元格边框或每条大卡片。时间小且灰，摘要是视觉主角；级别 INFO/WARN/ERROR、来源 API/网关、阶段 模型/工具/投递 作为小型胶囊。普通行无背景，仅悬停/选中行极淡紫。过滤器包括“最近24小时”“全部来源”“全部级别”、关键词输入“搜索日志内容”，可展开 Session ID、Run ID 精确筛选。“查询”“刷新”简洁按钮。不画下载或实时连接。右侧打开约340px宽的抽屉/检查器，无遮罩，左侧日志仍可读；包含安全长原因、字段名值、可复制Session/Run、关联会话入口。运行日志与会话事件是不同事实：可出现执行开始/结束的运行日志，但绝不展示无意义保存条数的RUN回执。不得记录提问正文、模型思考、完整工具参数结果、token、堆栈局部变量。一个选中错误的安全信息可写“模型连接超时”“等待60秒后连接结束”“provider_timeout”，这是失败说明不是自动推断。页底可显示“已加载200条 · 当前实例”，不是每行的辅助事件。
示例日志摘要可自然重复形成24条左右紧凑真实行：“收到渠道消息”“消息已分发至企微助手”“开始模型请求”“模型请求完成 · 1.8秒”“开始调用 docs_search”“docs_search 完成 · 842毫秒”“开始调用 docs_read”“工具仍在等待 · 30秒”“docs_read 完成 · 1.3秒”“最终答案投递完成”“等待用户在控制台操作”“模型请求失败：连接超时”。关联示例统一 Session s-demo-1024、Run r-demo-0816；会话名称“月度费用变动分析”，用户“林同学”，Agent“DeepCube助手”。
本张主题 L2，白底最简文字流日志页，极高坪效，导航“日志”选中。设计区别：顶栏标题与最近24小时筛选同一行，第二行一个较宽关键词搜索框，与来源和级别筛选横向合并；没有统计卡和大标题空间。主体宽幅日志流，时间窄列，摘要排在最前最清晰，来源与阶段胶囊贴在摘要末尾，级别仅小胶囊。每行逻辑高24px，显示约30行，不画垂直边界或背景条纹。让同一行信息像开发IDE输出但保持漂亮中文。右侧280px窄抽屉打开，显示选中的长时间等待日志。标题“等待详情”，小橙色“WARN”“工具”，主要正文“文档读取仍在等待，已持续30秒”，注释“仅记录等待时长，不判定卡死”。紧凑竖排字段，底部并列两个小链接“同 Run 日志”“查看会话”。顶部范围胶囊“来源 API ×”“阶段 工具 ×”，能够感受过滤后的密集内容而非传统表格。最下面范围提示“已加载200条 · 可继续查询”。
输出必须是完整、不透明、干净的白底页面截图，所有背景为实色，不能带透明通道效果、黑色破洞、噪点、蓝色斑点、局部未绘制、损坏像素或扫描纹理。保证全部像素完成渲染。
```

## L3 · 局部校准

```text
这是UI截图局部校正，不重新设计。保留原图布局、字体、白底、导航、紧凑行高、颜色、右侧关联抽屉、中文标签与16:10比例完全不变。只修改日志流的示例时间和末尾内容，确保单次Run终止后没有继续执行：将中部模型连接超时的红色ERROR行移到全部日志最末尾，时间10:19:10；其他所有正常模型/工具/渠道步骤均发生在它之前。删除“已记录错误信息”“运行记录已保存”“重新开始模型请求”和“最终答案投递完成”这些行，用发生在失败之前的“开始模型请求”“模型请求仍在等待 · 30秒”“docs_search 完成 · 781毫秒”“docs_read 完成 · 1.2秒”等安全事实替代。单次Run最后一行只能是模型请求失败，后面无继续执行或成功。右侧错误发生时间同步10:19:10。不要添加任何保存数量、RUN回执、工具参数正文。其他布局像素尽量保持原样，整体不透明干净白底。
```
