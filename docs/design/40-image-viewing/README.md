# 图像查看与PDF原页核验

状态：纳入 v0.15.2。本地实现、千问主模型真实验收及自动回归完成。v0.15.1 基线（62c61ee）不含本课题实现。日期：2026-11-03。GPT连接未通过、Linux硬内存隔离未实测，单列于私有验收报告，不计为通过。

## 最终边界

- 工具固定为view_image／查看图片，归属runtime:file，支持PNG、JPEG、WebP、GIF首帧及PDF整页渲染。
- 授权附件File ID、当前Skill索引资源、已授权Web公网URL可混合查看，最多8项/8图页；PDF默认第1物理页。
- 合并旧web_image_view入口，Web包仅剩search/fetch；旧事件、原名和URL引用继续回读，不重写历史。
- 只由当前主模型视觉理解，不新增辅助视觉模型；不进入PTC。Python/Skill/PTC产物先返回File ID，再由外层查看。
- 原生图片只留当前Run，持久化/SSE/轨迹只保留轻量来源。多次查看在同Run累积；下一轮按需重新查看。
- PDF渲染采用pypdfium2==5.14.0独立子进程，限制并发/像素/字节/时间；不新增工作区、路由、配置或数据库迁移。

完整签名、限制和依赖镜像交接见[使用指南](../../guides/image-viewing.md)。验收证据另存私有local-artifacts，不提交用户PDF、业务材料或原始模型响应。

## 历史决定

早期WebImageView单独位于Web包，目的是让模型在工具循环中实际获得已安全下载和验证的图片，而不把URL当作看过图片。此前只处理公网单图，不进入PTC；当前将同一原生视觉通道扩为授权文件与PDF，并保留权限边界。2026-11-03以前使用web_image_view的设计说明按历史状态保留，当前新请求使用本课题协议。

验收必须检查实际SDK HTTP/SSE图片请求、历史轻量化、授权与下载、取消清理，以及真实浏览器中的矢量PDF、扫描PDF、战略多页、模糊材料、多来源、PTC产物和跨轮重新查看；环境失败不计为成功。
