# 电子表格助手

## 从正确的交付包开始

管理员通过Agent安装入口选择电子表格预制包，先预检，再新建隔离Agent或明确覆盖目标。核对包的提示词版本、业务Skill、UI工具和MCP引用；产品版本不是Prompt版本，也不自动升级已安装Agent。

资料基线{{DEEP_AGENT_VERSION}}预制包已同步V124及其交付资产。目标OP可能较旧，按实际目录和回读验证，不把此处版号当作目标已安装。缺MCP或模型需要补配，安装完成本身不证明业务查询可用。

## 应用专用配置

在「集成 → 电子表格助手 → 应用配置」为可管理的应用保存追加提示词和上传专用 Skill。当前会话的应用通过平台校验，且运行的是集成关联的 Agent 时，服务才追加这些内容。同一业务口径优先使用应用专用内容。

在测试工作台选择调试应用，再新建对话。用同一份模拟数据对照「不分应用」，在轨迹核对是否实际加载并读取了专用模板。加载工具使用目录里的能力 ID，例如 `app--budget001--monthly-report`，资源和脚本工具的 `skill_code` 使用 `app:budget001:monthly-report`。

## 给模型明确的表格上下文

至少提供当前工作簿/Sheet、选区范围、表头、必要单元格样本和业务目标。财务模型问数需要真实Cube、POV和维度口径，不因用户只说“这个月”自行猜模型和单位。

上下文通过业务客户端的context_refs提供。把模型需要理解的数据放payload；metadata只承载展示来源。页面范围改变时同步，普通追问不重复塞整份表格。大表按授权工具读取和确定性计算，不把截断样本当全量事实。

## 分清三类动作

1. **只读分析**：读取选区、识别列、统计、比较、解释和图表。
2. **生成建议**：提出可核验的填充、公式、映射或格式建议，保留目标范围和版本。
3. **实际写入**：经过业务要求的人工确认，由明确UI工具或业务保存执行器写入；回读被修改的真实单元格。

模型说“已完成”不证明写入。UI工具的执行结果、业务版本与回读才是证据。不要为了复现聊天错误去覆盖现有报表或更改真实数据。

## 图表与文件

当前Console可将严格JSON的g2围栏渲染为图表，默认图表、配置可切换；流式阶段不反复初始化图表。业务客户端是否有同等渲染需核验其实际版本。

Console 的 G2 5.4.8 默认主题来自预制 `deepfos-financial-charts 2.0.6` 的 `assets/theme.json`（主题版本 2.0.0）。默认分类色依次为蓝、青绿、琥珀、紫、浅蓝，复用字体、文字、背景及边框色。用户显式主题字段或图层颜色优先，不根据类别名称猜测实际/预算。图表和配置共用300px内容区；显示默认主题不改原JSON、数据、坐标或精度。

图表所用数据必须可追溯到真实查询/选区。内联数据和有限图层可以展示，不能把远程数据URL、任意回调代码或HTML放进配置以取得额外能力。图表展示不替代计算校验，关键数字、单位和时间范围应独立核对。

Python/Skill产生的正式报告需要publish_path登记、FileStore上传和真实File ID；下载后校对内容与摘要。看图用主模型视觉，PTC生成产物后在外层view_image查看，不假设PTC内部能看图。

## 推荐验收任务

- 选中一块有表头的数据，按指定口径统计并说明来源。
- 换Sheet/选区后追问，确认没有继续使用旧范围。
- 提出一份填充建议，取消确认，验证没有发生写入。
- 确认一次指定小范围写入，再读取目标单元格核对。
- 生成一张图和一个可下载报告，刷新后检查结果及附件仍可访问。

客户端源码可能是独立电子表格仓库或Planning套件内模块；按实际交付目标定位，不自动双向同步。修改UI、Prompt、Skill、平台服务是不同发布动作，分别验证已加载版本。
