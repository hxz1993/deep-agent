# GPT 订阅思考摘要批量实测

> 测试日期：2026-11-07（Asia/Shanghai）。本地只读实验，不修改产品代码、模型配置或凭据，不新建 Agent／Skill／平台会话。

## 结论

- 28 次订阅请求全部完成：2 个已配置模型 × 4 道题 × 每题 3 次，共 24 次 `auto`；另用相同代码审查题，2 个模型各 2 次 `detailed` 对照。
- 直接请求 `https://chatgpt.com/backend-api/codex/responses`，使用本地 GPT 订阅 OAuth。没有使用 OpenAI API 中转地址，也没有经过 DeepAgent Runner 或 Console。
- 6 次简单题均实报 0 reasoning tokens，公开摘要为空。18 次非简单 `auto` 请求均实报非零 reasoning tokens，摘要只有 27–131 个原始字符，主要是短标题。
- 4 次 `detailed` 对照均有 reasoning tokens，摘要仍为 0–32 字符；其中 Sol 一次 116 reasoning tokens，公开摘要为空。本批没有观察到 `detailed` 带来更丰富的过程说明。
- 流式摘要增量与最终 `output[].summary` 全部一致，仅统计时在分段间补换行；这份短内容已出现在上游完成响应中。
- 结论适用于本账号、本模型和这些题目；不能推广为所有 OpenAI 模型、所有问题或 ChatGPT 网页的呈现均相同。未获取或推断模型的完整内部推理。

## 参数与统计口径

- 模型：`gpt-6-luna`、`gpt-6.1-sol`。每个请求独立，没有前序聊天或工具。
- 默认 `reasoning={"summary":"auto"}`；显式对照仅改为 `detailed`。所有请求都省略 effort，不提高思考强度。
- 系统说明固定为“请准确、简洁地回答用户问题。”；流式、`store=false`、并发上限 3、SDK 自动重试关闭。
- 摘要长度为接口返回文字的 Python `len`，含 Markdown 标记及分段换行；不是 Token 数，也不是内部推理的可见比例。reasoning tokens 使用订阅接口实报数值。
- 只保存合成题、公开摘要、答案、用量和安全元数据；不保存 OAuth Token、账号标识、认证 Header 或加密推理内容。

## 使用的题目

### 简单算术

```text
1+1等于几？只回答一个数字。
```

### 整数约束

```text
找出所有满足条件的整数三元组：(x,y,z)都在1到9之间，x<y<z，2x+3y+5z=58，且x*y+z为偶数。请核对是否遗漏，简要给出候选、排除理由和最终结果。不要使用工具。
```

### 组合优化

```text
项目A到H的成本依次是6、4、7、3、5、8、2、4，收益依次是18、10、23、8、14、25、6、11。预算20，至少选3个项目。选C必须选D；选E必须选B；G和H不能同时选；A和F不能同时选。求收益最大的项目组合、总成本、总收益，并简要验证最优性。不要使用工具。
```

### 支付代码审查

```text
审查以下支付代码。场景：同一订单可能并发请求；客户端超时会重试；charge不支持幂等且调用超时不代表未扣款；db.save可能失败。请指出主要风险并给出可落地的最小改造伪代码，说明哪些失败只能先对账而不能盲目重试。回答控制在500字内，不使用工具。
async def settle(order_id):
    order = await db.get(order_id)
    if order.status == 'paid':
        return order.receipt
    receipt = await pay.charge(order.amount)
    await db.save(order_id, status='paid', receipt=receipt)
    return receipt
```
