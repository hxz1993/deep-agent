# 真实事件及时落库（0.8.5）

已完成的内容直接写入 `chat_session_events`，不等待整个 Run 结束。没有运行快照、保存数量或正常完成回执；不再生成 `run/progress`、`run/terminal`。

## 保存边界

| 内容 | 保存时机 |
| --- | --- |
| 用户输入 | 模型执行前 |
| 助手完整轮次 | SDK 确认完整响应后 |
| 工具调用 | 参数通过校验、调用被接受后 |
| 工具结果 | 单个工具结果确定后，不等并行工具全部结束 |
| 流式半段 | 只经 SSE 展示；停止或异常收尾尽量保存一次 |
| 标题、规划、人工操作、压缩 | 保留原有生命周期 |

每部分记录携带稳定的消息序号和部分标识，按调用 ID 关联工具结果；同一 Run 中不同轮次复用调用 ID 不合并。读取 SDK 历史时按来源归组，保持消息顺序和调用/结果关系。
正式终态只补充尚未写入的真实内容，必要的完成/中断/待操作状态更新在对应记录上。没有第二份完整运行快照。
参数未通过校验的中间纠错不保存为正式调用或孤儿结果；已接受、实际执行后要求业务重试的调用与脱敏结果属于真实事实，保留。跨轮复用调用 ID 不混淆。

会话列表的消息数仍按 SDK 消息归组，不按部分数量计数。为兼容 MySQL 5.6 等无 JSON 操作的数据库，在当前页会话中分批读取来源标识；大历史会增加列表查询 I/O，本轮不通过新增字段或表绕开这一限制。

运行锁与短数据库事务分离。写入失败终止后续执行，不能宣称落库成功，也不能自动重跑工具。已经提交的内容保留；进程强杀可能丢失尚未完成的半段或尚未收到的工具结果，不推断外部操作成功、不补造结果。

## 异常事实

真正终止执行的 Provider 错误、未捕获错误、执行超时等保存一条 `execution/error`，同一 Run 幂等。内容仅含错误分类、脱敏原因、阶段，沿用现有会话/Turn/Run 关联字段；不存凭证、完整参数、堆栈。

- 正常结束不追加事件。
- 主动停止不是异常，不新增异常事件。
- 工具失败后仍可继续：仅保存实际失败结果；若错误最终终止执行，异常说明终止原因，不重复工具结果。
- 数据库不可写时，保留错误响应和服务日志，不保证异常本身已落库。
- 异常用于历史诊断，不进入模型对话正文。

## 控制台与渠道

原页面继续接收 SSE；刷新或另一个页面打开正在执行的会话，读取 History 并通过只读 SSE 观察指定 Run，
不重新发起模型。当前进程的有界回放可补齐这轮实时内容，但不是持久化恢复承诺；无法回放时退回
History / Run Status 轮询。终态后关闭订阅，不自动跟随新一轮；切换会话取消观察请求并丢弃迟到结果。

没有 RUN 专用行或选择逻辑；异常明确显示“异常”和原因。其他消息、工具、规划、人工操作和压缩保持原展示。UI 调用在正式进入等待、完成相应持久化之后才开放操作，执行中只读。

企微公开正文按空行累计；首段前原生三个点，有正文后等待时保留进度并显示文字提示，final 全量替换为最后答案。渠道去重、投递记录和失败处理不变。

## 升级边界

版本升级前排空旧版本活动请求，避免旧进程继续写入 RUN。旧数据库行原样保留，不清库、不迁移、不解析旧 RUN 快照或恢复它们；普通历史消息继续读取。

数据库结构仍为 V2 / Alembic `002`，没有新增表或持久化系统，没有跨进程自动恢复/重跑机制。现有压缩事件的状态收尾独立保留。联合启动、环境变量和 Jenkins 流水线不变；仍按现有单 API worker 部署。
