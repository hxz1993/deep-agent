核验日期：2026-09-16。源码基线：test / a8c213a / v0.10.8。范围：DeepAgent 内置 Console、管理 API、Service/Store、安装与备份、会话操作、运行装配及迁移保护。审查的是本地当前源码，不代表线上每个实例已部署同版。

本次只读审计；未执行删除、导入、迁移、重放或生产测试。以下“确认”表示源码条件已核实；并发后果和故障场景未实测的地方单独标注。常规字段长度、JSON 类型、分页上限按类别归并，不将每个参数限制算成一个产品卡控。

## 结论

“Agent 有会话不能删除”来自应用层选用 RESTRICT 策略，不是数据库或安全权限天然要求。当前确实避免了悬空会话，但没有提供管理员确认后清理的完整流程。用户提出的“强提醒后连会话一起删”可以实现，不能只移除校验而不处理关联数据与运行中的任务。

管理 CRUD 有 **9 个删除操作、13 个关联阻断条件**：渠道 binding/run 分开计数，UI 包包含工具/被 Agent 引用分开计数。为了按产品流程阅读，下表将条件归并；加上配置初始化，共 **12 项关联/历史限制**。其他编辑、安装、导出及权限限制单列，避免统计口径混淆。

## 六、建议统一的处理原则

- 删除配置时先展示影响：对象名、关联 Agent/渠道、会话数量、运行中数量，以及“删除”“解除关联”“保留”的具体范围。
- 用户一次强确认后，由服务端完成停止执行、解除关联、删除依赖与清理缓存。不要要求用户跨多个页面手工找依赖。
- 共享资源删除只移除使用关系，不顺带删除使用它的 Agent；Agent 删除可按本次明确意图连会话/事件删除。
- 渠道必须单独处理：其 agent_id 当前必填，不能保留指向已删除 Agent 的停用记录。选择改绑或一并删除渠道，或先设计允许空绑定的结构。
- 删除应按影响重新核验并事务提交。并发新建关联、活动 Run 取消失败、提交结果不确定，都要给出真实状态，不能先报成功。
- 平台附件原文件、下载中心产物、实例诊断日志与会话事件不是同一种数据；不能把“删会话”直接扩大为无差别删除平台文件。
- 优先交付：Agent/渠道删除闭环、C01–C04；随后补 C05–C07 的定向回归及修复；其他资源逐步复用同样交互。
- 本报告是审计与调整建议，尚未实施上述改动，也未提交、推送或发布新版本。
