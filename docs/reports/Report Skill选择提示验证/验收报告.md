# Skill选择提示与前后对照

日期：2026-10-14。仅加强提示，不改变Harness加载机制、供应商、Skill权限、配置或数据库结构；验证阶段未提交发布。

## 原有提示与改动

当前Pydantic AI 2.46.0、Harness 0.32.0。SDK目录提示只介绍load_capability，存在工具搜索时另提示先加载Capability再搜其工具；没有普遍要求匹配Skill后等待加载返回再执行业务。资源工具已有精确路径发现和按需读取说明，保持不变。

新增唯一规则位于skills/instructions.py，经实际build_agent仅在skill_capability非空时注入一次：先匹配描述，明确匹配才加载；等待加载结果后执行，不在同一批调用里加载并执行业务；多项匹配可组合，无关不加载，当前上下文已有正文不重复加载；子文档在任务或适用步骤需要时读取。不给Skill额外权限，不把失败改为框架强制阻断。

## 方法与边界

使用本地SQLite已配置的deepseek-flash凭据，只读取得；不修改配置、会话、Skill或业务数据。使用项目build_agent、真实SDK Skills和真实模型API；读取工具为隔离的确定性合成数据，无生产副作用。不是8000 REST/真实租赁业务端到端验收。

三份相同Skill（租赁、BOM、旅游）及工具同时提供给每组。4类任务，每类新旧各3次，共24次新Run；固定任务、提示、工具、max_tokens=2048、request_limit=10。按轮次交替新旧顺序，并发3；不额外设置temperature。唯一产品变量是新增选择提示。

首轮24次为评测脚本预检：暴露合成附件ID不明确、金额千分位被字面评分误判、usage属性和加载消息类型解析错误。修正双方共同的附件说明和评分器后冻结正式场景，重新跑24次；正式数据全部保留，未挑选回答。产品选择提示在预检后未调整。预检不计入下表。

“先加载”按完整调用轨迹判定：read_file调用前必须已有对应load_capability成功返回；同一模型响应里同时加载和读取，计不通过，即使调用列表显示加载排在前面。不能依据模型自述或最后答对算先加载。

两组Skill选择均为12/12正确，无误加载旅游Skill；需要的税率参考资料均被读取，不需要时未展开它。主要差异是旧版6次把加载和业务读取放进同一模型响应；新版全部等待加载结果再继续。旧版另有一次试错子文档路径，真实最终路径可读，但该试错不作为加载顺序改善的证据。

这证明了这批样本上的顺序改善，不能推断全部模型或业务正确率提升。每场景仅3次且模型有随机性；正式报告不把合成读取当成真实合同、完整Excel或HTTP上传验证。
