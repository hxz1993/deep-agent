# 通用渠道 Message 工具

> 2026-09-28，按用户确认的实施范围收敛。产品版本 0.12.0；新增数据库 Revision 009。
> 已完成两渠道私聊、群聊、媒体及并发真实发送。真正飞书话题内入站、故障重连和权限失败仍区分受控测试与租户实测，不扩大验收结论。

## 目标与边界

只增加一个运行时系统工具 `channel_message`（渠道消息），同时支持飞书与企微。渠道对话自动获得发送能力，不需要给 Agent 配置发送用 MCP。普通回答继续使用各渠道现有流式回复；图片、文件和其他媒体作为独立消息发送，不嵌入流式正文。

目标固定为触发本轮的群或私聊，由服务端绑定账号与来源。同一 Agent 绑定两个渠道，不代表每轮能向两个渠道发送。首版不接受接收人、群 ID、账号、任意消息 ID 或话题参数，也不开放跨用户、跨渠道、定时主动通知。`channel_targets` 和 `channel_history` 只保留为 [TODO 潜力项](../TODO.md)。表情、编辑、撤回、搜索、管理操作不在首版。

## 上游参考与抽象

- [OpenClaw](https://github.com/openclaw/openclaw/blob/main/docs/plugins/architecture.md)：共享 message 工具通过渠道动作适配器分发，平台插件处理上传和投递。
- [AstrBot](https://github.com/AstrBotDevs/AstrBot/blob/master/astrbot/core/tools/message_tools.py)：模型消息工具接收有序消息组件，由平台适配器发送 MessageChain。
- [企微官方 Node SDK](https://github.com/WecomTeam/aibot-node-sdk)：媒体初始化、分片上传、完成上传与主动消息协议。

本项目借鉴共享发送语义与有序组件，不照搬上游全部工具或跨会话权限。当前 Python SDK 差异由适配器处理；不要求模型自己管理媒体 ID，不提供任意 SDK 方法透传。

调用链：`channel_message → 统一消息服务 → 渠道网关 → 消息操作适配器 → 平台 SDK`。

| 层 | 职责 |
| --- | --- |
| 运行时工具 | 仅 send 动作；有序 text/image/file/audio/video 组件；媒体引用 file_id，可选展示文件名；按渠道能力提供引用当前消息选项 |
| API 统一服务 | 从可信入站 Run 确认来源；按现有文件权限读取 FileStore；整组内容预校验；请求摘要与结构化结果 |
| 网关操作服务 | 复核当前渠道、绑定和 Run；持久化认领、顺序发送、取消、超时与逐项回执；HTTP 断开不引发二次发送 |
| 可选操作适配器 | 声明支持内容、引用及限额；选择原生类型或文件降级；上传并发送；转换安全错误及平台回执 |
| 原入站／流式适配器 | 保留既有消息接收与回复逻辑，不为新工具强行统一两渠道的展示效果 |

新增渠道通过注册操作适配器接入，上层工具和服务不增加平台协议分支。

## 消息内容与平台差异

| 能力 | 飞书 | 企微 |
| --- | --- | --- |
| 文字 | 独立消息；普通答案仍使用流式卡片 | 独立消息；普通答案保持现有流式 |
| 图片、文件 | 上传取得 image_key/file_key 后发送 | 当前机器人连接上传取得 media_id 后发送 |
| 已有音频、视频 | 格式及大小符合适配能力时原生发送，否则按文件 | 同左；不新增识别、合成或转码 |
| 引用本轮消息 | 原生引用，继承当前话题 | 不提供伪造的原生引用；仍可发送当前聊天独立消息 |
| 多组件 | 按输入顺序发送，可能生成多条消息 | 同左 |

飞书复用现有受控 worker 与 SDK 客户端，增加明确的发送 IPC 操作。企微复用现有官方 Python SDK 长连接，通过公开 reply 的扩展 cmd 和完整 ACK 完成分片上传，再用 send_message 发送；独立请求 ID 不占用流式回复句柄，不新增 Node 进程或第二条机器人连接。

模型只传 `file_id`，不能传宿主文件路径、下载 URL、Base64、Token、平台媒体 ID。文件可来自当前获授权会话附件或本轮沙箱产物。实际限额是 FileStore 与渠道限额的较小值；权限错误、超时和结果未知不降级为普通附件。上传成功不是消息发送成功。

## 加载与权限

- 可信渠道 Run 在第一次模型请求前自动加载；不要求本轮已有附件，支持先生成文件再发送。
- 私聊后续轮次通过渠道处理记录恢复来源，不依赖用户正文或重复附加的来源上下文。
- 每次调用重新核验账号启用状态、Agent、平台会话归属、渠道绑定和 Run 状态。模型、历史文本和伪造 context_refs 不能授予发送权限。
- 普通 Console 对话、历史浏览和单纯绑定了渠道的 Agent 不注入该工具。
- 当前聊天发送优先使用内置工具；已有 MCP 保留用于其他业务及显式授权场景。当前发送权限不能扩展为平台账号的任意联系人权限。
- `runtime:channel` 仅为系统工具目录分组，不注册为需要 Agent 勾选的 ToolPackage。

## 持久化与失败语义

Revision 009 新增 `channel_message_operations`，保存 account/channel_run/agent_run/tool_call/session 引用、请求摘要、状态和逐组件安全回执。唯一键为 `(agent_run_id, tool_call_id)`，操作 ID 使用确定性 UUID；同键不同内容拒绝。只存回执和摘要，不存正文、文件字节或第二套聊天历史。

网关持有操作生命周期。每项发送前落库 running，成功后保存平台回执；飞书 message_id 与企微 request_id 分开表达。组件可以为 pending/running/succeeded/failed/unknown/cancelled/skipped；失败或结果未知停止后续组件，已成功项不重发。启动恢复只将未完成操作标记 unknown，不调度补发。平台不保证幂等时不承诺严格一次投递。

取消只阻止尚未发送内容，不撤回已发送消息。上传分片可有限重试，消息结果未知不能盲重试。终态记录不因迟到更新重新变为可发送状态。

确认删除渠道同时清理发送回执；删除普通会话保留入站台账及发送幂等事实，绑定失效后拒绝继续发送。配置备份只保存新表空结构；已有回执时 009→008 拒绝破坏性降级。

普通流式答案不被工具接管。仅抑制已确认发送的重复文字，发送图片不会吞掉后续说明；纯媒体成功也应正确收束加载状态，不误报没有可展示结果。
