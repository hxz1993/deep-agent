# 三一助手：战略核对与同行对标

## BPP 销售预算审批模式

收到以 `【BPP 销售预算审批回填】` 开头的按钮请求时，用 `read_file` 读取本 Skill 的 [审批模式说明](references/bpp-sales-opinion.md)。复用下文的报表定位和查数方法，交付按审批模式执行。仅对话查数、战略比较和下载报告继续使用各自原有规则。

## 报表定位与口径恢复

本节仅用于需要内部报表或Cube数据的请求；纯文档解析和外部同行比较仍按各自分支执行。

1. **定位来源。** 优先复用用户明确指定的对象、当前Page/活动Sheet及实时筛选；工作簿摘要是保存态定义，不能覆盖用户条件或实时筛选。没有页面上下文时，按报表名称、业务关键词和分析目标主动搜索，核对候选说明、绑定Cube及关键口径。唯一且业务匹配时，简短说明采用的来源后继续；多个候选会改变分析结果时才澄清。用户已明确指定Cube时直接核对模型，不强求先找一张表；不能仅凭名称相似或能出数就认定匹配，更不能称搜索结果为用户“当前表”。
2. **识别失配。** 引用成员经定向核对仍无法定位、工具明确报成员不存在或绑定关系矛盾时，及时说明具体不一致项，停止沿错误坐标反复查数。没有版本或变更证据时，只说“报表定义与当前模型不一致”，不直接认定报表过期。有效切片零行、无权限、接口失败分别处理，不作为失配或切换模型的依据；工具调用完成也不代表返回的业务查询成功。
3. **形成候选。** 根据真实Cube结构、相关维度成员的名称/说明/别名及明确映射，按运行边界有限补查，提出少量可用口径。相关维度和关键词合批，已知目标维度时限定检索，不能把无关维度的数字ID命中当成目标成员。优先核对元数据；确需数据可用性探测时保留已确定条件，只定向核对当前不确定项，不同时放开多维、扫描全模型或遍历全年快照。探测结果只说明可用范围，不能证明新旧业务含义等价，也不在确认替代范围前展开排名、同比等正式分析。
4. **按业务澄清。** 候选用用户能理解的指标、组织、期间、场景和版本等业务含义表达，指出与原口径的差异及尚缺条件；提供少量真实选项或一个推荐方案，允许用户自由补充，不要求其填写Cube或成员编码。有明确证据证明仅编码变化、业务含义及范围完全一致时，说明映射后继续；名称相似不足以证明等价。需要用其他Cube替代原来源或改变关键业务条件，且尚未获用户明确指定/确认时，一次问清并等待；已确认条件不重复询问。没有可靠候选就说明缺口，不编造选项。
5. **依确认口径查询。** 复用已核实映射，显式保留各维度的固定或展开范围，包括已确认的辅助维度；不靠省略维度让工具扩大范围。允许修正编码、表达式和查询方式，但不能改变业务含义。父级成员存在不代表已存储合计，改按子级汇总须核实范围、可加性并避免父子重复。确认该切片无数据时如实说明；需要换年份、组织、场景等才能继续时，提出有依据的替代建议，由用户决定，不为查出数自行换条件。
6. **准确交付。** 最终说明实际采用的业务范围及重要缺口；使用替代口径时交代与原表的差异，不声称复现原表，也不把局部数据当整体。用户确认仅授权本次分析，不修改报表、模型或维度；文档核对仍以附件目标为准，不能用替代模型口径改写文件真值。

## 文档目标与预算：重点核对

核对战略报告与当前表时，优先比表内 SP 战规。表里只有预算列时，按“报告战规 vs 表内预算”标明口径。有 SP 列但查无数值时，说明缺数。用户已指定比较对象的，按其要求。

1. 有PDF/文档图片时，与表格工具一起发现`parse_document`，先调用专业解析，保留物理页码；不要先用`read_file`。按解析返回位置续读本题相关页；同一文件复用结果。仅专业解析失败/不可用且文字PDF可读时，说明后用`read_file`降级；扫描件或图片不能按文字层降级。解析失败不等于无目标。
2. 按上节定位来源；需要补充表内绑定时，读`deepfos_deeptable_workbook_get(detail="summary",sheet_id=已核实的活动Sheet.id)`恢复行列、固定POV、版本含义、金额单位及Cube，参数以实际Schema为准。与`cube_describe`、`cube_compare_data`、必要的成员查询集中发现；已有本轮有效绑定就复用。
3. 查询粒度与文件目标一致，例如文件是大区×事业部，先取这个粒度；模型已明确存储的合计成员可直接读取，不预先展开所有产品，也不重复累加父子。固定年度、期间、场景、版本、指标及其他维度，不用省略维度扩大范围。比例不求和。
4. 核对预算且当前表明确包含下达版与当前预算版时，优先`cube_compare_data(base=下达版,compare=当前预算版,group_by=目标业务维度)`定位非零差额及缺失侧。比较结果已有base_value/compare_value/diff，直接使用，不把所有原值复制进Python。**模型下达版只是筛选线索，不是附件真值**：首轮重点项必须核对附件对应原值、对象、期间、单位及页码；不一致时以文件为准定向查数，不能把模型差额冒充文档差额。
5. 首轮“哪里没对上/挑明显的”列已核对重点项，注明是重点核对，不承诺全文逐格审计；不额外校验所有区域合计、不统计全部相等格、不读取或计算全部产品结构。核对预算且没有模型下达版时，从文件与预算同粒度直接比较，仍只输出重点项。用户明确要求全量核对才做全覆盖。
6. 缺失侧用null/未查到，不能当0，不能断言业务未编制。工具只查了合计坐标，不能说全部产品均无数。`compare.summary.total_diff`在缺侧时可能是全量减部分，**不得用于可比总差额**。用户没问合计就不算；问合计时只对双方齐全的group原始数求和，缺数坐标两侧一起排除，最后再舍入。工具已有各项差额不重复编程；确需额外批量算术只计算小范围相关值一次。
7. 下一步只建议可执行且有证据支持的动作：确认版本/数据状态、导出差异清单、查看预算产品结构等。文件只有全球产品目标时，不能宣称或承诺某地区产品目标差额，也不推断“沿用旧拆分”等原因。目标与预算核对不修改数据。

### 查询调度（同样适用于普通表内查数）

沿用本题的分析范围、证据核验与交付要求，按查询依赖安排执行：

- 复用已核实且仍适用的Sheet、Cube、筛选与成员映射；切换表或筛选变化时重新核对受影响的口径，不照搬上一张表的POV。
- 来源、成员或口径不明确时，按“报表定位与口径恢复”核对；已具备Schema和查询规则时，不先枚举全部Resource或加载通用分析模板，只有缺少具体用法时才读取相关说明。
- 无相互依赖的文档解析、表结构、Cube结构及成员检索可并行。已有授权Schema与完整参数时，将当前已具备条件、首答确需的独立查询集中在同一次模型响应中发出多个工具调用，不等待无关查询完成后才决定下一批。
- 未知编码先定位，再执行依赖它的查数；仅缺显示名称时，名称映射可与已知坐标的查数并行。必要探索按依赖分步，不强求一次确定全部口径，也不固定探索批次数。
- 多指标各自保留已核实的SP/Budget科目、Region、Product_Line等维度覆盖与单位，分别构造请求后并行；不因合批混用坐标或扩大对象、指标与查询范围。
- 首答只取用户所问范围所需的指标和分组；组织下钻先覆盖所问组织层级，再按请求或重要异常定向展开，不自动补齐所有产品、地区、日期和预算版本。已有交叉分组能完整支持同口径汇总时复用，不为每个展示角度重复查数；不把独立查询拆成多轮模型往返。
- 结果返回后仍逐项核对原值、差额、缺失侧及文件证据。同批发现且互不依赖的定向补查合批执行，沿用运行边界的补查上限，不因提速省略必要核验。

### 计算与失败处理

- 工具已提供同口径汇总、差额或比率时直接使用，不复制整表重算。确需计算时，优先在运行环境支持的范围内直接处理结构化结果；无法直接传递时，仅提取必要字段和原值并核对来源，不为此重查全表或强制使用PTC。本节不放宽同行比较中禁止复算缺失财务指标的规则。
- 缺失记录保留为null/未查到，真实0与负数原样保留，不用默认0补齐产品或年份。按实际字段确定分组键，记录结构保持一致，不混用元组位置与字典键。汇总、差额和比例由代码计算，不先在模型正文中口算分项再抄进代码；保留原值精度，最后再舍入。使用已有总计或独立分组结果核对范围和金额，不把同一变量重复求和当作独立校验。
- 纯只读计算报错时，识别具体原因后修复一次，并核对结果；仍失败则交付已核实的部分事实和未完成项，不编造计算结果、不重复全量查询。此重试约定不适用于含上传、发布或业务写入的脚本，不能因计算报错重放已成功或状态未知的副作用。

## 上市公司同行比较

本节自包含，不加载公共分析或金融对标Skill。默认Wind，公司请求并行；缺项才有限补iFinD。用户指定供应商不静默更换。明确外部公司比较不读内部Sheet/Cube，不加载合并/归因流程。

指标按本题选，用户列出的保留；未指定时选少量相关直接指标。不网页搜索、不凭记忆补数字、不复算缺失财务指标。名称、年度、单位、年报/累计及归母/合并净利润口径一致才直接比较。内部集团模拟预算与上市公司历史分区呈现；市占率必须产品/区域/期间/统计分母一致，无外部值就留缺，不用营收占比替代。只有缺少具体调用方法时才读供应商Skill，不同时读取两家全部操作说明。

### 直接取数步骤与停止规则

1. 从问题确定公司/股票代码、报告年度、指标；本轮页面里的内部预算不冒充外部实际。不写死公司、年份或指标清单。普通财务比较默认完整年度；期间不明确且会改变答案时只澄清一次。
2. 已有授权Schema直接调用Wind的`get_stock_fundamentals`，缺Schema时一次发现；各公司并行、同公司同年指标合批。请求明确同一年报、人民币及需要的字段，优先原值和供应商直接比率。若工具用自然语言参数，也把公司、年报日期和指标一次写清。需要参数说明才加载wind-finance-data-http；失败/缺项时，仅为缺项读取ifind-finance-data-http并调用`get_security_indicators`。工具实际前缀和参数按Schema，不猜参数。
3. 核对字段名：营业收入不等于营业总收入，归母利润不等于合并净利润，研发费用不等于研发投入。三家公司选同一字段并准确标注；供应商只给不同字段时单列，不硬拼。金额保留单位，比例保留百分数或百分点含义。原值表保持供应商精度，说明要舍入时正确四舍五入。
4. 真实0、无值、接口错误分开。不得用记忆补数、用营收占比替代市占率，或自行复算缺失财务比率。市占率须同产品/地域/期间/分母；“约、超、排名”等原样保留。金融MCP均未给出同口径值就留缺，停止补查，不改走网络搜索。
5. 未要求图表时，回复一张可读的原值表、2—3条短观察和一个下一步；明确要求图表时，按下方交付规则在对话画图，不重复列同组数据的大表。每条只比较同一指标，不作跨指标大小排序；收入或现金流高不自动等于经营质量好。跨年并列值，未核实重述基准就不算增长或判增幅排名。不为普通比较启动Python、公式归因或重复双平台全量查询。

## 普通查数与交付

普通表内问数优先沿用已核实的Sheet→Cube；无上下文或发现失配时按“报表定位与口径恢复”执行，用户已指定模型则直接核对模型。口径明确就查询，单值一句话、多值小表，不启动文档或同行流程。

普通回答用一句结论＋一张重点表＋必要缺口＋一条下一步，少解释、不重复原值。技术编码仅用于消歧。缺数不填0，不编“模型单位”或取数日期。未要求图表时不主动画图；仅要求图表时，遵循Agent系统提示词的G2 5.x格式，在回答正文输出完整的`g2`围栏，不用`json`围栏，不重复列同组数据的大表。复用已核实事实，单位、尺度可比才同图展示，缺失不补0；数据或口径不足时说明缺口，不自动改为文件交付。必要计算仍可使用Python，仅为对话画图不生成或发布图表文件，不使用`publish_path()`或下载中心工具；明确要求生成报告时按下段交付报告，报告内图表随文件生成。本规则不改变OCR正常文件交付。

用户明确要求生成、导出或下载报告时，默认发现实际文件/下载工具并发布报告，无需再次确认“导出”；明确要求仅在对话中写报告或不生成文件时不上传。单独图表仅在明确要求导出、下载或保存为文件时发布；普通查数、分析、总结和单纯画图不自动生成报告文件。未指定格式的报告复用事实生成自包含静态HTML，status=published即结束并告知文件名及下载中心入口；返回无URL就不写URL，不能为拿链接或润色重复发布。默认一页结论、原值表、来源，未要求图表就不写多图长报告。不承诺未配置的个人报表保存；对话图表仅使用前端已支持的g2围栏，不新增其他UI协议。


## 运行边界

本Skill及本Agent提示词独立维护，不加载external-financial-benchmarking、deeptable-assistant-workflows或其他公共业务Skill。只可按需读取已关联Wind/iFinD供应商Skill。工作簿、Sheet、Cube、维度、成员、版本含义和文件页码全部从本轮上下文与真实工具取得，不内置环境编码、示例答案或金额。工具结果足够就结束；本次任务围绕同一定位/口径异常最多两次有依据的定向补查，仍缺条件就说明缺口并澄清，不因换关键词或换候选重置次数，不循环全库扫描或重复解析。必要的首次定位、用户确认后的正式查数及用户新提出的分析范围不计入这两次异常补查；计算失败按上节单独收敛。

用户明确要求生成、导出或下载报告且未限定只在对话交付时，默认生成自包含静态HTML，无需公共模板：用蓝紫标题、简洁结论、同口径原值表、证据页码或供应商来源、缺口四部分组织单页报告。未要求图表的报告默认不画图，不依赖CDN或脚本；明确要求含图的报告在文件内包含对应图表，不把对话G2围栏当成文件内容。普通对话图表仍按Agent的G2围栏输出。发布前检查每行单位及原值，不能以“待修正”脚注保留错单位。发布成功后立即交付文件名和下载中心说明；无真实URL不造链接，只有实质错误才修正一次，不为润色重出。
