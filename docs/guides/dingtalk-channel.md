# 钉钉渠道

钉钉企业机器人通过官方 Stream SDK 接收消息，不需要公网回调地址。当前实现复用渠道账号、会话、资料查询和内置 `channel_message`，没有新增数据库结构。

## 创建与连接

在「渠道 → 新建渠道 → 钉钉」选择 Agent、会话归属用户，扫码创建或手动填写 Client ID / Client Secret。扫码整体最多等待 10 分钟（平台更早过期时遵循平台），状态查询单次最多等待 3 分钟，网络中断继续轮询原任务；扫码后选择已有机器人时显示待连接，创建新机器人时显示正在创建，成功后另留 10 分钟保存。扫码链接过期可重新生成；授权凭据保留在服务端，保存成功后才消费注册任务。扫码是否需要企业管理员审批，以钉钉页面为准。

手动创建从 [钉钉开发者后台](https://open-dev.dingtalk.com/) 进入企业应用，添加机器人能力，使用 Stream 模式，配置发布与可用范围。发送消息需要机器人消息权限，普通正文不需要 AI 卡片权限；默认 AI 流式卡片还需要卡片创建、投放及流式更新相关权限。请按实际控制台的 API 权限说明开通并发布，获取 Token 成功不代表这些能力全部可用。

「测试连接」验证凭据，不创建第二条收消息连接。渠道列表显示实际 Stream 状态。SDK 在账号独立子进程中运行，停止账号时清理进程；同 Agent 的不同渠道仍按来源账号和聊天隔离。

## 支持消息

文字、富文本图片、图片、文件、语音及视频由回调转换到公共消息结构；平台未实际投递的类型不会通过抓取客户端历史补齐。群聊按平台投递规则触发，快捷命令遵循现有渠道规则。

语音使用钉钉回调提供的转写，同时保留原音频附件。原音频标记为 reference：模型默认读取文本，不自动接收音频二进制，也不伪造 MIME。没有转写时明确提示用户补充文字；不自动接入 STT。附件仍保留文件授权及下载能力。

当前聊天自动提供 `channel_message`，模型只提供授权文件 ID，不填写接收人、账号、媒体 ID。支持原生文字、图片、文件、语音、视频。私聊投递使用平台提供的员工 ID，群聊使用当前 conversation ID；不根据 ID 外观猜测，不依赖昵称缓存路由。

v0.14.8：媒体也可直接提供公开HTTP(S) `url`，与`file_id`二选一；下载仅在调用内存中。
启用PTC时可在`run_code`内调用同一工具，普通入口和当前会话目标不变；不自动转码、不绕过格式校验。

原生语音、视频先读取真实时长，视频提取封面，上传媒体后发送对应原生消息。格式、大小和时长校验失败时明确报错，可显式选择 file 发送普通附件；不自动转码或静默降级。平台回执作为 request_id 返回，不伪装成飞书 message_id。

入站引用文字单独进入引用上下文。出站原生引用尚未接入，不生成伪造引用条。默认使用 AI 流式卡片回复；多媒体作为独立消息发送。

钉钉默认使用 AI 流式卡片，不提供流式开关或模板配置扩展。固定使用钉钉官方 OpenClaw 连接器当前模板 `02fcf2f4-5e02-4a85-b672-46d1f715543e.schema`，按创建、投放、INPUTING、流式更新、FINISHED 流程处理。完整结束更新包含正文、内容顺序和自动布局，避免空卡片。

卡片创建或更新失败时记录投递失败，不转为普通正文。工具文字和媒体仍走普通独立消息，不嵌入卡片。


## 用户资料

扩展「用户详情」默认关闭（settings.dingtalk.user_details_enabled）。关闭时不使用或缓存消息昵称，新会话标题和新来源上下文仅使用 ID；不修改已有历史。开启后消息自带昵称写入按账号隔离的内存 LRU（2,000 条），同 ID 的新非空昵称覆盖旧值。统一资料入口只读取缓存，不主动查通讯录。重启、账号重建或淘汰后显示 ID，用户再次发言才重新取得昵称。

统计按账号内稳定 ID，当前姓名展示和搜索读取资料缓存，不读取历史姓名补齐。缓存不完整时姓名搜索提示不完整；同名不合并。Runs 和消息来源只保存当时快照，不更新历史标题或消息。

## 媒体依赖与验收

网关运行环境需安装 FFmpeg（含 ffprobe）。Jenkins API/网关镜像使用 Debian 的 `--no-install-recommends` 安装；macOS 本地可使用 Homebrew。没有新增 Python 媒体服务、模型或常驻进程。

`channels/media_metadata.py` 只在原生音视频发送时运行，限制单进程并发为 2、每个子进程 20 秒，取消清理进程和临时文件；仅允许本地媒体格式及本地协议，不加载远程媒体或播放列表。普通文件和图片不调用这些工具。

自动化测试覆盖扫码协议、身份隔离、回调解析、昵称更新、引用上下文、原生媒体请求、失败回执及流式卡片终态发送。真实租户仍需验收发布权限、私聊/群聊、媒体事件、音视频呈现、转写、正文与断线重连；自动化通过不能替代钉钉客户端验收。
