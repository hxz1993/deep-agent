# v0.13.7 发布审计与验收

日期：2026-10-19（Asia/Shanghai）。仓库 `deep-agent`，分支 `test`，基线 `261c1cc`（v0.13.6）。本次覆盖该提交以来全部未提交产品、测试、说明及新增文件。

## 改动范围

- Console Agent／模型目录共享、成功维护后失效、同服务同用户同App的标签页同步、切页／窗口激活复核；保留运行对话、新建草稿、附件和手动选模，删除当前Agent只在空闲时回到新建。
- 诊断状态、活动时间与详情批量SQL；普通会话先分页再聚合消息、轮次、附件等展示统计。权限、NULL Run、状态及来源含义不变。
- 概览最近提问按会话去重，展示当前筛选时间范围内每会话第一条真实输入，再按该输入时间倒序，最多10条。异常列表和其他提问聚合不变。
- 诊断超时／繁忙错误及加载失败空态；网络配置的重复Key标签、新选择DeepSeek／Kimi时默认跟随Fetch，历史缺省仍系统内置；缓存入口统一更新。

## 审计结果与修复

| 发现 | 处理与验证 |
| --- | --- |
| 供应商断开订阅会改变模型可用性，但目录失效遗漏了disconnect路由 | 成功断开后失效Agent及模型缓存，并通知同范围标签页。新增行为回归验证两类缓存被重读；临时OAuth verify不持久化凭据，仍不发送无效通知 |
| 全量Console中的模型选项测试仍依赖旧的直接HTTP解析语句 | 保留共享选项函数接入验证，行为测试覆盖目录更新后Agent默认模型不可用时保留该项、手动模型及运行中模型不被替换；未通过修改测试绕过产品缺陷 |

两个独立审查覆盖后端SQL/仓储与Console异步状态；未发现其他可复现的阻塞问题。只读Store的MySQL、PostgreSQL、SQLite状态SQL编译通过，不依赖窗口函数、CTE或新索引。静态源码、测试、当前指南和缓存依赖均在审计范围。

## SQL实测与边界

- 本轮沿用同日实际Test MySQL结果：31天状态筛选原约2.50–2.79秒，优化后约0.50–0.85秒；16组诊断及12组普通会话列表对照响应一致。
- 最近提问改动再次只读实测Test：7天8次提问、5个会话、展示5条，概览0.375秒；31天52次提问、25个会话、展示10条，0.196秒。独立轻量键对照与首条事件完全一致。
- 最近提问先聚合序号和会话ID，再排序限量，最终正文主键回查；现有created_at与session+sequence索引被使用。1000会话/10000事件隔离规模回归中概览+列表约0.05–0.07秒，8+8条SELECT。
- 上述为Test当前样本，不承诺Alpha或未来大库时延。Test既有其他概览聚合存在字符串转整数警告，本次新增首条查询未产生该警告；不将其混同为此次SQL错误。
- Test/Alpha/Cloud未写入数据或部署。无新增表、字段、索引、迁移、依赖或环境变量，数据库Head保持011。
