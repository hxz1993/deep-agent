## 发布内容

- `execute_python`、`execute_skill_script` 增加 `include_context=False`。开启后通过 `DEEP_AGENT_CONTEXT` 提供公开用户资料及本次 `app/space/language`；关闭不查询、不注入，也不继承宿主同名变量。
- 普通调用与 PTC 共用一次逻辑 Run 的资料快照和并发合并；成功空值保留，资料失败继续执行，只保留 User ID 和安全错误。Run 结束清理，SDK 内部恢复不重新解析。
- 资料服务与 Console 共用 30 秒成功缓存，按环境、可信用户、认证指纹和有效语言隔离。Token、Cookie、API Key 与任意 Header 不进入脚本环境或自动写入结果／历史。
- 两个工具的模型可见说明包含固定 JSON 结构、字段、读取代码和失败规则。无需 Skill metadata 或新的上下文工具；既有脚本输入输出、文件授权与上传下载流程保持。
- 统一鉴权适配器仍属后续研究，见[42 课题](../design/42-enterprise-auth-adapters/README.md)；当前上下文不作为权限凭证。

## 审计修复

1. 统一 Console 与执行路径的有效语言，避免浏览器 `Accept-Language` 与执行白名单不同导致重复查询。
2. 将执行上下文与可配置的 MCP 转发白名单分开。新增服务端私有映射，独立提取固定白名单和已解析范围；MCP 转发仍保持原配置。覆盖 Console 覆盖值、可信渠道 owner／Key、禁用关联和默认关闭行为。
3. 本地开发用户名只用于同一可信用户，不能与渠道替换后的 owner 混用；字段仅在服务端使用，不进入公开工具入参。
