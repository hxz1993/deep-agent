# BPP 销售预算审批回填

读者是审核销售预算的财务人员。按按钮传入的表单、组织、期间和版本定位送审数据。即使入口为费用表，也要按当前应用核实对应的销售预算和战略目标（SP）。附件仅在取得正文后作为依据。

1. **事业部、大区的销售额与战略一致性。** 分别核对各自的预算销售额和同口径 SP 目标，列出预算、目标、差额（预算减目标）及偏差率（差额除以目标），写明低于、达到或高于目标。战略材料明确优先区域或结构目标时，再对照相应的预算分布。集团大区跨事业部统计时单独列示，只有取得事业部与大区的交叉数据才能据此解释某事业部的缺口。
2. **销售占比、历史与行业差异。** 事业部占比用该事业部销售额除以集团销售额。大区占比按其统计范围除以所属事业部或集团销售额，在占比旁标出分母。比较预算与战略或上年实际的占比时，各用同场景、同口径的分母，结构变化写百分点。

   - **历史增幅差。** 对可核实的事业部、大区分别列预算同比（本期预算销售额 ÷ 上年同期实际销售额 − 1）和上年实际同比（上年同期实际销售额 ÷ 前年同期实际销售额 − 1）。相减得到增速差，写明快或慢多少个百分点。
   - **行业差异。** 将上述预算同比与同期间、产品、地域、销售金额口径可比的行业增速相减，写明高或低多少个百分点，标注来源、期间及实绩或预测属性。有可比行业结构时，可另列占比差并说明双方分母。仅有行业销量或个别同行时标明指标或样本，不能据此计算与行业销售额增速的差距。

基数为零时列出原值和能计算的金额差，标明比率无法计算。数据缺失或不可比时，说明哪个组织、哪项判断缺哪份资料；有依据的项目继续交付。最终判断由审批人作出。

## 审批意见写法

- 页首是两行送审信息：第一行「组织、预算范围」，第二行「送审表单、送审批次」。在 `scope` 中逐项填写本次送审值，标签和排版由模板生成。组织、表单优先用送审资料或本轮工具核实的业务名称，仅有编码时可填原编码。送审批次只取明确的批次信息，缺失留空；流程标题、任务 ID 和版本号均不能作为批次。
- 范围字段仅填年度、实际送审期间、场景和版本。期间未指定时留空，不能自行认定为全年。金额单位随数字列示。Cube、POV、科目编码、维度坐标放在 `sources`，缺资料对判断的影响写入对应结论。
- `summary` 通常写两三句。先写事业部、大区最影响审批的销售目标偏差，再写最需要解释的结构或增速差异。只有费用数据时，点明缺少的销售预算或 SP 目标及受影响的判断；费用明细仅在能解释销售偏差时引用。
- 占比写明分母，增幅写明比较期间，事业部和大区分别列示。明细数值进指标表，正文只解释会影响判断的差异。避免在每栏反复抄表、复述同一缺口或添加“综合来看”“建议重点关注”等开场语。
- 核实事项写成编制人能直接办理的动作，如“请补该大区上年同期销售额，并注明是否含内部交易”。按材料合并同类缺口。每个来源保留足以复核的表单、口径和必要坐标或页码，不逐条抄写查询过程。

## 渲染与返回

使用 `execute_skill_script`，指定 `skill_code="sany-demo-workflows"`、`script_path="scripts/render_bpp_opinion.py"`、`resource_paths=["assets/bpp-sales-opinion.html"]`。把本次结论放在工具的 `inputs` 对象中，显示值使用纯文本。下表是字段说明。

| 字段 | 要填写的内容 |
| --- | --- |
| `scope` | 对象。键为 `organization`（送审组织）、`year`、`period`、`scenario`、`version`、`form`（送审表单名称）、`batch`（送审批次）。每项只填对应的值。 |
| `summary` | 最影响本次审批判断的销售目标偏差、结构或增速差异。 |
| `shares`、`comparisons` | `shares` 列事业部、大区各自的占比和分母。`comparisons` 先写相对历史增速的百分点差，再写相对行业的差距；两种基准分别交代，有哪项就写哪项。 |
| `division_strategy`、`region_strategy` | 分别说明事业部、大区的预算与 SP 目标一致性，注明重点偏差。 |
| `metrics` | 非空数组。依次列事业部和大区的销售额与 SP、销售占比、同比与历史增幅差、同比与行业增速差。`metric` 标组织与指标，`budget` 写预算金额或比例及单位，`benchmark` 写基准名称、期间和值，`difference` 写差额、百分点差或具体缺口。多个组织共缺同一基准时可合并一行并写明范围。 |
| `checks` | 非空数组。每项含 `finding`、`verify`，分别填写核实事项与可执行的核实动作。 |
| `gaps` | 非空字符串数组，列出待补资料；材料齐备时说明已覆盖的范围。 |
| `sources` | 非空字符串数组，列出实际使用的来源编号、表单与坐标或资料与页码；取证受阻时如实说明已取得与缺失的依据。 |

脚本用包内模板渲染 UTF-8 文件 `approval.html`。从本次工具返回的 `files` 取该文件的 `file_id`，调用 `present(file_ids=[该文件的实际 ID])` 将它交付给当前任务。成功后调用一次 `publication_result`，设 `status="completed"`，在 `reply.text` 简短说明“审批意见已生成”。当前发布未配置业务 Schema，省略 `reply.data`。按钮直接下载该文件回填 BPP，无需在回复中复制 HTML 或发布到下载中心。渲染或文件交付失败时说明具体原因，不宣称生成成功。
