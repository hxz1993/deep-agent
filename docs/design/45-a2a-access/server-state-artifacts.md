# 发布配置、任务状态与交付

[总案](server-implementation-plan.md) · 本轮为设计评审。

## 首版存储

| **对象** | **拟用存储** | **保存内容与生命周期** |
| --- | --- | --- |
| Agent 发布 | 独立配置表候选 `agent_publications` | `code`、`name`、`description`、`agent_id`、`scope`、`enabled`、`revision`、`created_at`、`updated_at`。协议验证可用注入式配置。 |
| Task 与 Context | API 进程内有界仓储 | Task 保存状态、调用主体与发布、开始结束时间、Run 关联、待补材料、去重回执和公开结果引用。Context 绑定发布、已验证主体与内部 Session，同 Context 一次只跑一个活动任务。 |
| 内部会话与诊断 | 现有 Session、事件和日志 | 复用会话消息、工具事件和日志。A2A 诊断记录只写安全字段，Task ID 可用于关联排查。 |
| 产物 | 现有 FileStore | 只存成品字节和现有文件元数据。Task 记录交付引用，不复制文件。 |

运行流程在受理、开始、暂停和终态时更新自己的 Task。普通 Console 或渠道聊天的结束路径不承担 A2A 状态同步。相同作用域和消息 ID 的重试在进程内去重。先核验发布、用户、App/Space 和模型，再调用现有 Runner。会话和工具事实沿用现有落库规则，已核验可下载的产物与 Task 成功状态一起发布。取消在任务的运行令牌上完成，任务终态后禁止迟到结果覆盖。

## 先内存，按需换存储

首版先跑通提交、观察、补答、取消和取件。A2A 和 Console 经过同一个任务服务访问仓储，内存实现保存真实 Task 状态。以后如果需要持久化，在仓储边界更换实现。

- 任务服务负责身份、状态规则和协议投影；仓储负责按作用域读写 Task、Context 和受理去重。以提交时登记任务及回执、同 Context 单活、状态条件更新为原子边界：首版用进程内锁，将来用事务或条件写入。
- 更换仓储后，保留现有 URL、Task/Context ID 格式、状态与错误、查询过滤、流式事件和 Artifact 引用语义。分页游标保持不透明，不使用数组位置或数据库主键作为公开契约。Console 继续使用同一管理接口。
- 用同一套契约用例验证两个实现。持久化延长的是记录可查的时间；把记录放进数据库本身不会恢复已中断的 Runner、实时订阅或跨实例取消。需要这些能力时单独设计和验收，不把首版的旧会话历史当作可恢复 Task。

## 清理与部署

- 已完成、失败、拒绝和取消的 Task 从终态起最多留 24 小时，每进程最多 500 条终态，超过容量从最早结束的开始清理。运行和暂停分别受执行及等待期限约束。Context 到空闲上限且没有活动 Task 时清理。
- 浏览器刷新或观察连接断开后，可在原进程继续查询和订阅。API Worker 重启后近期任务、外部 Context 和受理去重均失效，原 Task ID 无法查询、补答或走 Task 取件。会话历史和 FileStore 各自按原规则保留，日志可用于排查，重启不自动重跑。
- [仓库 Gunicorn 配置](../../../deploy/gunicorn.conf.py)限制每个 Pod 一个 Worker。同一个端口也可能经代理分到不同 Pod。首版的部署条件是该 A2A 入口所有操作固定到一个 API 进程。多个副本各持内存时，某一实例收到的查询、取消和补答看不到另一实例的 Task，Console 也只能显示当前实例记录。部署前核对目标环境的副本和流量路由。
- 若后续需要跨副本查询、取消、重启恢复或稳定的跨重启去重，再评审共享 Task 仓储和跨实例调度。只做粘性路由不能解决 Worker 失效和重启恢复。发布配置存储单独评审，任务寿命不跟着发布配置持久化。

## 身份与访问

- 边界顺序：可信网关/身份验证 → 发布授权 → 实际租户与 App/Space → 被选 Agent 与执行身份 → 现有下游授权。客户端自带的 user、tenant、app 或任意 Header 都不是授权。A2A 的 `tenant` 是声明过的路由参数，不能取代企业权限核验。
- 按平台核验后的调用身份和目标 App 执行。服务账号使用平台签发且适用于目标 App 的凭据；令牌过期时按已验证的重新授权渠道恢复，同主体续跑，不保存令牌进任务。没有可刷新凭据时不能承诺持续执行。API 及文件路由都禁止弱化现有 MCP／App 授权。
- 所有 get/list/subscribe/cancel/resume/download 通过作用域查询；后台管理端另做平台权限，不允许利用 Session ID 普通聊天接口读写专用会话或看到他人任务。校验普通会话列表、历史/导出、后台诊断、文件直链及跨租户缓存。轮询、提交、附件与并发限额按调用主体和发布限制，监测等待、失败和取消，不输出凭据和内部提示词。
- Card 只描述认证方式，不执行认证；FastA2A 上游明确需自行实现 middleware。安全策略以 Task 服务重复核验为准，避免某个 JSON-RPC 方法因绕过入口而放行。

## 输入与 Artifact

| 阶段 | 处理与失败 |
| --- | --- |
| 输入 | 支持发布明确允许的 text/data；用规范的 Part 承载小型 `raw`（Base64 解码后限额）或通过授权上传得到的自有文件引用。先验媒体/大小/内容和当前主体，引用绑定有效范围及内容摘要，再交给已有附件和解析机制。任意外部 URL 首期不抓取；将来接入由明确域名策略和隔离抓取服务实现。 |
| 内部生成 | Runner、Python、Skill 可写内部文件；仅经明确交付策略和可信文件桥接采集成品。模型文字、工具 stdout、原用户输入和中间文件都不能自行晋升为交付引用。 |
| 发布 | 先上传 FileStore、验证元数据与实际可读，再创建稳定 Artifact ID。写入公开的文件名、类型、大小、SHA-256、过期信息及私有 FileStore 引用，与终态一并写入当前内存 Task。上传成功而任务终态写入失败时，沿已有文件事实排查独占孤立件；不得误删共享或输入文件。需要 XLSX 而文件失败时 Task 不标完成。 |
| 返回 | 摘要优先用 `Artifact.parts[].data` 或 text；文件用 `parts[].url`、`filename`、`mediaType`。稳定受控下载路径可出现在授权快照，签名地址按需短效生成，不落库或放日志。首期不切分文件进 SSE，完整已发布 Artifact 一次送达（`append=false, lastChunk=true`），不拷贝字节到数据库。 |
| 取件 | 客户端对 `parts[].url` 发 HTTP GET，携带适用的 App 和鉴权 Header。DeepAgent 核验身份、任务和访问权限，从 FileStore 流式返回原文件。 |
| 留存 | Task、Context、沙盒、文件分别设期限。Task 还在而文件已过期时，展示文件已过期。Task 清理不删除 FileStore 文件，旧 Task 的 A2A 取件入口失效；多个 Task / 用户不能借名称或路径访问其他文件。 |

例：Task 交付两项，`summary` 结构化摘要和 `report-xlsx` 文件，二者 `artifactId` 在订阅、查询、SDK、CLI 和 MCP 中一致。平台的 [local-files 路由](../../../src/deep_agent/api/v1/local_files.py)在平台存储模式不可当作下载实现；复用 [FileStore 文件桥接](../../../src/deep_agent/sandbox/file_bridge.py)及可信平台身份。若报告以后需要多版本编辑、独立搜索、共享、重发布，再建产物实体，不把该模块混入首阶段。

## 隔离验收的初始参数

下列数值是设计验收夹具，不能当生产承诺。统一从发布策略读取；同一任务的有效上限固化在受理修订中，临时放宽只影响新任务。

| 资源 | 初始验收目标 |
| --- | --- |
| 执行并发 | 单进程先 2 个执行槽，Context 始终单活；同发布或调用者并发/排队另限流，不饿死其他发布。 |
| 运行和观察 | 单 Task 累计执行时间先以 10 分钟验收；暂停不占 Worker 槽。SSE 以 15 秒心跳检查网关，SDK 默认等 120 秒。阻塞 RPC 与网关需协调；长请求优先显式立即返回。 |
| 状态和清理 | 暂停等待暂定 24 小时。终态最多留 24 小时及最近 500 条，分别验证超时、容量和清理后的取件。 |
| 请求和文件 | 普通文本/JSON 与解码后的文件各有限额；小文件可内联，大文件按现有平台上传限额与发布策略取更严；若业务要求的 XLSX 无法交付则失败，不回报空成功。 |

## 结构评审

当前基线为数据库 015。发布配置拟用 `agent_publications`，Task 和 Context 首版继续放内存。确定实际数据库、规模、锁与权限、备份及回退后，按仓库要求单独确认 DDL。
