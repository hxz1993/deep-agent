# 财务分析场景如何落到报告工作台

> 2026-11-09 场景梳理与界面建议。依据用户提供的受限飞书多维表格，核对指定 Grid 可见的全部 13 条场景。以文字字段为依据，将场景通用化整理。

## 入口和任务布局

以现有 EPMS 内嵌的共享 Agent 为基础。从财务业务页面进入“财务分析”，带入当前期间、组织或品牌、模型和用户有权读取的范围。下表是可逐步接入的业务场景。DeepAgent 管理 Agent、Skill、工具与会话轨迹，EPMS 提供固定的操作流程，以及团队模板、版本和使用范围的管理入口。

沿用[原报告工作台](pigment-and-prototype-research.md#用户交接包本地核验范围)的配置、运行、预览和历史。进入任务后，将范围与模板放在顶部，左侧保留对话和追问，右侧为可复核的分析结果、报告或待确认草稿。周期性工作可保存为模板，下一期换期间后重新运行。即时问答可直接在当前会话完成，用户要复用或交付时再保存为任务。

| 工作台入口 | 原需求覆盖 | 用户可看到或带走的结果 |
| --- | --- | --- |
| 月结与报告 | 品牌及公司汇总月结报告、月结批注汇总、固定月评图表、按映射生成提报文件、自定义管理报表 | 按模板生成报告，按科目汇总批注，预览并导出 PDF 或提报文件。固定布局和已确认映射由程序执行。自定义报表先生成布局草稿，确认后保存为模板。 |
| 差异与下钻 | 差异自动解释、异常差异检测、明细账模糊搜索与归类、费用及 ROI 专项分析 | 差异桥或贡献排行、阈值与历史范围、品牌／渠道／科目切换、凭证明细和批注来源。匹配不确定时显示候选和未归类项。 |
| 情景模拟 | 销售变化影响模拟、不同经营口径的损益拆分与摊分 | 输入假设，查看基准和模拟的损益对比，导出保留手工输入格的表格。计算和摊分使用确认过的规则，保存前可以预览。 |
| 改表与映射 | 在预算表新增渠道、修改映射等自然语言改表请求 | 生成变更草稿，列出新增项、受影响范围、冲突和修改前后差异。人工确认后调用对应业务接口。 |

## 个人方法如何进入共享 Agent

大家使用同一条 EPMS Agent。允许个人直接安装或修改它的运行 Skill，会影响其他成员看到的能力和执行口径。每人继承一条 Agent 可以隔离配置，但随之产生升级同步、权限和版本管理问题。当前财务场景以共用团队配置为前提，个性化先放在用户自己的默认筛选、常用模板和本次关注点里。

财务团队在 OPP 的报告、脚本和日常分析方法可以作为迁移材料。实施时先核对一份样例的输入、数据来源、口径、计算步骤与交付样式，再决定形态。

| 线下资产 | 线上形态 |
| --- | --- |
| 一个人的临时分析或探索过程 | 保留为个人草稿、一次性分析或建议，继续验证适用范围。 |
| 多人用同一套方法反复出报告 | 维护者审核口径，发布为有版本、适用范围和数据权限的团队模板；成员以自己的权限运行。 |
| 需要新查询、算法、渲染或写入动作 | 把已验证的脚本和业务规则整理为受管能力，由维护者测试后接到固定业务流程。 |

共享动作可从“保存我的草稿”开始，再由维护者决定是否发布成团队模板。模板复用指标定义、可选维度、受控步骤和布局；聊天正文、原始账明细和个人授权不随模板发布。面向独立 Agent 的 Skill 包属于另一种交付方式。

## 正式执行的可靠性

提示词适合规定分析重点、解释方式和输出结构。EPMS 界面负责表达期间、数据范围、生成进度、缺项、预览、确认和导出。程序负责执行必跑步骤、校验权限及计算口径，并检查明细与汇总能否按约定规则对上。缺少必要数据、计算失败或对账不通过时，页面给出明确结果并阻止生成正式报告。

共享 Agent 可在授权范围内选择下钻方向、归纳批注、提出解释和生成草稿。事实、原始批注和模型推断分别展示；无法核实的原因标为待核对。运行记录保留模板和口径版本、输入范围、数据时点及必要证据，让同一份结果可以回查和复算。

## 首个纵向样板

建议先做“品牌月结报告＋差异下钻”，它能在一次任务里验证固定报告和交互分析是否可以共用同一份数据范围与事实。

1. 用户选择月份、品牌、对比基准和报告模板。公司汇总是独立授权的查询范围，按业务确认的聚合口径计算。
2. 程序取数并算好损益与差异。报告先呈现指标、分科目表和图表。Agent 汇总批注，对重点差异选择下钻方向，将解释与数据来源一起写入草稿。
3. 用户点击某项差异，在原任务内按品牌、渠道或科目下钻，查阅贡献金额、序时账和批注。计算贡献、源系统批注和 Agent 推断分别标识。来源不足时提示待核对。
4. 用户调整重点或确认说明后生成 PDF。只改措辞或样式时沿用已校验的事实。改期间、对比基准、品牌范围或数据时点时重新计算相应结果。

报告需求草稿可先只维护期间、范围、对比基准、口径版本、模板和关注点。结果携带指标、实际值、对比值、差异、可查来源及解释状态，明细按需加载或以 File ID 引用。报告文件与配置、业务结果、技术轨迹分别关联，便于追问、复算和排障。已确认的草稿修订可交给固定程序渲染。

首期用一份 OPP 脱敏月结样本确认模板字段、品牌与汇总权限、序时账可查询范围、对比口径及导出格式，核对线上与原报告的数字、下钻合计和批注来源。情景模拟、映射落库和模板共享按各自业务规则验收。工作台的产品方案延续[可选中间产物模块](optional-artifact-module-design.md)，已有业务系统也可以通过 [44 · Agent 对外调用](../44-agent-invocation/README.md) 使用同一分析能力，按相同的结构消费结果。
