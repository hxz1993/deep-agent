# D01 上下文压缩验收（v0.11.6）

本次交付同一用户轮内的安全压缩、续作交接摘要、来源索引及有界历史回读。保留 Event Store、现有 Token 估算器、工具结果外置和公开聊天协议；数据库为 007，无迁移，无 SDK 升级。默认触发比例保留 **80%**，删除 **55% 压后目标**。

## 实现与修复

- 自动、主动及 Provider 明确超窗恢复使用同一候选策略；可压缩当前用户轮的早期闭合步骤，不能拆消息、并行组、PTC 或 Pending 工具对。
- 最新原始用户请求与 context_refs 确定性保留。摘要上限 4096 Token，受当前模型输出上限约束；可选尾部最近两个完整工作单元合计不超过 8192 Token，必要保护内容另计。
- 摘要不强制八个标题，保留目标、纠正、事实口径、进度、失败结论和下一步。程序索引提供工具名、参数、状态与真实来源；成功历史回读不递归堆叠索引。
- 持久化前核对真实模型输入与原始来源，再在事务内校验来源及完整请求预算；摘要期间追加的事件不能被误纳入摘要范围。持久化成功后才发出后续模型请求，保存失败不伪报完成。
- 历史工具增加工具名、来源区间、Call ID 条件、Part 选择及字符分页；所有者、Agent 和原始附件授权不变。
- Console 移除目标线，按已持久化事件即时显示成功；后续业务错误、取消或 UI 等待不会把已完成压缩改成失败。自动聊天保留 nullable `target_tokens=null`、布尔兼容字段；管理员测试与主动压缩接口清理废弃目标数据。
- Moonshot Kimi 2.6 摘要请求明确关闭原生思考，避免摘要输出预算被思考占用；自定义兼容地址从注册配置取得供应商身份，不通过 URL 猜测。不修改主会话模型行为。

## B：真实模型效果对照

基线：`v0.11.5 / f4673b047cdf069810c0deefc431fd1d9f9ed5dc`。正式 Flash v4 使用八个合成闭环场景、每场景每臂三次，共 144 次（80%/85%/90%各48次）。测试压力窗口 24,000、输出预算 2,048，两臂相同；它不是供应商标称窗口。触发比例作用于扣除输出预留及安全余量后的可用输入预算。

D01–D04 是调参集；D05–D08 使用新的私有留出值。主矩阵用合成指令和冻结报表／工作簿工具，覆盖中部关键值、用户纠正、期间／币种／单位、成员与版本、授权、分页、工具发现及长轮重复压缩。写入只落隔离替身，不重放线上写操作。开发期 v3 已反馈过失败，不再冒称未见终验。

80% 最终结果：

| 指标 | 基线 | 新策略 |
| --- | ---: | ---: |
| 业务正确 | 15/24 | **24/24** |
| 业务＋压缩协议＋必要工具工作量严格通过 | 12/24 | **24/24** |
| 新留出集严格通过 | 1/12 | **12/12** |

新策略更可靠，但**没有证明更省 Token 或更快**。基线部分任务提前失败，不能直接比较总开销；双方共同成功的15个相同 case/repeat，输入为423,733 / 589,843，新策略约1.39倍，仍有幸存样本选择影响。每场景三次不构成统计显著性结论。

独立子代理仅看匿名轨迹及隐藏标准，不知方案标签：80% 48条裁决39通过／9失败，与基线15＋新策略24一致；未发现已写入字段错误、越权或重复副作用。工具执行时序以独立协议测试补证，不能由答案盲评推断。

85%/90% 的原始严格分分别为新策略18/24、20/24；对全部144次冻结输出统一解析审计并经独立匿名裁决后，两者均为 **21/24**。原始记录不改写，基线和候选一视同仁。两者仍未达到80%的24/24，且压缩次数、P95和回读增加，故不提高默认阈值。失败包含模型输出预算耗尽及测试夹具请求次数预留，不把所有失败归因于上下文溢出。

真实助手专项从原版电子表格 V91、DeepCube V34 安装包逐字读取 system prompt 与完整 UI JSON Schema，记录哈希；通过真实 Runner 两次压缩、历史回读和冻结 UI 答案续作。独立语义盲评新策略 **2/2**，基线 **1/2**；基线电子表格第二次摘要材料超限，停在旧版本答案。专项没有执行真实业务 MCP，也没有冒充电子表格客户端端到端恢复；真实 Deferred 通信另由协议线验证。

Kimi K2.6 同窗口专项：新策略 **1/1任务、六字段正确、两次压缩完成**，基线0/1；实测摘要请求 `thinking.type=disabled`。这只是跨供应商冒烟，不是完整八场景矩阵。最终并发修复快照另跑三个 Flash 场景，**3/3严格通过**。

完整匿名指标、输出裁决、完全重复读取及失败分类见 [效果评测明细](../20260926-d01-context-policy-evaluation/README.md) 与同目录 `metrics.json`。80%共同成功子集的证据读取从22次降到15次，但完全重复读取两臂均为0，尚未证明“无意义业务重查减少”。
