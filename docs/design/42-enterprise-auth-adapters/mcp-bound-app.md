# MCP 绑定应用与跨应用访问

状态：已接入 DeepAgent，本地与 Test 只读验收。

## 配置

在 MCP 的 Streamable HTTP 配置中，将「请求上下文」分为「外部固定」「会话应用」「绑定应用」。「会话应用」沿用现有 `inherit`，在说明卡片内分别标注「目标应用」和「登录身份与其他请求头」。目标应用是提问所在的应用，空间随会话确定。「绑定应用」复用场景的应用选择弹框，可按企业筛选，或按应用、空间、企业的名称和编码搜索。选项左侧显示应用和 ID，右侧显示空间。选中后回显 `应用名 · App ID` 和空间名，Space 随应用一并保存。

| 请求上下文 | App 与 Space | 身份与凭据 |
| --- | --- | --- |
| 外部固定 | 按原固定 Headers | 按原固定 Headers |
| 会话应用 | 取本轮有效会话范围 | 沿用原继承规则 |
| 绑定应用 | 取这份 MCP 配置的目标范围 | 取本轮已认证的平台用户 |

应用候选复用「场景 → 电子表格助手 → 添加应用」的后端目录和权限判断。平台目录与企业级权限按企业批量合并，范围包括企业管理员、空间管理员、应用管理员及应用开发者可配置的 App。MCP 选择入口不受电子表格助手已经配置哪些 App 的限制。Console 一次读取授权候选后本地搜索，无需逐应用发请求。提交时服务端仍校验目标关系及配置者权限，覆盖权限在打开选择弹框后变化的情况。

原型中，当前账号在「示例商贸」只管「销售预测」。搜索企业或销售计划空间时，只会返回这个 App。

MCP 列表的「请求上下文」列同时回显模式与目标。绑定应用在模式标签右侧分两行显示应用名和应用编码，悬停可看完整名称与空间。会话应用和外部固定只显示各自的模式标签。点 MCP 名称进入编辑，保存后返回列表并回显本次选择。绑定应用通过重新选择来更换目标。

`mcp_servers.config.request_context` 保存 `mode: bound_app`、目标 App／Space 编码和后端核实的显示名。候选接口为 `GET /api/v1/mcp/bound-apps`。配置保存与导入校验共用目标检查。升级保留旧模式和默认行为。回滚到未识别该模式的旧版本前，应停用相关 MCP 或明确改回旧模式，避免按旧默认解释。

## 运行时

1. 先确定原会话范围和已认证的当前用户，照常装配会话提示词与 Skill。
2. 调用绑定应用的 MCP 时，统一解析这一连接的目标 App、Space 和当前用户凭据。同一个 DeepFOS MCP 地址可配成多份。只向同环境、服务端确认允许的 DeepFOS MCP 地址转发凭据。`user` 由服务端用可信身份组装，不接收模型、任意静态 Header 或工具参数提供的身份。绑定模式缺凭据或目标授权失败时明确报错。允许地址取服务端配置的 HTTPS 网关根地址，固定追加 `deepfos-mcp/mcp`，拒绝重定向。
3. 用当前用户校验目标 App 与 Space，继续由 MCP 及平台组件执行各自的数据权限检查。配置者的访问权限仅用于管理。Search Tools 查询已保存的工具目录，原生调用、PTC 内部调用和资源读取在实际连接时使用同一目标解析规则。首期逐项核对接受 `app` 或 `space` 参数的工具，确保不能绕开绑定范围。不同用户及不同目标的 MCP 认证会话隔离。
4. 轨迹可记录 MCP 配置名和生效目标，用于核对路由。凭据不进入提示词、轨迹、日志或导出配置。

## 同名工具的搜索与调用

同一 URL 可以配置成三个 MCP。配置名在模型调用名和 PTC 函数名中都可辨认。配置描述写目标应用、空间和业务用途，区分三个返回结构相同的工具。

| MCP 配置名 | 目标与用途示例 | 模型调用名 | PTC 函数名示例 |
| --- | --- | --- | --- |
| `budget` | 年度预算 · 预算管理空间。预算数、实际数、预算差异 | `mcp__budget__cube_query_data` | `budget_cube_query_data` |
| `operations` | 月度经营分析 · 经营分析空间。经营实绩、同比和趋势 | `mcp__operations__cube_query_data` | `operations_cube_query_data` |
| `sales` | 销售预测 · 销售计划空间。销售预测和渠道数据 | `mcp__sales__cube_query_data` | `sales_cube_query_data` |

- Search Tools、首轮预选与模型目录使用同一份来源信息。完整调用名精确匹配，纯裸名保留各来源，带应用或业务语义的查询优先匹配对应来源。目标明确时选择对应工具。多应用都符合且用户未指定范围时，先澄清再调用。
- **现有 PTC** 使用已披露工具生成函数目录，复用原生工具的连接。可唯一转换的函数名带 MCP 配置名前缀。如果名称转成 Python 标识符后发生碰撞，冲突项保留原生调用，代码中只使用实际披露的函数名。

## 验证

- Alpha 已用同一登录态向同一 MCP 地址执行过同空间和跨空间的只读调用，并检查了对应 App、Space 的平台权限。DeepAgent 验收通过本机 8000 调用 Test MCP，只执行只读连通性探针。
- 至少配置预算、经营、销售三个 MCP，同一地址均暴露同名、同参数结构的查询工具。每个 App 的同名指标用不同校验值，覆盖同空间跨 App 和跨空间。用足够的其他工具触发渐进披露，目前超过 10 个工具时才启用预选和延迟披露。
- 分开验证搜索与执行。搜索覆盖完整调用名、裸名、带应用名的自然语言、三项批量披露和错误名称。执行覆盖逐一单查、同一轮三方对比、先查预算再追问销售、缺少应用信息、原生调用与 PTC 批量调用。另验证 Python 别名碰撞后的原生调用。
- 提示词测试用本地订阅 GPT 跑真实模型。先用自然业务问法，不在问句里提供 MCP 配置名或函数名，再用明确目标的提示词对照。记录候选是否召回、首次选择是否正确、执行是否完成。以实际 MCP 配置、发出的 App／Space、目标返回的校验值和最终答案为准，已知目标时的错路由、拒绝后改查其他应用均按失败记录。确认入口会话的提示词和 Skill 仍取入口 App。
- 覆盖仅有单 App 管理权限的配置者、有入口权限但无目标权限的会话用户、缺失或过期凭据、App 和 Space 不匹配、并发用户，以及外部固定和会话应用的兼容性。
