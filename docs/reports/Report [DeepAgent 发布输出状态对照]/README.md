# DeepAgent 发布输出状态对照

2026-11-20

**两个模型都正确区分了完成和待补充。五道复杂题没有观察到封装导致关键计算结果丢失或错误。** DeepSeek 的封装版有一道题用了两次模型请求。两种方式都曾正确标记待补充，同时给出了题目要求暂不列出的候选数值。 [完整题目和回复](对照原始结果.json)

## 测试设置

- 从本地 SQLite 只读加载现有模型配置。使用 Test 工作区的 Provider 装配和 Pydantic AI 发起隔离请求。输入为七道人造题，无真实业务数据。
- 同一模型的两组使用相同业务指令、题目和请求预算。两组均加入当前发布 Agent 的提示词「远程任务缺少必填信息时，使用请求补充的结构化结束方式」。
- 基线复用普通正文或独立业务输出与发布追问 `ToolOutput` 的组合。封装组统一输出 `status + message`。DeepSeek Flash 通过 `ToolOutput` 提交封装，GPT-6.1 Terra 通过 `NativeOutput` 提交。仅在同一个模型内比较。
- 本机 OpenAI-trans Provider 试探请求超时，GPT 正式对照使用本机配置中的 OpenAI Provider。
- 两个模型分别做七组配对。账期题另在同一消息历史上补一句「用十一月」，四个分支各测一次继续作答。此次测的是最终内容和状态判定，发布 HTTP 端点、SSE、控制台展示和真实 Task 续接没有纳入本次测试。

## 对照结果

| 模型 | 预期状态命中，基线／封装 | 首次请求交付，基线／封装 | 补答后继续 |
| --- | --- | --- | --- |
| DeepSeek Flash | 7/7 ／ 7/7 | 7/7 ／ 6/7 | 两边都返回 `completed` 和十一月差额 −13 万元 |
| GPT-6.1 Terra | 7/7 ／ 7/7 | 7/7 ／ 7/7 | 两边都返回 `completed` 和十一月差额 −13 万元 |

`首次请求交付` 统计初始七题。每题无业务工具调用，DeepSeek 封装版故障复盘题使用了两次模型请求。本轮只保存了最终输出和请求数，无法从记录判定第一次响应触发重试的具体原因。

| 题目 | 核对点 | 实际差异 |
| --- | --- | --- |
| 四区预算差异 | 合计 400／401，达成率 100.25%，正负差额 +18／−17 | 两个模型的前后版本均保留分区表格、抵消分析及两项核查 |
| 合同发票对账 | 应付、合同余额、暂扣、未验收分别为 21800、54500、10900、21800 元 | 四份结果完全一致，封装里的 `message` 保留为业务对象 |
| 故障复盘 | 引用 E1–E5，优先排查路径重写，并区分相关性和已确认根因 | 两个模型前后均给出只读验证和回滚条件。DeepSeek 封装版更长，且部分排障表述偏强，需要结合请求日志完整性判断 |
| 现金缺口预测 | 最少融资 50 万元，收款延迟则为 70 万元，均须在首次破线前到位 | 两个模型前后均算对。GPT 封装版给出延迟后的最差余额及融资额，基线额外给了延迟场景的逐日余额 |
| 上线门槛 | 合并错误率 1.0625%，Alpha p95 为 240 ms，等值边界缺失，结论不放行 | 两个模型前后均覆盖四个门槛，修复优先级不同 |
| 缺账期 | 返回待补充，取得十一月后按单一账期算 −13 万元 | 四份都询问目标月份。DeepSeek 前后都提前给了两期候选差额，基线还额外问了差额符号口径 |
| 缺批准口径 | 返回待补充，确认政策 A 或 B，暂缓给出正式数字 | GPT 前后都只索取政策或批准信息。DeepSeek 前后都列出了两套候选毛利，违反题目要求先只追问的约束 |
