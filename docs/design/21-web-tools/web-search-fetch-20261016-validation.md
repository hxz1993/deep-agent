# 网络搜索与抓取接入验收

核验日期：2026-10-16（Asia/Shanghai）。本地 `test` 工作区，基线 `c53646a`，未提交、推送或升级产品版本。不代表 Alpha 已部署。

2026-10-17发布审计：本项纳入0.13.6；额外修复HTTP代理fake-IP环境的首次云Fetch公网校验，并补充真实私网仍拒绝和超时取消回归。以下真实供应商观测保留2026-10-16快照，不将发布回归冒充重新实测或Alpha验收。

## 实现结果

DeepSeek Search迁移为独立API，移除搜索模型。DeepSeek、Kimi可选择跟随搜索抓取，共用实际供应商和凭据；其余搜索服务商仅系统内置。原型未改，正式Console沿用原样式补充单选项，无分割线、无Fetch测试按钮。

旧记录不含 `fetch_mode` 时仍系统内置；历史model读取忽略，保存清理。兼容旧客户端省略新字段时保留已存选择。无DDL、环境变量或依赖变化。

## 供应商真实接口

使用本地已有Key与实际配置地址，公开网页为输入；未外发业务附件、合同或历史会话。以下均为单次观测，不是性能承诺。

| 样本 | DeepSeek | Kimi |
| --- | --- | --- |
| 搜索 `site:docs.deepfos.com DeepFOS 平台` | 200，5条，0.67秒 | 200，5条，3.33秒 |
| `https://docs.deepfos.com/` | 200，156字符，4.92秒 | 200，67字符，2.54秒 |
| 文档中心平台介绍含图正文 | 200，1461字符，4.24秒，无图片链接 | 200，1484字符，3.78秒，1条图片Markdown |
| Python JSON技术文档 | 200，26791字符，6.43秒 | 403 `security_risk`，0.24秒 |
| Kimi Fetch接口文档补测 | 未重复请求 | 200，2977字符，3.16秒 |

含图正文为 `https://docs.deepfos.com/component/deepfos_platform/overview/what_is_deepfos`。原页有平台架构示意图。Kimi将图片地址改为自身图片域名、alt改为`image1`；DeepSeek该次未保留图片链接。两家首页仅提取局部正文，不能把返回成功等同于完整目录或完整站点。

真实契约：DeepSeek为 `title/content`，Kimi为 `url/title/markdown`。两家请求只传 `url` 即成功。实现按此差异适配；Kimi对某目标URL风控拒绝，不能解释成整个Key或Fetch不可用。

## 真实Agent与图片

本地8000创建隔离Agent，仅关联 `builtin:web`，主模型使用已配置DeepSeek Flash；两家分别新会话完成检索与抓取，并回读SSE、History、事件记录。

| 场景 | 整轮耗时 | 实际结果 |
| --- | --- | --- |
| DeepSeek搜索＋抓取 | 4.84秒 | 两工具成功，返回标题及来源 |
| Kimi搜索＋抓取 | 7.47秒 | 两工具成功，保留图片链接 |
| 图片链接→图片工具→模型回答 | 11.68秒 | 成功读图，识别出的模块经原图复核 |

这轮模型将已知URL的搜索和抓取并行调用，工具耗时不能简单相加；直连与Agent观测存在供应商缓存等差异，不计算固定提速倍数。图片工具结果含公开引用，不把图片二进制或Base64嵌入证据报告。

首次验收发现云Fetch事件顶层被旧逻辑标记为local，已修正：调用开始不猜执行后端；完成结果依据真实 `web_fetch.mode` 标记execution。系统内置、供应商及图片工具保持各自真实来源。

修复后两家各做一次实际Agent Fetch复验：DeepSeek整轮5.11秒、工具168毫秒；Kimi整轮5.18秒、工具3084毫秒。SSE结果均为`execution=provider`，供应商对应正确；Events原始parts及History保留相同metadata。复验曾遇到一次主模型上游zstd解压错误，未产生工具调用；记录失败后仅重试一次，通过，不将其算成Fetch成功。
