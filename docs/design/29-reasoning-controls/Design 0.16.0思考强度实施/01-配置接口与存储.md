# 接口、目录与 014

| 表／位置 | 写入 |
| --- | --- |
| `llm_models.reasoning_options` | 可空 JSONType。保存原生 effort 选项和服务端生成的来源、接入绑定。 |
| `agents.reasoning_effort` | 可空 JSONType。保存值及接入绑定。跟随供应商默认时存 SQL NULL。 |
| `model_catalog` | 沿用 Provider、能力和模型资料的 JSON，以 Provider 的明确声明优先。 |
| `chat_session_events.payload.message.metadata` | 每个新用户轮写一次 `reasoning_effort` 字符串。 |

现有模型 POST/PATCH 接收 `reasoning_options: [{"type":"effort","values":["low","high"]}]`。PATCH 省略保留，null 清空，空数组声明无可选档位。管理请求使用 `?management=true` 读取单模型档位声明及来源，沿用管理员校验。模型选择响应通过 `reasoning_efforts` 提供当前可用值。模型管理端可用 `reasoning_catalog: {provider_id,provider_model_id}` 让服务端读取同一接入的目录选项。

Agent POST/PATCH 接收可空 `reasoning_effort` 字符串，与默认模型在同一事务内更新。换模型且未指定档位时归空，旧客户端提交其他字段时保留。

014 从 013 追加两个可空字段。对已标记 014 的库验证物理列。升级中断后重试，先核对已存在列的类型和可空定义，再补缺列。空配置可单独回退到 013，任一列存在配置时禁止删列。
