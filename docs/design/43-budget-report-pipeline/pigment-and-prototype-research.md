## Pigment 官方能确认什么

### Mission 的来源与建立过程

Mission 是 Pigment 官方概念：自然语言描述的可重复分析任务。官方流程支持先聊天打磨 Report，再保存为 Mission；配置中可修改要求、预览并设置重复运行。预览分过程与 Output。[官方运行说明](https://kb.pigment.com/docs/configure-and-run-the-conversational-analyst-agent)

因此，“Mission 只是一次输入大目标就结束”并不完整；前面的报告建立过程可以多轮对话。过程页可见对话，也不能单独证明自动运行支持任意时刻的人审往返。

### Instructions 的作用

官方要求说清分析哪些数据、按什么步骤分析；输出结构和风格等可补充。它给出差异、贡献及趋势分析示例，并支持引用具体模型对象。[官方要求编写指南](https://kb.pigment.com/docs/write-prompts-for-the-analyst-agent)

这是面向分析目标的约束，不能据此认定底层保存着一份开放给用户的可执行查询 JSON。

### Output 与 Export 的含义

Output 是报告结果。官方描述 Mission 报告可编辑文字、调整图表并保存；可分享 PDF／链接，或导出到 Text Metric 后用于 Board。聊天报告与 Mission 报告的编辑／分享范围不同，导出设置还区分自动和人工触发。[官方编辑与分享说明](https://kb.pigment.com/docs/edit-analyst-agent-reports)

不能把这里的 Export 解释成导出 Mission 配置 JSON、源代码或完整查询流水线。

### 对我们有价值的借鉴

下列属于设计归纳，不是 Pigment 内部实现披露：

- 先通过对话形成可用结果，再把稳定要求保存下来，减少用户第一次就配置完整流程的负担。
- 将要求、一次运行过程和报告结果分开，让用户知道自己修改的是未来规则还是本次产物。
- 报告作为可查看、可修改、可交付的内容存在，而非只留在聊天正文。
- 保存后的重复运行、人工确认和发布可以分阶段实现，不必一开始建设完整任务平台。

## 尚不能确认的 Pigment 内部实现

公开文档未证明其查询计划、内部草稿、报告存储 Schema、Python 使用方式或渲染引擎。
不能断言其内部一定是“一个 JSON＋一个自由脚本＋HTML”，也不能断言重跑只机械填充上次结果。

## 继续研究时的核验方式

先选一份报告，分别比较固定程序、AI 辅助配置后固定执行、每次按需 Agent 分析三种做法。
以事实正确、要求修改成本、复跑一致性、缺失数据处理、耗时和模型成本判断收益，不以“有 Agent”作为验收目标。
新增查询或新图表必须明确是既有能力的参数变化，还是需要补充实现；有界渲染以真实脚本校验为准。
