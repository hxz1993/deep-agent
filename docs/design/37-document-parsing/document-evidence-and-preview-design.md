# 文档证据引用与 PDF／Word 原文定位

> 2026-10-11。DeepAgent 0.13.0 实现范围与交接记录；发布、在线验收状态见[回归报告](evaluation/evidence-layout-20261011/validation-report.md)。租赁前端和公共预览服务不在本轮实现范围。

## 本轮实现

仍保留一个 `parse_document`，供应商为 Paddle、GLM。增加两个独立布尔参数，默认都为 `false`：

| 参数 | 作用 | 不影响什么 |
| --- | --- | --- |
| `include_layout` | 当前工具批次附稳定 Block 引用、字符位置、页尺寸及供应商坐标 | 不自动上传、不重新 OCR、不恢复无用显示属性 |
| `export_file` | 程序将本次解析的完整证据 JSON 上传当前 File Store | 不受页范围、Token 分页或布局开关影响 |

默认继续现有精简 Markdown、普通／合并表格结构及布局正文补漏。普通表格可靠转换成 Markdown，复杂表格保留精简 HTML。信息完整性用正文、数字、标点、顺序、空单元格、合并关系与补漏回归保证，不能等同于保留所有 style/class。

新增实现入口：`documents/evidence.py`、`documents/export.py`；集成在 `documents/cache.py` 和 `documents/toolset.py`。当前正式协议（0.13.1 起为 ZIP/v2）以[使用指南](../../guides/document-evidence.md)、[JSON Schema](document-evidence.schema.json)及两家合成样例为准。

## 固定布局视图与分页

首次需要布局或导出时，在工作线程中生成一次固定证据对象。它尽量复用已经适配的正文，用字符范围关联供应商原始 Block；可靠匹配不了的块保守补回，不把相似金额误当作同一原文。无识别文字的图像块有明确的系统占位标记，原生正文仍为空，避免大量零长度块导致分页无法推进。

- `document_id` 标识本 Run 的解析；`block_id` 如 `p2:b7`，只在该解析内唯一。输出序号不能伪装成物理页码。
- 完整包装统一按 24K／48K 估算 Token 分页；布局元数据也计入，不在返回前偷偷追加。
- `next_read` 自动携带两个开关。超长块可拆片，每片仍沿用整块 ID 与坐标。
- 字符位置按 Unicode 码点计量，引用固定视图；切换布局开关必须从头读取，不能混用偏移。
- 普通视图和布局视图无损重建分别验证，格式适配和原生内容保留另行验证。

六份合同的当前重放中，48K 布局模式下 46 页 Paddle 需要 3 次、GLM 需要 2 次；55 页分别为 3 次和 2 次。没有上调预算。详细 Token、页覆盖与文件大小见回归报告；历史产物重放不算重新在线 OCR。

## 完整文件与历史恢复

证据文件由后端直接从真实解析对象生成，不让模型重写，也不需要 PTC。文件保存完整已取得的页面、原生页正文、原生 Block 正文／表格、固定布局视图、原文件引用与 SHA256、页尺寸／坐标空间、完整性及版本。不包含凭据、Base64、签名下载地址或运行机器路径；不是供应商整个 HTTP 响应。

同一 Run、同一次解析并发上传合并，先读后导出复用缓存，续读不重复上传。导出状态为 `not_requested/saved/failed/unknown`，只有有效成功回执才提供文件引用。明确失败或结果未知都不因模型再次调用自动重传，上传失败保留正文。平台证据上传不经过 SDK 自动重试，也不登记下载中心。

`parse_document` 继续跳过通用大结果外置，所以不存在默认 `auto` 上传。默认只分页；模型明确传 `export_file=true` 才导出。Run 结束释放私有解析缓存，已成功保存文件由现有文件服务管理权限、保留和删除；不承诺永久可访问或跨 Run 去重。

平台和本地文件引用都标记 `storage`，禁止混用下载入口。原文附件／Skill 每次续读都重新验证授权，Hash、文档 ID、文件 ID 不授予权限。历史保存已返回工具结果与可信导出元数据；新 Run 的旧文档引用不能恢复原 Run 缓存。

## 租赁任务如何消费（待该任务实现）

1. 模型调用 `parse_document`，需要字段定位及交付时同时开启两个参数，按 `next_read` 读完所需内容。
2. 模型保留既有业务字段、来源解释和置信度，只额外返回证据文件引用与 `(document_id, block_id)`。必要引句可以保留，不复制全文件坐标／原文。
3. 租赁端按可信文件身份下载 JSON，核对实际字节 SHA256、Schema、原合同引用／Hash、解析身份、Block 存在性及范围，再绑定字段。
4. 历史恢复使用最终结果中的证据文件引用重新下载；没有文件或权限失效就显示证据不可用，不用相似文字、文件名或最后一次解析猜来源。

```json
{
  "field_key": "monthly_rent",
  "value": "10000",
  "reason": "示意说明，不是真实合同数据",
  "source_blocks": [{"document_id": "doc_example", "block_id": "p2:b3"}]
}
```

证据文件引用由工具提供，包含 `storage/file_id/file_name/byte_size/mime/sha256/schema_version`。模型可能传错引用，前端仍需校验；程序导出避免模型重抄所有原文，却不能替代引用和业务结论校验。多条款推导允许多块来源，整表框不能猜成具体单元格像素框。

文件交付是与“达美乐｜租赁智能填报”任务确认的主路径，不依赖 SSE 捕获，也不要求从 History 汇总所有分页 Block。其既有下载／Hash／JSON 校验机制可复用，但不能照搬复核业务的签名和 revision 约束。真实部署版本须由租赁端确认；Git 推送不等于 Alpha 已部署。

## 坐标与 PDF 预览的边界

供应商坐标先描述它实际识别的图像平面。`location_status=available` 只表示该平面内的框有效，不表示可直接叠到原 PDF。

- Paddle 开启展平或旋转时为 `paddle_processed_page_pixels`，本轮原件映射状态 `unavailable`；192 页历史样本全部明确启用展平。
- GLM 按实际接口返回页尺寸和像素坐标保留，不能固定当作 0～1000。已知一页小样按比例缩放吻合，但全局原件映射仍为 `unverified`。
- 缺页码、缺坐标、尺寸冲突、框越界等明确报告；不补造位置。本轮没有图像配准算法，也未导出供应商处理后的页图。

因此本轮完善“字段 → 原生 Block”的可追溯协议；“Block → 原始 PDF 高亮”需要消费方验证同一平面或另取得可靠变换，不能宣称已经全程实现。前端可以先显示块的原生文字／表格，用于核对逗号、百分号和千分位。

无需修改公共预览服务的后续路径是在租赁自定义 JS 中自建左右对照窗口，控制 PDF.js 页面与 SVG 覆盖层的滚动、缩放和翻页。依赖固定版本、匹配 worker、按需加载，可用自有静态服务或 CDN；合同文件仍走授权下载，不上传给 CDN。不能在不可控 iframe 外盖框并假设它会跟随内部页面变化。平台 CSP、网络及 worker 加载由租赁任务实测。

## Word 与其他文件后续方向

| 原件 | 读取内容 | 稳定预览与定位 |
| --- | --- | --- |
| DOCX | 直接读取段落、表格、页眉／页脚等，不为提取文字强制 OCR | 必要时同一原件只转换一次 PDF 核验副本，并记录原件／副本 Hash 与版本 |
| 文字层 PDF | 直接提取文字，核验阅读顺序、表格与字体编码 | 从同一 PDF 的文字项与变换取得位置 |
| 扫描 PDF／图片 | Paddle／GLM OCR | 原生块框加经过验证的变换 |
| 混合文件 | 文字和图像区域分别处理 | 保留各自来源与坐标空间 |

Word 转 PDF 用于固定版面，不代表必须重新 OCR；转换仍可能改变字体、分页与表格。现行 `read_file` 不提供物理坐标；当前两家 `parse_document` 接口只支持 PDF／PNG／JPEG，不自动转换 Office。这部分是设计方向，不是本轮功能。

## 实施与交付范围

本轮修改工具、缓存、文件上传、可信 History 元数据、诊断、测试和文档；不修改租赁前端、提示词、公共预览服务、数据库、环境变量或配置入口。已合并仓库实际主线 `origin/main`（仓库无 master），发布目标经用户确认由 0.12.x 升为 0.13.0。

验收分开记录：受控协议及单元回归、六份合同历史重放、两家在线小样、真实模型续读、本地／平台文件闭环、坐标样本。任何一项受外部网络阻塞都不能写成已通过；最终状态和发布提交见回归报告。


## 0.13.1 增量：处理页图证据包

本节覆盖本文件前文 0.13.0 中“只导出 JSON、未导出处理页图”的历史范围；前文实现与验收数值保留为当时记录。当前详细字段及限额见[证据指南](../../guides/document-evidence.md)。

本轮只改 DeepAgent：`export_file=true` 生成一个 ZIP，包含根 `evidence.json` 和已确认与解析页对应的供应商处理图；外层回执与内部 Schema 均为 `document-evidence-v2`，MIME 为 `application/zip`。两个参数仍是独立布尔值，默认不下载、不上传。GLM 请求仅增加原生版面可视化选项；正文适配、布局视图、Block ID、字符位置、24K／48K 分页均不改变。

1. 解析时只保存 Paddle `result.preprocessedImages` 的私有下载引用，按响应页面关联，不把 `layout_det_res` 或原 PDF 页图当作处理图。
2. 只有显式导出时，以受控无凭据下载取得图片，核验静态 PNG／JPEG、尺寸、字节及像素；图片与未压缩 JSON 和最终 ZIP 均受现有文件限制。
3. 同一次导出上传包含页图和 JSON。单图失败或缺失保留正文，包内标记 `failed/not_provided`；包超限导致导出失败，正文读取不受影响。
4. GLM 请求增加 `need_layout_visualization=true`，取得原生 `layout_visualization` 带框整页图，统一放进同一 ZIP 结构；`role=layout_visualization, annotated=true`，明确区别于 Paddle 的 `processed_page, annotated=false`。旧缓存或供应商未提供页图时保留 `not_provided`，不伪造，也不额外做 OCR。
5. `matched` 仅证明可在对应供应商处理图上按原始像素绘框；原 PDF 仍按旧的 `original_page_mapping` 状态处理。本轮不加入 SIFT／RANSAC／非线性配准，不把早期 Demo 的近似框升级成精确原件坐标。
6. 同 Run 单飞、防重复上传、授权校验与取消清理延续；导出所有已获得页面，不由模型重写文件，也不通过 SSE 抓取组装。

消费与发布顺序已与租赁任务对齐：旧 JSON/v1 与新 ZIP/v2 按 MIME＋Schema 明确分流。先由消费侧支持 ZIP，再部署新后端，不能把 ZIP 冒充旧 v1 JSON。后端补丁代码和 Tag 可先交付，Alpha 部署与租赁线上联调必须另核验。历史协议及样例保留在 `history/document-evidence-v1/`；产品后端不增加旧导出兼容参数。

验收要求：受控两家包结构、缺图／图片损坏／尺寸错配／签名地址脱敏、单飞上传与取消、24K／48K 与布局正文不变、历史合同重放、两家在线样例、本地和平台上传下载 Hash 闭环分别报告。历史重放不能作为在线成功，合成 ZIP 不能作为真实供应商页图证据。任何业务主任务、线上配置与保存均不在本轮范围。
