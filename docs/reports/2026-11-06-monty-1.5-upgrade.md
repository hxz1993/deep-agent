# Monty 1.5.0 升级与 PTC 说明核验

日期：2026-11-06。开发基线：`test / 4f4f98ce22ca`；产品版本保持 **0.15.13**，数据库保持 **013**。本次作为同版本补充更新，提交推送 `test` 并创建注释 Tag `v0.15.13`，不部署线上。运维转发说明同步保存在[依赖镜像交接](../../deploy/dependency-images.md#monty-150同版本补充发布01513)。

## 结论与影响范围

只升级 Agent 服务端的 Monty，保留 Pydantic AI **2.46.0**、Harness **0.32.0**。`requirements.txt` 将 `pydantic-monty` 从 **0.0.23** 固定为 **1.5.0**；该发行包要求 client、runtime 同为 **1.5.0**。不修改独立 Python／Skill 沙箱的依赖。

客户轨迹中的两次 PTC 失败分别来自字符串 `%` 格式化和 `json.dumps(default=str)`。新版可直接执行这两种写法；失败后的自动纠正、真实工具调用事实及文件权限仍沿用现有链路。本次没有重放客户业务任务，也不据此宣称报告业务内容已重新验收。

原始轨迹有 36 次编排调用，其中 2 次失败，两次失败的外部工具调用数均为 0，后续纠正继续执行并完成发布。第二次纠正使用 `len(str(...))`，它不等于 JSON 的 UTF-8 字节大小。原始轨迹及客户材料不纳入 Git。

版本与限制依据：[1.5.0 发行说明](https://github.com/pydantic/monty/releases/tag/v1.5.0)、[PyPI 依赖信息](https://pypi.org/project/pydantic-monty/1.5.0/)、[版本对应的限制文档](https://github.com/pydantic/monty/blob/v1.5.0/docs/limitations/index.md)。文档结论同时用实际安装包执行验证，未单凭未指定版本的文档判断支持情况。

## 运行适配与保护

- Harness 0.32.0 仍传 `max_duration_secs`；异步桥将其转换为新版的 `max_feed_duration_secs`，继续复用官方 AsyncMonty、SDK 工具定义、入参校验和返回转换。
- **执行时间口径变化**：旧版在同一个 REPL 会话内累计，新版每段代码重新计时。每段 Monty 执行最多 120 秒；外层每次 `run_code` 仍有包含工具等待的 120 秒总截止。REPL 变量继续跨段复用。
- 保留 256 MiB Monty 内存、每段最多 100 次内部调用、单个内部返回 32 MiB 等现有保护。新版支持更多标准库不代表开放宿主文件、环境变量、网络、Shell 或第三方包。
- 执行时间／内存超限后销毁可能处于半修改状态的 REPL；普通代码错误不主动清空仍有效的变量。保留已完成及结果未知的外部调用记录，不自动重放代码或写操作。
- 针对仍不支持的 JSON 钩子、`gather` 关键字参数和 `yield`，按解释器的真实异常补充纠正说明；不依据工具结果或打印内容触发该说明。

资源限制语义参见[官方资源限额说明](https://github.com/pydantic/monty/blob/v1.5.0/docs/resource-limits.md)。

## 工具说明与开发 Skill

删除已经支持能力的旧限制提示，包括字符串 `%`、内置 `format()`、JSON `default`、CSV、Decimal 和 `asyncio.sleep`。`str.format()` 在旧版探针中已经可用，不将它误记为本次新增能力。

仍明确保留的高频边界：JSON 编码 `cls` 及部分解码钩子；`asyncio.gather` 关键字参数、`create_task`／`wait_for`／`as_completed`；`yield`；生成器表达式生成列表而非惰性迭代器。标准库仍是子集，不保证每个 API 都可用。

PTC 工具说明不再携带 `wecom-doc`、`wecom-chat`、WebP 转换及 Canvas 配对等特定服务操作流程。保留通用编排、授权、预算、文件交接及占位示例；具体服务的调用前置条件和业务流程由已选 Skill 与原生工具 Schema 说明。没有改写客户 Skill。

Harness 原始描述包含旧版标准库清单和已过时的 `asyncio.sleep` 限制，因此本轮统一管理通用执行文案，保留 SDK 授权函数目录和实际调用定义，避免追加说明后仍存在相互矛盾的提示。开发 Skill 的脚本与文件参考资料同步更新，ZIP 重新构建并核验一致性。

同时纠正目录中“所有函数都是 async”的旧说明：按 SDK 的 `sequential` 标记显示真实同步／异步调用形式，防止给同步签名误加 `await`；工具执行逻辑不变。

1. 基础运行镜像需要配套包含 `pydantic-monty==1.5.0`、`pydantic-monty-client==1.5.0` 和 `pydantic-monty-runtime==1.5.0`，包括 runtime 的平台二进制文件。目标 CPU／操作系统应核验对应 wheel 可用性并做启动与 PTC 冒烟。
2. 本轮不是仅替换产品源码即可交付的变更；固定依赖镜像须先重建，不使用服务启动时自动安装。无需升级 Pydantic AI、Harness 或独立 Python 沙箱。
3. 回退需要恢复基线源码及旧版三个 Monty 包／镜像，不能只回退其中一侧：新版异步桥使用的新限额名称不适用于旧版 runtime。
4. 不新增环境变量、数据库迁移、平台配置或用户数据修改。只保留本地 8000／8010 与私有验证记录，隔离验证虚拟环境可清理。
