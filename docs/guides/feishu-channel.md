# 飞书机器人接入

飞书与企业微信共用一个渠道网关，由独立适配器处理平台差异。飞书只使用官方 SDK 的 WebSocket 长连接，服务器主动连接飞书，无需给机器人配置公网消息回调地址。服务器仍需能访问飞书的 HTTPS 和 WebSocket 服务；平台网关的登录白名单不参与飞书入站消息传输。

## 创建渠道

在 Console 的渠道页点击新建，下拉选择「飞书」，选择关联的 Agent 和会话用户。支持两种方式：

- **扫码创建**：由服务端调用飞书官方应用注册流程，展示飞书授权二维码。使用具备相应权限的飞书账号扫码，完成后保存渠道。App Secret 只在服务端接收和保存，查询接口不会返回原文。二维码不是分享给任意聊天用户的机器人入口。
- **已有应用**：在飞书开放平台创建企业自建应用、开启机器人能力，填写 App ID 和 App Secret。配置消息接收事件为长连接，并完成权限申请、版本发布和可用范围设置。

扫码并不绕过企业管理员审批、应用可用范围或发布要求。权限不足或应用尚未发布时，仍需在飞书管理侧完成配置。本轮不支持商店应用多租户安装、Lark 国际版和 HTTP 回调模式。

新二维码直接使用飞书 PersonalAgent 默认应用模板，仅预填应用名称，不附加自定义权限、事件或描述。默认清单由飞书服务端维护；已添加的事件不代表所需权限已经获批。此配置不自动更新已有应用，也不代表已实现默认模板包含的所有业务能力。

扫码任务保存在当前 API 进程，最长保留十分钟；过期、取消、保存成功或进程关闭会清除临时凭据。仍沿用单 API worker、单渠道网关的部署约束，不需要新的任务表。未保存的扫码任务不跨进程重启恢复，重新扫码即可。

## 消息和身份

私聊按发送人区分会话，群聊按群区分会话；群内不同发送人共享该群的历史，各条消息保留独立发送人 ID。群聊要求明确 @ 机器人。群访问可通过 `settings.feishu.group_allowlist` 限制，空列表表示应用可见的群；这不扩大飞书应用自身的可用范围。

飞书的 open_id 用于稳定区分发送人。SDK 能取得姓名时使用姓名辅助展示；资料权限不足时继续使用 ID，不阻塞消息处理。姓名、union_id、tenant_id 都不代替 DeepFOS 的执行账号和权限。

消息记录分别保存 sender_id、sender_name、tenant_id、thread_id；已有会话绑定表继续记录私聊／群聊类型和来源。原始群与私聊会话不混用。

数据库 008 的四列是共用来源字段，不使用渠道前缀：

| 字段 | 共用含义 | 当前企微 | 当前飞书 |
| --- | --- | --- | --- |
| sender_name | 当前消息发送人姓名 | 消息本身不提供；现有姓名仍由企微应用资料缓存及 peer_metadata 提供 | SDK 返回的姓名，无权限时为空 |
| tenant_id | 来源平台的企业／租户标识，不是 DeepFOS 租户 | 智能机器人消息不提供，留空；不拿可选应用配置冒充消息来源 | 事件 tenant_key |
| thread_id | 来源平台的话题／线程标识 | 当前机器人消息不提供，留空 | SDK conversation.thread_id |
| source_metadata | 渠道特有的扩展来源事实 | 当前无新增扩展数据 | lark_user_id、lark_union_id、lark_chat_id、lark_chat_type、lark_parent_id、lark_root_id、lark_sender_type |

只有渠道专属字段使用 `wecom_` / `lark_` 前缀，当前飞书专属内容写在 source_metadata 的 `lark_*` 键中，不新增重复列。公共列可以由后续适配器复用；当前企微缺失值不猜测、不伪造。以上字段仅用于来源追踪，不授予权限。

DeepFOS 应用及 API Key 的关联规则与企微相同。飞书凭据只用于飞书通信，不是访问财务数据的授权。业务执行继续使用渠道配置的 Agent、会话用户和已有 DeepFOS 权限链路。

## 连接和运行

复用[渠道网关部署说明](wecom-channel.md)的 API＋Gateway 启动方式，同一网关可以同时运行企微和飞书适配器。

飞书连接测试只验证应用凭据和机器人能力，不另开一条收消息的 WebSocket，避免测试连接分走正在运行的消息。凭据验证成功不等于消息事件、群 @、附件与卡片权限均已完成，实际租户仍应逐项验证。

采用官方 `lark-channel-sdk` 和 `lark-oapi`，不自行实现飞书 WebSocket 协议。SDK 内部使用模块级长连接事件循环，网关为每个飞书账号启动受控 SDK 子进程，通过匿名管道通信，避免停用一个账号影响其他账号。子进程不对外监听端口，不是另一套渠道网关；业务调度、权限和数据库仍由原网关统一负责。SDK 的接收确认发生在异步处理入队阶段，因此进程恰好在 SDK 确认后、数据库接收记录写入前退出时存在短暂丢消息窗口。持久化消息 ID 用于业务去重，但不宣称传输严格一次投递。

## 数据库与回退

本次新增 008 迁移，只给 channel_message_runs 增加可空来源字段，不新增表。原有企微配置、会话绑定、消息与附件保留。API 先升级数据库，再启动新网关。

回退代码基线为 `cd98bdc`。旧程序不使用新增列，但不要把代码回退等同于自动数据库降级。已有飞书账号或新来源数据时，008→007 会拒绝降级，必须先明确处理相应配置与数据，不能为了降级静默丢弃。

## 验收边界

无需真实账号即可验证注册成功／拒绝／过期／取消、凭据保护、配置 CRUD、SDK 消息映射、持久化去重、群内多发送人、企微回归及 Console 操作。

真实账号仍需完成：扫码授权与企业审批、应用发布、私聊收发、群 @、断线重连、附件下载、卡片权限及频率限制、姓名读取权限。受控测试不代替这些租户验收。

## 扫码二维码与应用预填

先填写渠道名称再生成二维码，会将该次名称作为 `app_preset.name` 预填至飞书创建页；留空时使用 DeepAgent。名称按生成时快照生效，后续修改本地渠道名称不会重命名已经授权的飞书应用。

AstrBot 4.28.1 直接将注册接口返回的 `verification_uri_complete` 编码为二维码；本项目使用官方 SDK 的增强注册 URL，额外携带 source、name、desc、createOnly 和 addons。addons 已由 SDK 使用 gzip + URL-safe Base64 压缩，包含本项目明确声明的消息权限与接收消息事件；因此比基础验证链接更长、二维码更密。不要仅为视觉稀疏删除权限配置。二维码不包含 App Secret；服务端在用户确认后轮询取得凭据。

官方可预填：名称、描述、头像候选 URL，权限、事件订阅、卡片回调；可限制仅创建，或为指定已有 App 发起配置更新。本项目目前预填名称/描述及所需权限/事件，不额外配置头像或卡片回调。最终仍由飞书授权页确认、租户策略决定是否可用，不承诺无需审批。

依据：AstrBot `astrbot/core/platform/sources/lark/app_registration.py`、`dashboard/src/components/platform/PlatformRegistrationAction.vue`，官方 `lark_oapi/scene/registration`（1.7.3）与 [注册文档](https://github.com/larksuite/oapi-sdk-python/blob/v2_main/_autodocs/api-reference/registration.md)。
