# 文件读取、PDF与业务回归验收

日期：2026-10-10。范围为本地读取引擎、PDF文本层和预制核验Skill，不修改租赁/BOM业务仓库、不保存业务数据。

## 工具与格式

| 格式 | 实现 | 定位与限制 |
| --- | --- | --- |
| TXT、LOG、CSV、JSON、Markdown、HTML、XML | 现有文本解码器；JSON明确美化 | 源文本行；CSV引用、HTML/XML标签不自动改写 |
| DOCX | MarkItDown正文 + python-docx元信息补充 | 固定逻辑块；补页眉、页脚、批注，保留链接及脚注；不保证合并、嵌套表格或原版面 |
| XLSX | openpyxl + 安全OOXML内容范围与显示格式检查 | 每次一个工作表，源物理行；缓存公式不重算，复杂格式以原值及格式引用表达 |
| PPTX | MarkItDown本地转换 | 固定逻辑块及幻灯片编号；文字、表格、支持的图表数据、备注；图片保留说明占位，不伪造可读取图片路径 |
| PDF | pypdf逐物理页封装 + MarkItDown本地转换 | `format=pdf`、`unit=page`；没有文本的页仍保留位置和提示；不做OCR |
| 扫描PDF、PNG、JPEG | 显式启用的Paddle/GLM `parse_document` | 原页码与OCR结果；识别错误不能在通用适配器中猜测修复 |

所有格式先固定转换结果再估算Token，全文和包装共用24K/48K预算；长单项使用Unicode字符续读。不启用视觉插件、自动OCR、收费回退或引擎配置。旧DOC/XLS/PPT不声明支持。PDF默认上传不依赖OCR配置，但显式上传白名单仍优先。

## 方法与独立答案

读取器比较使用相同原件，分别记录上次提交、当前实现、默认MarkItDown。以原始OOXML/单元格/原图为答案，不把其他引擎或模型回答当标准。模型比较使用同一实际模型和请求参数，分开比较读取器与Skill；日志只记安全事实，原件和模型输出仅保存在Git排除的私有归档。

租赁复用既有事实提取提示词和Schema，结果只写隔离JSON。BOM尚为设计原型，只测试字段与层级草稿，不宣称真实入库完成。工具调用完整性按每批位置累计核对；末批`has_more=false`不能证明前批未漏读，也不能证明源文件全部识别正确。

## 已核对的读取结果

| 样本 | 当前实现 | 默认MarkItDown | 核验 |
| --- | --- | --- | --- |
| 完整BOM工作簿 | 约0.76秒；正文163084估算Token | 约2.19秒；正文225229估算Token | 27185个非空源值等价；21表在24K真实读取24次，48K读取21次，单次下载 |
| 两份真实DOCX | 24K读取3/1次；48K读取2/1次 | 对照检查正文覆盖及补充信息 | 835/57个非空OOXML段落覆盖；不据此宣称版面无损 |
| 答案确定的Word | 链接、脚注、页眉、页脚、批注均保留 | 默认转换遗漏页眉/页脚/批注 | 五类检查点；旧原生实现则遗漏链接URL和脚注 |

BOM正文Token约减少27.6%；这是同源输出比较，不是业务提取准确率。样式空格不再误计内容格上限，但不使用全表最大列填充所有稀疏行；保留动态源行宽度，避免稀疏表性能回退。Office图片、复杂表格关系及复杂显示格式仍有明确限制。

## 验收记录

本轮使用本地已配置的同一 `deepseek-flash`、1M窗口、相同事实Schema及请求参数，运行隔离的真实工具Agent；不修改现有Agent或业务数据。生产 `build_file_toolset`、`build_document_toolset`负责授权、缓存、格式和分页，远端OCR在业务对照中仅重放同一原始结果。真实Runner压缩与权限另由集成回归覆盖。

| 业务检查 | 实测结果 | 边界 |
| --- | --- | --- |
| BOM读取器A/B，固定旧Skill说明，各3次 | 上次提交3次均被样式范围误判为单元格过多，20字段全部未知；当前59/60源值等价 | 百分比换算只用于原件明确百分比格式的字段，不把显示值与底层值混算 |
| BOM同读取器的Skill对照 | 无Skill55/60；最终Skill三次60/60 | 最终3次有2次真实读取已授权参考文件；1次未读取参考但核心定位说明下也正确，不能保证模型总遵守Skill |
| BOM完整多级草稿，各3次 | 每次输出164节点；严格核验984个字段，分别984/984、967/984、269/984 | 最后一组源行号整体偏移2行；另一组部分数量取显示舍入值。源读取正确不等于模型草稿正确，禁止据此自动入库 |
| 真实Word租赁核心事实，读取器A/B各3次 | 编号、计租面积、租期月数、起止日期5字段，六次均5/5 | 不是整份合同所有业务字段的准确率 |
| 六PDF、两供应商核心事实 | Paddle19/20，GLM20/20已核对字段 | 仅抽取金标准子集；OA与正文冲突须保留复核，不将接口成功等同于全文正确 |
| 代表合同租金与物业，各3次 | 租金18字段三次18/18；物业5字段分别4/5、5/5、1/5 | 实际Demo Planner可运行：租金3次生成提成模型，物业合法候选下3次生成表格且无结构issue；仍有模型阶梯/金额归属错误，不能宣称付款计划正确 |
| 手写正式编号的明确用户约束，3次 | 三次均保留编号空值与待原图核对阻断，其他3核心字段正确 | 原Demo提示默认OA优先，因此该业务约束必须明确传入；通用Skill不能替代业务规则 |

已按这些失败调整Skill：涉及Excel定位或计算先读表格核验参考；关键单元格按源物理行定向读取；CSV单元格换行不等于新Excel行；显示值、缓存值、公式重算及未知阻断分别表达。不增加合同编号或BOM数值答案，也不在读取器中纠正模型结果。关键金额和完整BOM草稿仍需要确定性检查或人工确认。

### PDF原件与OCR对照

六PDF共192物理页，当前PDF读取器按24K/48K均一次返回各自固定文本层内容；两档逐字符续读重建、页码与空页保留均通过。四份是全扫描，另两份是混合文件：30页中24页、24页中19页没有可提取文本。一次读完空页提示不能当作合同全文已识别。

| 原PDF物理页数 | 无文本页数 | 当前正文估算Token | 默认MarkItDown估算Token |
| ---: | ---: | ---: | ---: |
| 46 | 46 | 1655 | 0 |
| 6 | 6 | 215 | 0 |
| 55 | 55 | 1979 | 0 |
| 30 | 24 | 11897 | 10991 |
| 24 | 19 | 11892 | 11171 |
| 31 | 31 | 1115 | 0 |

增加的Token来自页标识与未提取提示，不能解释为新增OCR文字。六份当前本地转换约0.01—1.06秒；默认MarkItDown不保留空白/扫描页的可靠页索引，上次提交的read_file不支持PDF。

同一供应商原生结果重新适配后，完整缓存重建通过。Paddle六份正文估算Token从403251降至210751（约47.7%），48K总读取次数12降至8；46页样本48K从6降至2。GLM从169976降至165572（约2.6%），48K总读取次数维持7。这是历史原生结果重放，不是新的全合同在线解析，也不是OCR准确率提升。

在线确定样例分别调用真实生产适配器：Paddle2.695秒、GLM1.09秒，均complete且1页，标题及已知金额正确。真实Agent对四份扫描件读取全部适配内容；两份混合文件先读取全部物理页文本层，再按所需页调用OCR。OCR指定范围完成与文本层全页读取分别统计，不声称未读取的OCR页已经覆盖。
