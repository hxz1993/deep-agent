# D01 上下文压缩效果评测（2026-09-26）

建议保留 80% 触发值。独立合成闭环矩阵中，候选在 80% 达到 24/24 严格通过，基线为 12/24；提高到 85% 或 90% 后候选均为 21/24，耗时和调用量上升。本结果支持当前方向，不等于完整生产助手验收或最优阈值证明。

## 样本与裁决

- 主矩阵使用真实 DeepAgent Runner、真实模型、真实压缩能力与历史工具、隔离 SQLite/Event Store；业务工具是本地确定性函数替身。8 个合成场景，每臂每阈值 3 次，共 144 次；主模型 DeepSeek Flash。窗口 24,000，最大输出 2,048；普通任务至少 2 次压缩，长轮任务至少 3 次。
- D01–D04 为调参场景，D05–D08 为 v4 新数值 holdout；场景结构已知，不能称全新任务分布。v3 已用于调优，不作为未见终验。输入通过封闭历史轮次施压并略超触发点，不能据此推定生产大窗口容量。
- 原始评分的只读输出解析器把首个到最后一个大括号整体解析，遇到附带 JSON 元数据/重复同值 JSON 会误判。对全部 144 次冻结输出统一审计，发现 6 条（基线 2、候选 4）；独立匿名评分确认 36/36 字段正确。原始结果不改写，下表并列原始和裁决分。压缩协议分未调整。

## 失败边界

- 候选 80% 无业务或压缩失败，53 次压缩均完成。
- 候选 85% 裁决后 2 次业务失败，均为主模型 2,048 输出预算被推理消耗、尚未生成响应；这是输出预算耗尽，不是上下文溢窗。另 1 次业务完成但出现 request_limit_reserved 安全降级，保留最终回答请求，因此严格分为 21/24；67 次压缩完成、1 次降级失败。
- 候选 90% 裁决后 3 次业务失败：1 次主模型输出预算耗尽，1 次工具重试超限，1 次虽正常结束却未完成获准写入。70 次压缩均完成，未记录真实上下文溢窗错误；协议成功不代表业务成功。
- 基线 85% 压缩失败包含 protected_context_exceeds_target 4 次、SummaryUnavailable 6 次、summary_input_too_large 3 次，另 4 条遗留 running；90% 分别 6、10、3 次，另 6 条 running。SummaryUnavailable 是包装错误，不能一律认定为溢窗。这里的 summary_input_too_large 是摘要输入门禁，与主模型真实超窗需区分。

## 原版助手专项与跨 Provider

主矩阵的 system prompt 和六字段工具是合成资产，不是原版电子表格助手。另用内置电子表格 V91、DeepCube V34 安装包的原版提示词及全部 UI JSON Schema 做四次独立 smoke：真实 Runner、两次压缩、每次历史原文回读，固定本地 UI 确认返回，后续核对修正或生成配置。原版 prompt/schema 从包中逐字读取并记录 hash，未向评委提供 system prompt。窗口 48,000/输出 4,096，不能混入主矩阵成本。

独立匿名语义评审：候选 2/2，基线 1/2。DeepCube 两臂都保持已确认组织及参数/范围引用契约；候选电子表格正确采用最新修正。基线电子表格第二次压缩 summary_input_too_large，未完成最后修正。候选电子表格原字符串评分将“引用已失效旧值”误判，原分保留，盲评确认语义正确。

专项使用本地同步函数替代 UI 交互返回，覆盖真实参数 Schema 和返回 Schema，未覆盖浏览器 deferred dispatcher、真实业务 MCP、完整 Skill 加载、线上填报/保存或真实工作簿写入。真实业务两条 Test 会话身份仍未确认，未声称复用；现有本地综合会话与 DeepCube fixture 仅作为候选历史来源，未将正文注入 D01。

Kimi 同 profile 单例两臂各一次：候选闭环通过，2 次摘要请求均观察到原生 thinking.disabled；基线失败。单例只能作跨 Provider smoke。GPT/OpenAI Codex 配置的 OAuth 状态 disconnected，未发起模型请求，标记 skipped，不能称跨全部 Provider 已验收。
