# DeepAgent v0.14.5 累计审计与回归

日期：2026-10-23。工作分支：`test`。审计基线：`v0.14.3`（`3facbbb`）；本轮开始时 HEAD 为 `v0.14.4`（`2103608`），包含此前未提交的 PTC 与 Console 配对差异。

快照清理报告和 PTC 报告分别记录当时的版本、未提交状态及实测结果；先后由 `v0.14.4` 和本次 `v0.14.5` 接续，以本报告作为当前交付入口。历史报告中的执行次数不重复累计为本轮测试。

## 范围与结论

按累计源码差异审查，而非只检查当前未提交文件。覆盖后端执行与持久化、模型传输和异常、Console 事实配对和展示、PTC 规则，以及对应测试、缓存入口和文档。审查与定向复现由三个独立审查分工完成，再合并验证。完整差异和逐文件清单保存在私有证据目录。

| 累计变化 | 本次核对结论 |
| --- | --- |
| Schema 快照清理 | 不再写完整定义、引用或恢复来源，不在接受事务回查用户事件；每个 Run 从当前配置读取一次并在内存构造／校验输出。未重新引入配置副本。 |

## 本次追加修复

发现一项可复现遗漏：真实 Deferred Call 的持久 ToolCallPart 没有 `widget`，原 UI 耗时回退仅检查展示类型，跨 Run 完成后把人工确认等待计入工具执行时长。真实样本误算 19,871ms。

先以相同持久事件形状复现失败，再依据原 Call 的 Pending 来源排除该跨 Run 估算。没有真实执行计时时显示 Duration unknown；已保存的 `deepagent_timing` 仍优先。普通同 Run 工具的旧估算保留，不用零或伪造时间替代未知值。未新增字段或改写旧事件。

## 兼容边界与未重复项目

- 普通客户端仍只处理原有 HTTP／SSE／Live／History 及 `output_info`，不需要 Schema 或额外过滤。原始 Events 只停止新增完整配置快照和引用；旧事件不批量删除、不重写。
- 这里的兼容是业务值、状态、关联、输出身份和消费方式兼容，不声称原始帧逐字节相同：累计修复还补全了失败检查点的持久事实镜像和传输错误提示。此前 38 组协议差分以“v0.14.3 加实施前已有修复”为对照，不将其表述为原始 Tag 到本版的全累计零差异；本轮公共协议专项重新验证消费契约。
- 配置变化后续跑采用当前配置，默认同一对话配置一致，符合本轮已确认边界。旧 Pending 到新 Runner、旧损坏快照和引用的读取、请求／纠错预算由集成测试覆盖。
- 已发布旧 Runner `v0.14.3` 不能可靠接续新版无快照 Pending，会按 legacy 分支处理。回滚或混跑前须结束／取消这些 Pending，不能把“已完成历史可读”当成“旧 Runner 可续跑”。不为此重新存配置。
- 未再次执行未受本轮影响的 25,600 组合安装矩阵；该矩阵及旧运行时完整历史／回滚验证的既有执行记录见[快照清理报告](2026-10-23-structured-output-snapshot-removal.md)。本轮重新执行正式跨版本安装专项及全量中的安装、导出、配置备份／恢复测试，旧服务使用真实旧源码与当前依赖，不声称复现了旧生产镜像。
- 本轮真实模型使用 DeepSeek；其他 Provider 装配、标题、摘要、视频和订阅路径以定向／全量测试覆盖，不声称都完成真实外网请求。`identity` 可能增加网络响应字节，不改变模型 Token；上游若忽略协商仍可能有传输错误。
