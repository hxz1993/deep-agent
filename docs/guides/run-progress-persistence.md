# 运行中历史持久化

## 行为与边界

从 0.8.0 起，打开正在执行的会话，可以看到已经保存的正文、工具调用与结果，不必等整个 Run 结束。
控制台刷新或另一个页面打开会话后，通过现有 History 和 Run Status 接口跟随；不会重新发起模型请求。
企微仍使用同一 Run：阶段正文按空行累加预览，思考或工具执行时显示加载，最终只保留最后答案。

保存的是已经发生的事实，不是自动重试机制。服务崩溃后会保留已保存的过程，并将未完成部分标记中断；
不会自动执行工具、重发渠道消息或继续旧 Run。外部系统已经成功、但进程尚未来得及收到结果的操作，
只能标记结果未知/中断，不能凭推断写成成功或擅自重试。

## 同一个 Event Store，两种生命周期

| 内容 | 保存时机 | 终态 |
| --- | --- | --- |
| 用户问题 | 模型执行前 | 保留原 `user/message` |
| 正文阶段、已接受的工具调用、工具返回 | SDK 公开节点或工具事件发生时，短事务提交 | 归并成完整正式 Message Events |
| 尚未完成的流式正文/思考 | 首段及时保存，后续约 1 秒节流 | 用 SDK 完整消息校准；异常保留可恢复快照 |
| 运行检查点 `run/progress` | 每个 Run 一个稳定 Event ID，递增 revision 更新 | 与正式消息同事务封口，删除重复大正文，只留小回执 |

`chat_session_events` 仍是唯一事实来源，没有第二张聊天记录表。完整的 Message Event 仍不可变，
不会逐字符新增事件，也不会用 SSE 文本拼造已完成的模型消息。运行检查点仅供展示和中断恢复，
正常模型输入不会读取它；最终校验、工具重试过滤、Deferred 协议仍由原有规则处理。

运行互斥与数据库事务分离：Runner 保留整个 Run 的逻辑锁，检查点使用短数据库事务，
不再把运行中写入交给等待同一把逻辑锁的后台队列。正式历史和检查点封口先提交，再释放运行态。
检查点写入失败时终止本轮，不继续执行后续工具；终态写入失败如实报告，不宣称保存成功。

## 控制台与渠道

- 原页面保持现有 SSE；观察页面串行约 1 秒读取 History / Run Status。相同 Sequence 的检查点也可能更新，不能只按 Sequence 判断变化。
- 切换会话、Agent 或卸载页面，会终止观察请求并丢弃迟到结果；保留用户滚动、折叠状态和输入。
- 运行中工具快照一律只读；只有正式 `awaiting_input` 历史或完成持久化的 Deferred SSE 才能触发交互。
- 工具返回和完整阶段会及时保存；节流的半段内容在突发进程故障时仍可能损失最后一小段，不承诺逐 Token 零丢失。
- 渠道预览投递失败不重跑 Agent；最终投递的成功/失败记录仍与模型执行结果分开。

## 中断恢复与部署

检查点记录内部进程归属及租约，运行时续租。启动和周期扫描仅恢复已确认本机进程退出，
或者跨主机租约已过期的检查点，避免滚动发布期间抢走另一台服务仍在执行的 Run。
本进程已经退出执行、但终态写入失败的遗留检查点，在租约过期后也会回收；活 Run 的本地登记
覆盖 SDK 调用、压缩重试间隙及终态提交，不把暂时没有正文误判成卡死。
合法 `pending` Deferred 不属于崩溃恢复对象。恢复原子提交并幂等，重复扫描不会多保存一轮。

当前仍是一 Pod 一个 API worker；检查点租约不等于分布式取消、分布式会话锁或多副本 HA。
生产多副本仍需会话粘性路由/共享运行协调设计。本次不修改 Jenkins、数据库表结构或迁移版本。
由旧代码升级时无需手工改库；降回旧代码前应先结束新版本运行中的会话，旧代码不会恢复新检查点。
