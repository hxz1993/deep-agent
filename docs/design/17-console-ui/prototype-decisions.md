# Console UI 原型与取舍记录

> 本文件沉淀可复用结论。用户保留的统一侧边栏原型位于本课题目录；一次性 HTML、OpenDesign 工程副本和截图缓存仍在任务结束清理。

保留原型：[`Prototype DeepAgent 统一侧边栏/`](<Prototype DeepAgent 统一侧边栏/>)。
该目录从仓库根迁入，作为设计交付材料保存，不作为并行产品页面或生产实现依据。

## 1. 参考来源

本轮视觉方向综合了以下材料：

1. DeepAgent Console 既有 `/console/` 页面和全部真实功能。
2. OpenDesign 中“白色指挥台”“DeepAgent Console Bento”等阶段原型。
3. 数据流监控原型 `monitoring-instance-first-prototype.html` 的轻量企业控制台风格。
4. DevBox 的高密度服务列表、仓库列表和右侧信息甬道。
5. 用户提供的高密度列表、轻卡片、Token 占比条和 Agent 编辑界面截图。
6. DeepFOS 平台设计资产的主色、图标语义和企业工具型布局。

这些来源只用于确定信息层级、密度和视觉语言。生产结构必须重新映射到当前 Console 的真实
Agent、模型、工具、Skill、MCP、UI Tool、系统设置和会话能力，不能照搬外部模板的虚构字段。

## 2. 最终采用的组合

### 2.1 外壳

- 全宽白色顶栏优先。
- 顶栏下方使用固定纯图标一级栏。
- 配置中心使用独立资源目录，不再把一级切换放在顶栏中间。
- 浅蓝灰画布上承载白色内容表面。

### 2.2 内容页

- 对话测试沿用多栏运行指挥台，但把外层改为轻卡片并允许拖拽。
- Agent 使用卡片/列表双视图，编辑进入二级页面。
- 配置型对象优先使用“列表/目录 + 详情/表单”，不把大型编辑器塞进模态框。
- 高密度业务数据采用列表风格 A：弱表头、少分隔线、轻 hover、统一操作。
- Token 和上下文预算使用横向占比条，不只显示孤立数字。
- Skill 和 UI 工具使用轻卡片目录，详情与预览形成稳定左右布局。

### 2.3 颜色

- `#555FFF` 是唯一主交互色。
- 蓝、绿、橙、红只作为对象类型或运行语义的柔和点缀。
- 不使用多块高饱和背景，不让颜色先于信息本身被感知。

## 3. 明确舍弃的方向

- 全黑终端主题作为默认视觉。
- 复制 OpenAI Agent 编辑器的全部导航、字段和配置助手。
- 节点画布作为 Agent 的默认配置入口。
- 大面积渐变、重阴影、营销式 Hero 和过度 Bento 化。
- 所有信息都使用独立大卡片，造成纵向空间浪费。
- 表格完整网格线、每个动作都是文字链接、列宽随内容漂移。
- 为配合原型而删除真实 Console 功能或新增后端不存在的状态。
- 在仓库内长期维护一次性原型 HTML；用户指定保留的设计交付材料归入本课题，仍不作为生产依据。

## 4. 原型到代码的映射方法

```text
原型视觉块
→ 对照当前 Console 真实页面和接口字段
→ 确认现有功能不可删除
→ 映射为既有 no-build ES module
→ 使用现有主题变量和 Lucide 图标
→ 新增目标 Node 测试
→ 浏览器按真实数据逐页校正
```

原型中的名称、数量、状态和按钮如果无法对应真实接口，默认不进入生产代码。布局可以重构，
协议和运行语义不能随视觉草图变化。

## 5. 后续原型约定

- 新原型默认留在 OpenDesign、Codex visualization 或用户指定的外部设计目录，不直接放入项目源码。
- 需要长期保存时，先确认用户希望保留 HTML，还是只保留设计结论和截图。
- 仓库文档只记录稳定规则、页面映射和采用/舍弃原因。
- 新一轮设计开始前先核对当前分支源码和页面，避免基于旧模板重新分组。
- 设计确认后优先增量迁移到真实 Console，并用现有功能数据验证，而不是长期维护平行 V2 页面。
