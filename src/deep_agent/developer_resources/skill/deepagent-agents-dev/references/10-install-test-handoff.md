# 安装、迁移与交付验收

## 先区分两种Skill

本下载包是给开发人员的Coding Agent安装的知识Skill；它不会自动出现在DeepAgent业务Skill目录。业务Skill用于业务Agent运行，由管理员上传并关联。不要把两种安装目标混淆。

本开发包的 Coding 工具安装流程见[包内 README](../README.md)。以下介绍 DeepAgent 业务 Agent/Skill 的迁移与验收。

## 业务Agent跨环境迁移

源环境使用正式导出ZIP，目标使用预检，再按明确的新建/覆盖方式安装。Agent整包包含Prompt、上传Skill原包及UI工具定义；MCP与内置能力是引用，凭据和会话不随包迁移。

覆盖安装保留目标Agent ID与原会话，但会按包重建关联；单独PATCH Prompt或一个Skill则应保留未涉及关联，两者不能替代。共享Skill/UI同code内容变化可能影响其他Agent，先查看预检影响。安装成功仍需配置模型/MCP、回读和真实运行。

Skill原包的.env可能含固定服务秘密，导出会原样带上；在分发前自行确认。配置备份/恢复和Agent包迁移不是同一机制，备份恢复通常要求相同数据库Revision，不能拿ZIP兼容性推导数据库可跨版本恢复。

## 推荐验收顺序

1. 只读健康/版本/OpenAPI与管理权限。
2. 保存并回读模型、Agent、Skill、UI工具和输出定义。
3. 一次最小正常业务输入，查看完整轨迹及最终结果。
4. 缺字段、错误格式、无权限、无数据、超时、取消等负向用例。
5. 若有原生输出，覆盖失败后成功、重复通知、业务拒绝和真实Deferred；保持同Turn格式预算。
6. 文件上传→读取→生成→上传产物→下载校对，再在后续轮引用同一文件。
7. 刷新、断流、重开及旧会话只读恢复，不重复业务写入。
8. 业务写入/审批由真实执行器完成后独立回读，不能凭模型回答宣布已保存。

测试使用隔离Agent和脱敏数据，事先核对是否会调用真实收费接口或写业务。保留用户指定的原Agent、会话和附件。清理测试Agent前检查连带会话影响，不把“允许测试”当成“允许删除原资料”。

## 交付清单

目标环境及实际服务版本；Agent/Skill/客户端包版本；准确配置入口和资源编码；测试范围、用例结果、失败分类；可查看会话和可下载产物；未验证的客户网络、权限、数据库或第三方服务；所需后续动作。

明确区分：本地已修改、配置已同步、安装包已安装、页面已加载和业务已保存。依赖变化要交接固定镜像维护方；没有变化就写“依赖变更：无”。不要为文档/配置任务增加数据库迁移。

## 更新本资料

资料随其核验的产品版本配套。升级OP或Coding工具后，先读目标/info和OpenAPI，核对本包说明，再下载对应资料版。离线包不会自动升级，不能静默从公网拉最新文档套在旧环境上。
