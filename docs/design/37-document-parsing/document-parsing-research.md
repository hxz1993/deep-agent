# 复杂 PDF 文档解析：选型、成本与 DeepAgent 工具接入

核验日期：2026-09-29。本文是研究与隔离试验，不是已上线功能说明。产品基线 `test / baf3dd2 / v0.12.3`，数据库不变。

## 1. 当前建议

**先用同一组业务样本比较 MinerU 高精 VLM、百度 PaddleOCR-VL 和阿里 DocMind 增强，再决定主供应商；自部署优先验证 PaddleOCR-VL-1.6、MinerU，并把新发布的 Logics-Parsing-V3 列入挑战者。现在不能宣布某家“帕累托最优”。**

用户提到的“Minervae / Mind You”本次按 MinerU 核对。免费站点是否稳定、开源权重效果和商业 API 服务质量是三个不同问题，不能相互代替。

| 使用条件 | 建议方向 | 为什么 |
| --- | --- | --- |
| 初期量少、没有专用 GPU | 先在线 API A/B | 避免闲置机器和安装维护成本；按成功页计费更容易预算 |
| 中文复杂表格、跨页研究报告 | MinerU VLM 与 PaddleOCR 完整管线优先对照 | MPDocBench 有直接参考；仍要检查数字行列和单位 |
| 长文档、标题树、连续段落 | 加测 Logics V3 | 新模型面向跨页状态与层级；尚缺本轮生产服务验证 |
| 稳定大批量、文件不能外发、已有 GPU | 完整私有部署管线 | 前提是质量达标且机器利用率足够，不由参数量决定成本 |
| 原生文字 PDF、简单 Office | 确定性解析或 Docling 作为低成本对照 | 可省视觉推理，但不把文本抽取成功当扫描表格解析成功 |
| 图表含义、特殊图形、疑难单元格 | 保留截图，按需交给 Qwen 等视觉模型复核 | 图像定位与图表数据化不同；不让模型猜不可辨认的数值 |

本轮真实测试及未完成项见 [实验记录](evaluation/README.md)。公开成绩不是本次实测；免费 pipeline 不代表付费 VLM；没有 Key 的服务不写成“已测通过”。

**本次小样本结果：**同一合成扫描版面，MinerU免费pipeline为14/20精确数据格，本机MinerU standard为20/20，PaddleOCR-VL-1.6官方Demo也为20/20，并在显式开启chart解析后提取对4个折线图数值。MinerU standard首次产物生成后退出崩溃、独立复验成功；两者脚注仍有错误/表示差异。这些仅是定向用例结果，不是总体准确率。实际下一步优先开通百度正式API，再与MinerU精准API、阿里增强版比较。

### 新版本与阿里方向

- **PaddleOCR-VL-1.6** 已发布；[当前官方说明](https://www.paddleocr.ai/main/en/version3.x/algorithm/PaddleOCR-VL/PaddleOCR-VL-1.6.html) 报告 OmniDocBench v1.6 成绩 96.33。不能拿这个分数与上表 MP 的 80 分比较，也不能把 1.5 分数标到 1.6 商业 API 上。
- **MinerU** 的软件版本、后端与模型权重分开。当前软件已到 4.0，榜单仍标 MinerU2.5/Pro。锁定实验必须记录 software version、tier/backend、模型 revision、渲染分辨率与后处理。
- **Logics-Parsing-V3** 是阿里系新候选，9 月 22 日发布，作者称 0.8B、面向跨页和标题树。它还未出现在本次 MP 官方榜快照中，只能列为作者自报候选。[模型卡](https://huggingface.co/Logics-MLLM/Logics-Parsing-V3) 的 H100 1.39 秒/页不能外推为本机或低成本 GPU 的速度。
- Logics作者结果图自报综合85.26、标题62.33，单独保存于[作者快照](evaluation/logics-author-snapshot.json)，不加入上方第三方榜单表。本轮官方Demo返回403，未完成推理。
- **Qwen-Doc** 是研究集合，并非单一可直接订阅的解析 API；**阿里 DocMind**、**百炼 PDF 理解**、**Qwen 通用视觉模型**和 **Logics 开源解析器**必须分别评估。
- [OmniDocBench](https://github.com/opendatalab/OmniDocBench) 的更新榜还有 OvisOCR2、TeleOCR 等新候选。本轮以多页复杂表格需求收敛，不因单页新榜不断扩大安装范围；可在首轮候选未达标时补测。

## 3. 在线服务：格式、限制、输出与价格

以下为公开文档核验，不是账户实际额度保证。购买前再核对地域、具体接口与活动；结果链接有效期不等于供应商承诺删除原文件。

| 候选 | 单文件限制 | 主要输出/方式 | 已核实的长期价格口径 |
| --- | --- | --- | --- |
| MinerU 精准 API | 当前 API 管理文档：200MB、200页；批量最多200文件 | 异步，Markdown、JSON、图片 ZIP | 有免费/优先额度；未核实可承诺的长期付费单价与 SLA |
| MinerU 免登录 Agent API | 10MB、20页；固定轻量 pipeline | 异步，Markdown | 免费试验入口、有 IP 限频；不能替代高精 VLM 选型 |
| 百度商业 PaddleOCR-VL | PDF 100MB/500页；图片10MB、最长边8192px；其他支持文档按接口规则 | 异步；Markdown、布局 JSON、表格与图片信息 | 按量0.05元/成功页；1万页包440元；10万页包3800元 |
| 阿里 DocMind 大模型解析 | 文档150MB/15000页；图片20MB；须再按格式核对 | 异步；版面块、Markdown；增强可输出 HTML 表格与 chart2table | 基础0.02元/页；增强0.04元/页 |
| 百炼 PDF 理解 | PDF 150MB/256页 | PDF转为多模态输入再由Qwen理解 | 北京解析0.02元/页，新加坡0.024元/页，另加模型Token费用 |

来源：[MinerU 实时 API 文档](https://mineru.net/apiManage/docs)、[百度接口](https://cloud.baidu.com/doc/OCR/s/3mi73at9o)、[百度价格](https://cloud.baidu.com/doc/OCR/s/tlrzzplc1)、[DocMind 接口](https://help.aliyun.com/zh/document-mind/developer-reference/document-parsing-large-model-version)、[DocMind 价格](https://help.aliyun.com/zh/document-mind/product-overview/pay-as-you-go)、[百炼 PDF](https://help.aliyun.com/zh/model-studio/pdf-understanding)。

几个会影响实际接入的差别：

1. MinerU 部分旧教程写600页，与当前 API 管理文档200页不同，第一版不要按旧上限放行。免费入口关于表格/公式开关的说明也存在矛盾，以真实输出为准。
2. 百度商业 OCR 与 AI Studio PaddleOCR API 是两套开通、鉴权和额度；本表价格属于百度商业 OCR。百度提交/查询频率限制分别为2/5 QPS；不能每个页面独立疯狂轮询。
3. DocMind 完成后结果应在24小时内取回；百度文档给出的结果链接有效30天。我们的产物需要自行下载到已有受控文件存储。
4. DocMind 的电子文档0.005元/页是另一个接口，不能拿它作为复杂扫描件增强价格。其免费额度耗尽可能转后付费，应在产品接入时配置预算上限。
5. Office、HTML 等支持范围并不代表所有格式等质量。首版只验 PDF/PNG/JPEG；PPTX 中图表、讲者备注另验，XLSX 继续优先原生单元格读取。

## 4. 自部署与帕累托前沿

本机是 arm64 Mac、16GiB统一内存，没有 NVIDIA CUDA。可用于小样本安装与质量烟测，不能作为 Linux GPU 生产吞吐的代表。

| 候选 | 部署判断 | 首轮定位 |
| --- | --- | --- |
| PaddleOCR-VL-1.6 | 0.9B专用VLM，但仍包括布局、渲染和后处理；完整pipeline与裸模型不同 | 低成本私有部署重点候选 |
| MinerU | 需锁定tier、布局/OCR/表格/公式后端和VLM；4.0支持多种本地执行路径 | 表格与跨页重点候选；本机隔离验证 |
| Logics V3 | 官方快速路径依赖vLLM；MPS移植不等于官方路径已验证 | 跨页与层级挑战者，等待适配/真实GPU实测 |
| Docling | 多格式结构模型与本地转换，支持不同OCR/视觉后端 | CPU/原生文档对照，不默认视为复杂扫描精度第一 |

硬件采购不按“0.9B × 2字节”估算：该数仅接近部分权重下限，峰值还包括视觉编码、KV、分辨率、batch、布局模型及运行时。应在目标机器记录峰值显存、CPU内存、冷启动、热运行和并发；建议以8/16/24GB显存档做可行性实测，本文不宣称三个档都已支持/已通过。

许可要按固定版本核验：当前 [MinerU LICENSE](https://github.com/opendatalab/MinerU/blob/master/LICENSE.md) 是 Apache 2.0 加附加商业门槛及对外标识要求，不能写成无条件纯 Apache，也不能照抄旧版 AGPL 结论。PaddleOCR、Docling 的代码许可还需与下载权重、渲染依赖分别对齐。Logics V3 的权重与代码许可也须随选定revision确认；本文不提供一揽子商业合规结论。

### 成本模型

在线每月成本 = 页数 × 对应模式单价 + 额外模型Token + 重试/重复提交 + 存储/传输 + 人工复核。

自部署每月成本 = 机器/电力/运维固定成本 F + 页数 × 变动成本 v + 人工复核。

若质量等价且服务能力满足要求，粗略盈亏平衡页数为 `F / (在线单价 - v)`；分母≤0时无此成本拐点。还必须检查该机器能否在时限内处理这么多页。

| 成功处理量，未扣免费额度 | 阿里基础0.02 | 阿里增强0.04 | 百度按量0.05 | 百度对应包 |
| --- | ---: | ---: | ---: | ---: |
| 1万页 | 200元 | 400元 | 500元 | 440元 |
| 10万页 | 2000元 | 4000元 | 5000元 | 3800元 |

这是价格算术，**不是质量等价结论**。例如固定成本假设2000元/月、变动成本假设0.002元/页，与0.04元/页服务相比，理论拐点约52632页/月；这两个自部署输入是说明公式的假设，不是GPU市场报价或已测成本。

若只有80%的页无需返工，标价0.02元对应的“直接可用页”成本就至少0.025元，还未计返工。选择必须同时看：关键单元格完全匹配率、整文档成功率、p95耗时、每千可用页成本、维护工时与数据外发限制。没有同样本实测前只能列“候选前沿”，不画假精确的最优散点图。

## 5. 针对本需求的验收方法

最小校验单元不是“找到数字”，而是：

`文档 + 页码 + 表格 + 完整行标题 + 完整列标题 + 原始数值 + 单位 + 单元格位置`

必须覆盖：

- 合并表头、嵌套/无边框表格；跨页重复表头、拆行和合并单元格。
- `1,234.56`、括号负数、负号、`%`和`‰`、万元/亿元、科学计数、上标脚注。
- 数字或单位换行；空值、破折号、0、N/A不能互换。
- 页眉页脚与正文分开，但正文脚注/单位说明不能一并删除。
- 原生与扫描对照、低DPI/旋转/压缩、多栏论文和图文混排。
- 图表区域、标题与图例关联；有标注数值和仅靠坐标估读分别评分。

第一轮应使用12–20份、约40–60页经授权的样本，冻结原件Hash、渲染DPI、期望答案和模型版本。两名复核者校验关键表格；不要用待测模型自己出标准答案。当前两页合成样本只验证局部边界，不代表完整语料。

质量指标分开报：数字字符串完全匹配率、带行列/单位的单元格完全匹配率、漏表/漏图率、跨页关系正确率、页眉污染、静默截断。合成关键断言要求全部通过；真实样本的可接受阈值依据是否用于财务落库或仅检索阅读再确定。任何关键数字不明确必须标待复核。

稳定性测试：同一份文件至少重复3次；记录提交、排队、处理、下载各阶段以及总耗时、重试和错误码。服务可达率、解析成功率、数字正确率分别计算。一次SSL错误或一次成功都不能证明某服务长期稳定/不稳定。

## 7. 如何做成 DeepAgent 工具

### 7.1 保留当前边界

本次核对源码：[`files/toolset.py`](../../../src/deep_agent/files/toolset.py) 的 `read_file` 复用资源授权、下载缓存和有界分页；[`agent/attachment_extractors.py`](../../../src/deep_agent/agent/attachment_extractors.py) 处理文本/DOCX/XLSX。复杂 PDF 不继续加进这个工具，未来独立文档解析工具复用这些权限与存储能力。

建议第一版逻辑链路：

```text
当前会话中已授权的 file_id
  → 文件检查/页数与成本预估
  → 固定配置的解析适配器（在线或本地）
  → 结构化结果 + 页图/表格图 + 原始供应商输出
  → 数字/结构校验与警告
  → 有界读取 + 页码/位置引用 + 按需视觉复核
```

初期只接一家主服务和可人工切换的第二家对照，不做无提示多家自动上传。只有当前资源授权和部署外发策略允许时才调用线上；失败也不擅自换供应商。下载不开放任意URL，使用已授权文件及受限供应商地址。

### 7.2 建议工具契约（未实施）

`parse_document(resource, pages?, mode?)`：先返回document/job引用、状态、实际选择的解析器版本、处理页数、可读内容入口及警告。大文档返回任务状态，不让模型反复重新提交。

`read_document(document_id, page_range?, table_id?, cursor?)`：返回有界块、表格或页面证据；沿用资源授权，不因拿到document_id就允许跨用户读取。异步状态查询可以作为同一工具的操作参数，最终工具数量在实施时收敛。

结果建议保留：

- 文档Hash、解析器/模型revision、参数、原页码、渲染尺寸和坐标单位。
- block类型、阅读序、标题层级、bbox、原始文字；缺失字段明确标未提供。
- 表格HTML和cells：row/column、rowspan/colspan、完整表头路径、原始字符串、独立标准化值、单位与校验状态。
- 图片与图表裁剪引用，说明“提取图片”还是“已抽取数据”；表格跨页关系保留各源页证据。
- 处理成功/失败/跳过页、完整性警告、供应商计费信息（若提供）。不编造模型置信分数。

Markdown用于阅读，HTML/cells用于结构，JSON用于程序处理；CSV只作为显式降维导出，不能丢掉合并表头后冒充原始结构。标准化百分比时同时保存`12.50%`与`0.125`，不能用一个值覆盖原文。

### 7.3 运维与费用边界

GPU/CPU重任务进入独立worker，避免阻塞聊天API；在线任务限制并发，使用退避轮询、取消、超时和有界重试。缓存键覆盖文件Hash、解析器版本、参数与页范围，权限另校验；在供应商允许时复用任务，避免重复计费。

结果作为已有文件/Artifact产物保存，大结果不整篇塞进模型上下文。先复用文件存储与结果外置；是否需要跨进程持久任务记录应另设计，不在研究中新增表或迁移。

建议试点限制（产品建议，不是供应商上限）：PDF/PNG/JPEG、单文件≤50MB、PDF≤200页；前台先指定页范围、小批处理，后台整文档异步。加密/损坏文件明确失败；解密只使用用户提供密码，不记录密码。受控渲染器还应限制页像素、展开资源与处理时间。以更严的产品/供应商限制为准。

不要简单切成互不相关的单页后声称支持跨页表格。超过供应商限额时分块需保留相邻上下文、去重和原页映射，额外上下文页可能增加费用。
