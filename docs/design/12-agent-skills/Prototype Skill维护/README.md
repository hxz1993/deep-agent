## 建议方案

默认「按 Agent」查找 Skill，保留「按用途 / 共享 Skill / 全部 Skill」作为不同浏览视角。Skill 仍为独立共享资源，不增加唯一所属 Agent。同一 Skill 可出现在多个 Agent 或用途分组中；全库数量、共享列表均按编码去重。

列表先显示名称、用途、版本、引用 Agent 和资源数量，点击再打开详情；默认不展开整篇正文、Frontmatter 与资源树，降低浏览负担。

## 可体验内容

- 四种视图、Agent 切换、用途分组、共享引用范围、自定义/内置及未关联筛选。
- 名称、编码、用途和引用 Agent 搜索；列表计数、空结果和清空。
- Skill 详情：说明、示例文件、完整 SKILL.md、引用 Agent。
- 共享编辑影响提示；从 Agent 视角创建独立副本，仅替换当前 Agent 的引用。
- 管理多 Agent 关联、解除单个关联、关联已有 Skill。解除关联不删除 Skill；没有引用的资源在未关联分组保留。
- 调整多选用途分组、模拟上传入口、导出示例 JSON、主题切换、重置示例。
- 原型编辑结果在独立浏览器 localStorage 键 `deepagent-skill-management-prototype-v1` 中保留；重置只影响原型。

建议操作：三一Demo助手 → 合并财务模型分析 → 编辑共享 Skill → 查看受影响 Agent → 为当前 Agent 复制一份后编辑 → 切到电子表格智能助手，对比仍引用的原 Skill。

## 与当前产品的边界

- 所有 Agent 名称、关联、版本、资源和正文均为演示数据；部分名称沿用本次讨论，**不代表 Alpha 或本地的真实完整配置**。
- 无真实业务请求、安装、上传、保存、模型调用或环境鉴权。预览服务 CSP 禁止 `fetch` / WebSocket 等网络连接。导出的是原型 JSON，不是可安装 ZIP。
- 按 Agent、共享、未关联、全库去重可由既有 Agent—Skill 关联推导，不需要给 Skill 新增唯一归属。
- **按用途是可选增量设计**。目前没有假定产品已保存这类分组；正式落地前须确认是否需要分类及其存储方式，不在查询时按名称猜分类。
- 复制并替换、集中管理引用属于交互提案，不代表本轮增加了这些管理 API。
- 保留现有产品能力；原型不承担真实的 ZIP 校验、安装替换、版本发布、资源读取权限或删除流程。
