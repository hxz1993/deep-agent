# DeepAgent Console UI 实施规范

> 适用范围：`console/`。
>
> 本文规定新增或修改 Console UI 时必须遵守的实施方法。视觉背景与历史取舍见
> [`../design/17-console-ui/`](../design/17-console-ui/README.md)，真实行为始终以当前源码和接口为准。

## 1. 先对齐，再动手

每次 UI 修改前必须完成以下检查：

1. 在当前页面和至少一个相邻页面中找到同类布局或控件。
2. 确认已有 HTML 结构、CSS 类、主题变量、Lucide 图标和交互实现能否复用。
3. 明确本次变化属于页面导航、数据列表、字段表单、选择控件、状态反馈还是确认弹层。
4. 先写出字段与真实业务对象的对应关系，再决定标题、标签和辅助说明。

不得因为新功能独立，就为它另造一套视觉体系、控件或页面壳。

## 2. 信息层级与容器

容器只在它表达真实边界时使用：

- 独立页面或弹层表面。
- 独立滚动区域或左右、上下分栏。
- 可选择的资源、方案或状态项。
- 需要隔离的错误、警告、安全信息或空状态。

以下情况默认不增加边框、底色、圆角或阴影：

- 普通字段组。
- 条件显隐后的字段区域。
- 仅为两行字段排版而存在的 DOM 包装。
- 已经位于弹层或页面表面中的说明文字。

条件区域可以保留无视觉样式的语义包装，用于显隐和布局；不得把每组字段再次画成卡片。
同一层级只保留一个主要表面，避免“页面卡片 → 弹层 → 配置卡片 → 字段容器”的重复嵌套。

## 3. 页面、弹层与表单

- 页面沿用现有标题栏、资源目录、列表、详情区和操作位置，不重新发明导航。
- 简短、集中且必须确认保存的配置使用标准 Console 弹层：一个 Header、一个 Body、一个 Footer。
- 弹层正文中的字段直接排版；普通两字段可同排，主凭据或长字段另起一行。
- 保存、取消只出现在标准 Footer；页面式编辑则沿用页面标题栏操作，不混用两套模式。
- 字段标签位于控件上方；必填、错误和保留旧值等真实状态就近反馈。
- 辅助文字只解释约束、影响或例外，不重复“请输入某字段”这类显而易见的操作。

## 4. 控件语义

- 二选一且会改变后续字段时，默认使用紧凑分段控件；只有每个选项确实需要多行独立说明时才使用方案卡。普通枚举使用 Console 自定义下拉。
- 有自由输入又有推荐值时，使用现有可输入选择框，不用原生浏览器下拉。
- 同一页面同类控件必须复用同一结构、尺寸、焦点态、展开层和键盘行为。
- Console 图标只使用本地 Lucide 线性图标；尺寸、描边和颜色与相邻目录一致。
- 页面及弹框沿用既有 `32px` 控件高度，`28px` 只用于高密度行内操作，不因视觉参考改变控件尺寸。
- 选中态使用平台主色，状态色只表达成功、警告、错误等业务语义。

## 5. 命名与文案

- 标题和字段名必须指向真实业务对象，避免含糊的“方式”“类型”“设置”等泛化名称。
- 模式选择组统一使用“搜索模式”；实际 Provider 字段仍明确标为 `Provider`。
- 同一概念在页面摘要、弹层、错误和文档中使用同一名称。
- 已由控件自身表达的信息不重复写在副标题、标签和说明中。
- 配置摘要只回显当前生效值；支持范围、例外和操作说明不得重复堆在摘要区。
- 单一配置值优先与页面标题、短说明和编辑操作排在同一行，不额外占用一整行属性区域。
- 不展示后端不存在的状态，不把推断写成事实，不用说明文字掩盖缺失的交互或校验。

## 6. 列表、卡片与状态

- 配置对象优先使用现有高密度列表、目录加详情或紧凑表单。
- 卡片只用于可选择对象或需要独立扫描的资源；普通属性不用卡片。
- 表格沿用弱表头、少分隔线、稳定列宽和统一行内操作，不绘制完整单元格网格。
- 页面级操作的成功或失败使用 Toast；弹层内的连接测试、草稿校验等即时动作必须在当前弹层内就近反馈，避免状态落到弹层背后。
- 网络图片工具结果只按已审计的HTTP(S)引用懒加载预览，使用`referrerpolicy=no-referrer`并始终提供
  “打开原图”回退；不得为了预览上传附件、落库图片字节或嵌入Base64。
- 不调用浏览器原生 `alert`、`confirm`、`prompt`。

## 7. 主题与响应式

- light、paper、dark、contrast 只改变 token，不改变信息结构和操作顺序。
- 桌面和窄屏保持同一交互模型；断点只调整列数、宽度和滚动归属。
- 下拉菜单、Tooltip 和弹层不得被父容器裁切，也不得超出可视区域。
- 重要操作不能因宽度变化被隐藏或覆盖。

## 8. 实施与验收门禁

代码完成前逐项确认：

- [ ] 已对照当前页面和相邻页面的真实实现。
- [ ] 没有新增无语义的容器、卡片、底色、边框或阴影。
- [ ] 没有直接展示原生 `select`、原生确认框或第二套图标库；原生 select 可作为公共适配器的数据源。
- [ ] 字段名准确表达真实业务对象，辅助文案只保留必要信息。
- [ ] 字段布局、按钮位置、控件高度和选中态与相邻页面一致。
- [ ] 条件字段、错误、保存、取消和重新打开后的状态均已验证。
- [ ] 纯 UI 修改完成一次受影响桌面流程冒烟，视觉由用户确认；涉及共享布局或主题变量时按实际风险抽查，不默认扩大为移动端与四主题全矩阵。
- [ ] 运行相关 `node --check` 与目标 Node 测试，并在真实 `/console/` 页面完成浏览器检查。
- [ ] 浏览器、测试子进程和临时产物已清理；没有覆盖无关工作区改动。

自动化测试只能保护结构和行为，不能证明视觉一致。浏览器检查必须包含控件展开、条件切换、
弹层边界和实际信息密度，不能只确认页面能打开。

## 9. 当前 Web Search 示例

- 搜索服务采用 DeepSeek、Kimi、网络搜索服务商三段切换，前两者复用本地品牌图标，后者使用 globe 图标；标题右侧用文字选项“暂不配置”表达清空草稿，保存后才生效。空配置与旧 native 显示“未配置”，弹框选中“暂不配置”。
- API Key 回显后端脱敏值，输入新值转为密码显示；原掩码或留空不提交替换。切换供应商不得串用密钥。
- 常规页的网络搜索采用有细边框的配置卡：名称和说明分两行，右侧显示当前 Provider 与编辑操作；弹框使用固定宽高，条件切换不得改变外框尺寸。
- DeepSeek 默认 Flash，直接展示搜索模型；Kimi 不显示模型。第三方入口再选择具体搜索供应商；凭据来源或 API Key 另起一行。
- DeepSeek/Kimi 的凭据配置分两行：第一行“凭据”在左、精简的来源选择在右，第二行只出现对应的会话 Provider 或 API Key 控件。
- 条件字段区域只负责布局和显隐，不绘制额外配置卡片。
- DeepSeek/Kimi 可沿用同类型会话 Provider 或单独填写 API Key；其他 Provider 只展示必要字段。
- 显而易见的“输入某 Provider API Key”提示不展示。
- 连接测试只在当前弹层内显示“测试中 / 成功 / 简短错误”，不展示搜索问题或结果正文；草稿字段变化后清空旧结果。

## 10. 公共弹框与字段组件

- 弹框表面统一使用 `--console-surface`，与 Agent/MCP 编辑页一致；只读字段和表头使用 `--console-readonly-surface`，可编辑控件使用基础表面与边框，错误和提醒使用各自状态色。不得用 `--bg-soft` / `--bg-elev` 染满整张弹窗。
- 弹框严格沿用 Console 已有主题色、按钮和输入框高度、内边距及字段间距。视觉参考只辅助信息排版，不覆盖主题或强制复制参考图尺寸；`console/ui-dialogs.css` 仅维护布局。
- 简单字段使用 `dialog-field-grid` 两列，长字段整行；窄屏折成一列。正文独立滚动，Footer 操作始终可见。不要在业务模块重复覆盖公共尺寸。
- 短说明用 `field-label-row` 中的 `field-subtitle` 放在标题右侧；长约束使用 `field-help` 问号及 `field-help-tooltip`，设置 `tabindex="0"`、`aria-describedby` 和 `role="tooltip"`。错误和操作进度继续就近展示，不收进提示。
- `ui-field-help.js` / `ui-channel-hints.css` 提供统一悬停与焦点提示：顶层展示、边界约束、Esc 只关闭当前提示。
- `ui-editable-select.js` 用于同时允许推荐选项、自由输入和清空的字段，例如 Widget；用一个输入框完成，不拆成下拉加第二个编码输入。
- `ui-select.js` / `ui-select.css` 由 `main.js` 一次初始化，自动增强普通单选 select，包括动态插入的表单。原生元素保留 id、name、value、FormData 和校验契约；视觉和键盘操作由公共 combobox / listbox 承担。
- 业务代码继续更新原生 select 的选项或 value，不直接操作适配器 DOM。已有专用搜索选择器保留；用 `aria-hidden` 或 `data-native-select="true"` 排除其内部数据源，避免双重增强。
- 工作台按钮叫“调试”，未选 App 时回显“不分应用”；会话历史属性缺失沿用各字段既有中文或横杠与字体颜色。不要自动翻译原始值或改写业务状态。


## 11. 统一视觉基线与公共实现（2026-09-24）

新增页面先从 `console/ui-primitives.css` 取公共 token 和类，再组合业务布局。该文件承载公共尺寸与配置列表基础样式；`console.css`、`configuration/configuration.css` 及业务 CSS 只保留页面布局和明确的语义变体。不要通过文件末尾持续追加覆盖来定义新的基线。

| 语义 | Token / 取值 | 使用范围 |
| --- | --- | --- |
| 正文 | `--ui-font-body: 13px` | 字段值、普通配置说明、列表主文字 |
| 辅助文字 | `--ui-font-helper: 12px` | 搜索、按钮、表头、次级说明、摘要 |
| 元信息 | `--ui-font-meta: 11px` | 环境变量编码等低优先级信息，不用于主要操作 |
| 详情分组/弹框标题 | `--ui-font-title: 16px`、`--ui-line-title: 24px`、字重 600 | 同层详情分组及弹框标题；一级页面标题16px/20px，字段组13px |
| 控件 | `--ui-control-height: 32px`、`--ui-control-compact: 28px` | 标准按钮/输入/下拉；紧凑值用于行内操作 |
| 圆角 | `--ui-radius: 8px`、`--ui-radius-inner: 6px`、`--ui-radius-overlay: 12px` | 控件/表格/选择卡；分段内部选项；弹框。状态胶囊保留圆形 |
| 图标 | `--ui-icon: 14px`、`--ui-icon-action: 16px`、`--ui-icon-title: 18px` | 搜索/小计数；按钮/关闭；分组标题 |
| 组内/组间 | `--ui-group-content-gap: 8px`、`--ui-group-gap: 28px` | 标题至正文、同级详情组之间 |
| 设置详情宽度 | `--ui-detail-max-width: 1080px` | 常规/模型/运维统一限宽，左对齐，可随窗口收缩 |

颜色使用现有主题 token：正文 `--text`、次级 `--text-dim`、更弱信息 `--text-faint`，选中态 `--accent` / `--accent-soft`，表面 `--console-surface`、只读表面 `--console-readonly-surface`、边框 `--console-card-border`。禁止给普通页面另定一套灰色或品牌紫色。原始协议编码使用 `--mono`，中文说明与按钮不用等宽字体。

### 分组、标题和滚动

- 公共结构为 `.console-stack` 中放 `.console-section`，内部由 `.console-section-heading`、`.console-section-title`、`.console-section-actions`、`.console-section-content` 组成。既有全局配置类兼容同一规则，不复制一套数字。
- 标题栏统一 32px，标题文字行高 24px、顶对齐；操作放右侧，避免各页因按钮而改变标题位置。标题栏到内容 8px，同级组之间 28px，不额外叠加 margin，也不用横线补分组。
- 顶部主页面标题、副标题占自己的行；详情标题不是另一层页面卡片。普通无分组页面不强行加组名。
- 常规/模型/运维详情左右各留 24px，滚动条在留白外侧。内容独立滚动；左右目录的细分隔线上下留白，不顶到页面边缘。
- 独立编辑页、目录加详情、聊天和诊断多栏各保留真实空间需求；1080px不是所有控制台页面的全局硬限宽。

### 表格、分页和搜索

- 普通管理列表复用 `.table-wrap.console-list-a > table.data-table`，不引入表格库。表头 36px、12px弱色，单元格默认 `9px 12px`，行高随单行/双行内容增长；弱横线，无竖向网格。`min-height` 不能当作表格单元格的固定行高契约。
- 主名称与编码需要并排或两行时，用主次字重与颜色区分；长编码允许换行/省略并保留完整信息入口，不挤掉操作。时间/计数可用等宽数字。
- 操作列右对齐，图标按钮有名称和可见焦点；分页归属当前表格，在表格下方右对齐，不横跨左侧目录。排序和筛选变化继续使用现有分页逻辑。
- `.console-search` 是搜索框公共样式；已有 `.agent-search`、模型搜索、成员搜索复用同一基线：32px高、8px圆角、14px搜索图标、12px文字。宽度可按空间调整，不单独改高度和焦点态。
- 带前置图标的筛选下拉/输入复用 `.console-control-with-icon`（现有诊断类为兼容入口）：图标16px、左内距 `--ui-control-icon-inset: 12px`、文字间距 `--ui-control-icon-gap: 8px`，文字起点36px；图标在32px控件内垂直居中。会话、用量、渠道的时间/Agent筛选共用，业务CSS不得再覆盖 left/top/padding-left；无前置图标的下拉不预留图标空间。
- 模型目录的搜索/筛选在左、数量及最近更新在右；搜索必须保留中文名称与编码检索能力。不要为视觉统一增加新的筛选条件。
- 成员缓存等高密度表允许紧凑行；诊断事件、日志、轨迹及聊天正文保留自己的密度，不套管理表格字号到内容正文。

### 按钮、选择和反馈

- 主操作使用现有 `.btn.primary`，普通操作 `.btn`，危险操作沿用 danger 状态；字体12px，普通高32px，行内高28px。文字+图标保持一致间距，不在业务CSS改圆角和内边距。
- 关闭按钮统一可点击热区28px、图标16px；不得用裸 SVG 或字符 × 代替。纯图标按钮须有 `aria-label`，所有操作保留键盘焦点。
- 模式切换使用现有分段结构，例如工具 UI/内置、渠道/企微应用；内容页签使用轻量页签，二级导航使用无边框选中底色。三者语义不同，不互相替代。
- Agent 内置/UI/MCP 批量选择是一个支持未选、半选、全选的复选框；单个资源开关只控制该包，计数是摘要，不恢复逐工具选择。
- 状态值本身可导航时，图标与值共用一个热区，例如网络搜索的铅笔+供应商；不再额外堆一个“前往设置”文字链接。
- 空值用弱色正常字体；加载、失败、禁用不靠颜色单独表达。Toast用于页面动作，弹框内即时反馈保持在当前弹框。

### 现有模块归属与允许差异

| 内容 | 复用入口 / 边界 |
| --- | --- |
| 单选下拉 | `ui-select.js` / `ui-select.css`，保留原 select 数据契约，由公共适配器增强 |
| 可输入推荐项 | `ui-editable-select.js` / `ui-tool-editor.css`，不另做双控件 |
| 字段提示 | `ui-field-help.js` / `ui-channel-hints.css`，悬停与键盘同等可用 |
| 弹框字段排版 | `ui-dialogs.css`，普通双列12px间距，长字段跨列，表面/尺寸取公共规则 |
| 资源主从页 | `ui-resource-layout.css`，Provider/Skill/UI工具/内置工具共用目录与详情分栏 |
| 普通图标 | `vendor/lucide.min.js`，模板 `data-lucide`，动态内容插入后统一 `createIcons()` |
| 品牌图标 | 现有本地Provider/平台资产；不能用emoji替代，也不新增在线图标依赖 |
| 表格/列表逻辑 | 现有各业务ES模块；公共CSS只负责呈现，不改分页、API、保存和权限语义 |

Provider 身份回显统一取后端类型目录的显示名，列表按创建时间、ID 稳定排序，不另加括号别名或前端字母排序。配置目录、会话模型选择和用量明细都按 `provider_type` 使用同一供应商本地图标；新增类型时逐一核对这些入口。ChatGPT 订阅使用 OpenAI 官方完整 Blossom 图标，浅色主题呈黑色、暗色主题呈白色，留白由图标自身保留；不要裁切图形。品牌底色应克制，不盖过图形。API Key 状态使用钥匙图标，订阅授权状态使用带勾用户图标；地址模式在 URL 后用无边框的小号灰底胶囊显示“默认”或“自定义”，不放标题旁。实验开关关闭时，新建弹框隐藏整组选接入方式，保留原 API 表单尺寸。

Agent能力选择卡、全局二级导航使用无边框选中底色；Provider/Skill/工具包资源目录保留可扫描的选择卡。网络搜索是一项可编辑配置卡，数据库信息和运行设置只读。运行设置只展示运维人员可能需要调整的少量 Agent 行为参数，使用横向 `.cap-tab` 按钮切换分组，一次显示一组；搜索跨组。数据库连接另有摘要，不在运行设置重复展示主机、端口或凭据；部署启动、内部子进程和本地开发变量也不展示。新增环境变量先判断是否真的需要在 Console 运维页查看，不按代码变量总量自动铺开。MCP工具资源弹框、集成双栏弹框保留固定尺寸与独立滚动。代码、Markdown、聊天消息、图表标签及日志不是普通设置文案，其字号和换行按内容保持，不用全局通配符覆盖。

实现完成须检查 CSS 加载顺序与最终计算样式；删除已永久失效的旧覆盖。纯UI默认只做必要静态检查与一次受影响桌面冒烟，不能把测试通过写成视觉已获用户确认，不为样式变更自动升级版本、提交或推送。

### 公共样式归属与去重（2026-09-24）

- `ui-primitives.css` 统一拥有按钮（`.btn` / 诊断兼容类 `.diagnostics-button`）、输入（`.console-input`）、搜索、分组、分页和分段切换（`.console-segmented` / 原有模式切换类）的外观基线。业务文件只写位置、宽度、滚动和语义变体，不复制高度/字号/圆角/图标尺寸。
- `ui-select.css` 同时服务 `.da-select-*` 原生适配器与 `.console-select-*` 现有控制器。两者触发器、选项、选中/禁用/焦点态共用规则；浮层定位保留区别：前者 fixed/Popover，后者相对控件定位。不为样式统一重写已验证的选择与键盘逻辑。新普通选择器优先 `ui-select.js`。
- 普通按钮32px，行内 `.btn.compact` / `.btn-sm` 28px；文本按钮以 `.text` 表达。分页复用 `.console-pagination`，原有模型/诊断分页为同一规则的兼容类；所在栏和页码信息布局由页面负责。
- 页面不得新增与现有类等价的 `xxx-button` / `xxx-select` 样式。需要新变体时，在公共拥有层新增有语义的 modifier，并同时删除原位置的重复声明；禁止仅在文件末尾追加覆盖。
- 诊断日志的24px记录行、28px行内查询操作、只读详情、图表、聊天正文属于明确的密度变体。它们保留专用布局，不因普通配置控件统一而被拉高。
- 验收以浏览器最终计算样式及真实展开/切换为准；源文件测试应引用公共拥有层，不断言旧页面里必须存在重复样式。
