# 诊断会话：概览、列表与只读排查

诊断中心包含「日志」「会话」两个入口。会话入口把统计概览和完整列表放在同一页面，
进入具体会话后复用对话测试的正文、工具、轨迹和右侧信息栏，但不提供执行或修改能力。
统计读取现有 `chat_sessions + chat_session_events`，不从诊断日志推算，不新增统计表、事件或迁移。
日志的实例范围、保留期和文件约束见[诊断日志指南](diagnostic-logs.md)。

## 入口与筛选

- 概览：`/console/#/diagnostics/sessions/overview`；本次访问期间记住最后使用的概览或列表。
- 列表：`/console/#/diagnostics/sessions/list`。
- 详情：`/console/#/diagnostics/sessions/{完整 Session ID}`；直达详情不受列表时间范围限制。
- 公共筛选：Agent、时间；普通会话与渠道会话统一纳入，不提供来源筛选。平台用户与状态筛选在列表搜索同行右侧无边框展示，与关键词、状态和下钻条件仅影响列表，不影响概览聚合。
- 默认最近 7 天，可选最近 24 小时、7 天、30 天或自定义；范围最多 31 天。
- 接口传 UTC，页面按浏览器本地时区显示和分日，时间区间为左闭右开 `[start, end)`。
  翻页、切换视图固定实际起止时间，点击工具栏“查询”重新计算相对时间；自定义时间保持不变，搜索不自动放宽其他条件。
- 列表固定每页 50 条；按最近活动倒序，同时间按 Session ID 稳定排序。
  「搜索会话名称或 ID」中，名称按字面量模糊匹配；Session ID 按完整值相等匹配，不做 ID 前缀 / 包含匹配。
  两者以 OR 合并，输入完整 ID 时仍可能匹配包含该文本的会话名称；`%`、`_` 不作为通配符。
  Session ID 允许业务自定义，不按 32 位十六进制格式猜测搜索类型；精确查看具体会话使用详情路径中的完整 ID。

页面继承 Console 白底和主题。“重置”常显在查询右侧，为无边框文字按钮；概览/列表使用 Agent 同款图标切换，固定在第二行右侧。
第二行只保留下钻条件、加载提示和视图操作，不常驻显示时间范围。时间框中部打开周期下拉，右侧预设显示 Information、自定义显示设置图标；当前范围与时区在浮层查看，自定义起止时间也在浮层编辑并应用。控件显隐与加载提示不挤动内容区起点。
最近提问为38px单行，右侧“Agent · 用户名 · MM-DD HH:mm”按自然宽度整体右对齐，完整时间保留悬停提示。列表为50px双行，名称下方显示“Session ID前8位 · 最新提问”，ID与问题同色，不加重复说明前缀。分隔点与复制图标共用固定位置，行悬停或键盘聚焦时原位切换，复制成功短暂显示对勾；无悬停设备直接显示复制图标。
列表6列（会话、Agent、用户、App ID、状态、最近活动）支持表头分隔处拖拽（或方向键）调整相邻列宽，受最小/最大范围约束；行点击进入详情，不另设末尾图标。分页位于表格底部右侧（前页、当前/总页、后页），去除多余边框；表格填满分页上方工作区。图表按实际宽度重算横坐标，文字、圆点尺寸保持固定。

所有用户维度指 `chat_sessions.user_id` 对应的**平台账号**。渠道会话仍归属于配置的平台账号，
此处不按企微实际发送人统计。渠道详情使用独立的消息账本统计发送人，见下文「渠道统计」；历史来源信息只读展示。

## 统计口径

真实事件的发生时间取首次记录的 `created_at`，辅助更新不会把旧问题移到今天。
一次概览共享同一实际范围，概览下钻与列表共用服务端筛选。不同请求不是永久快照，真实新数据可能改变总数。

| **指标 / 内容** | **范围内的计算口径** |
| --- | --- |
| 会话数 | 有真实事件发生的不同 Session，加上范围内创建的空会话 |
| 提问数 | 真实 `user/message` 输入条数；仅附件或上下文引用的输入也计入 |
| 活跃用户 | 有真实用户输入的不同平台 User ID；跨 Agent、跨渠道仍去重 |
| 含异常会话 | 出现 `execution/error` 的不同 Session；同一会话多次异常只计一次 |
| 提问趋势 | 按用户输入发生时间分日计数，无提问日期补零 |
| Agent 分布 / 活跃账号 | 按范围内提问数排序；分别先展示 8 个 Agent、5 个账号，可展开 |
| 最近提问 | 每个会话取筛选时间范围内的第一条真实输入，再按该输入发生时间倒序，最多展示 10 个会话；点击定位这条输入 |
| 最近异常 | 执行异常按发生时间倒序，最多展示 5 条，不按会话去重 |

工具结果、模型重试、UI 续跑、恢复执行和旧 RUN 记录不算用户提问；相同内容的真正再次发送算另一条输入。
重命名和压缩可形成会话活动，但不增加提问数。主动停止、执行继续中的工具失败不等于执行异常。
仅附件、上下文输入分别显示「附件输入」「上下文输入」；列表没有范围内问题时明确说明，不用范围外问题替代。
已删除会话不计入当前库统计；落库前被拒绝或失败且没有事件的请求只在已有日志中排查。

「范围内有执行异常」与「最近一轮异常」是两个条件：曾失败、后来成功的会话仍可由前者找到。
状态筛选先限定候选会话，再批量求整会话的最新执行状态，COUNT 与分页使用相同口径；不会先分页再筛状态。活动时间排序也从候选会话的真实事件批量聚合。普通会话列表先筛选和分页，再读取当前页的消息、附件及轮次数，不聚合其他页的完整历史。

查询超时与查询繁忙分别提示；失败时显示列表未加载并禁用分页，不把请求失败显示成“没有匹配会话”或“共 0 项”。

后端统一解释状态：可信活动执行为进行中，正式等待为待操作，明确完成 / 停止 / 异常分别显示终态；
有输入但不能确认终态显示未确认，无执行内容显示未开始。不能用活动注册表缺席或最后一次工具成功判定完成。

## 页面联动

以下「当前筛选」指当前 Agent 和时间。普通概览 / 列表切换保留公共筛选；列表私有条件保留在本次访问内存中，切概览时不传入URL或聚合请求，明确下钻才收窄条件。

| **起点** | **操作与落点** |
| --- | --- |
| 概览 · 会话数 | 进入列表，携带当前筛选 |
| 概览 · 提问数 | 进入列表，增加「有提问」；列表仍按会话计数 |
| 概览 · 活跃用户数 | 展开并定位本页活跃平台账号区域 |
| 概览 · 含异常会话数 | 进入列表，增加「范围内有执行异常」 |
| 提问趋势 | 点击一天进入列表，收窄到该天并增加「有提问」 |
| Agent 分布 / 活跃账号 | 进入列表，追加所选 Agent / 平台 User ID，保留其他条件 |
| 最近提问 · 查看全部 | 进入列表，携带当前筛选和「有提问」，不打开问题弹框 |
| 最近提问 / 最近异常 | 进入正确会话的对话 / 轨迹视图，定位对应消息 / 异常事件 |
| 会话列表 | 点击行进入完整详情；返回恢复筛选、分页和滚动 |
| 日志内容行 | 打开右侧日志详情，不切换页面 |
| 日志行或详情 · Session ID | 仅按完整 Session ID 打开对应会话，不携带 Run ID |
| 页面返回 / 浏览器后退 | 恢复来源视图和原查询位置；只接受 Console 内部白名单路由 |

会话详情不设置跳日志或轮次关联日志入口，避免在现有对话测试布局上叠加诊断操作。
日志跳会话不受旧列表筛选限制，使用完整 Session ID；Run ID 仅作为日志详情值展示，不提供筛选或跳转。
会话删除、事件缺失、日志过期分别提示。会话历史比当前实例日志更久是正常情况，不代表会话异常。

## 只读详情与历史真实性

详情初始读取元信息与 Conversation History；轨迹在切换到轨迹或需要解析轮次定位时按需读取，
每页最多 500 条，读取完 `next_after_sequence` 才声明完整。正文投影失败会显示错误，仍可切换轨迹排查。
运行中仅展示已保存内容，手动刷新更新；不保证尚未落库的半段输出可见，不订阅 SSE、不后台轮询。

- 正文、Markdown、思考、工具过程、PTC、轨迹节点和信息栏使用共享展示层；诊断状态独立于测试会话。
- 不渲染发送框、上传入口或可提交工具 widget，不挂载发送、重试、停止、审批、改名、删除、压缩处理器。
  切页、关闭、刷新只终止诊断读取，不取消真实 Agent 执行。
- 用户、App、Space 和渠道来自被查会话已保存的信息；未记录的 Language / Header 不使用管理员测试上下文补齐。
- 模型、使用量和结束信息来自真实历史；同一模型消息的多个部分不重复累计 Token。
  未知值不以零代替。上下文在读取详情时独立估算，标题提示说明为当前配置估算而非历史快照；配置缺失只影响该区。
- 附件保留原文件权限。管理员能看会话不等于能读取所有外部文件；不冒用所有者身份，不新增跨用户下载代理。
- 工具轨迹的 Summary 为已登记的工具产物逐个提供下载，包括 JSON、TXT、图片、文档证据包和外置工具结果。已存储的图片也可以预览。平台文件沿用平台下载权限，本地文件沿用会话授权下载入口。
  无权限、文件不存在或链接过期保留附件记录与失败提示。

## 管理员只读 API

以下接口均位于 `/api/v1/diagnostics/sessions`，每次请求重新校验现有企业管理员权限并返回
`Cache-Control: no-store`。被查询的 `user_id` 是条件，不是调用者身份；普通 `/sessions` 系列仍校验所有者。
权限范围不跨部署、不扩展租户，不伪造 user Header 或借用目标用户 Token。

| **GET 路径（相对上述前缀）** | **职责 / 主要响应** |
| --- | --- |
| `/overview` | `range`、`generated_at`、`metrics`、`trend`、`agents`、`active_users`、`recent_questions`、`recent_errors`、`agent_options`、`users` |
| 空路径 | `items`、`total`、`limit`、`offset`、`range`、`agent_options`、`users`；当前页摘要和状态 |
| `/users` | 当前时间与 Agent 范围内的去重用户候选；支持 ID / Username / Nickname / Email 搜索与 `after` 游标 |
| `/user-profile?user_id=...` | 管理员手动查询一个平台 User ID；独立于会话候选，仅返回资料及解析状态，不代表业务权限验证 |
| `/{id}` | 身份、来源、可确认状态、真实轮次 / 使用量等；`include_context=true` 时附带当前配置估算 |
| `/{id}/history` | 复用 `ConversationHistoryResponse`，由服务端投影正文 |
| `/{id}/events` | 复用 `SessionEventsResponse`，含 `items`、`next_after_sequence` |

概览 / 列表公共参数为 `start`、`end`、IANA `timezone`、`agent_id`、`user_id`。会话统一查询全部来源，接口参数不再声明来源筛选，旧 URL 的 `source` 不参与查询；响应中的来源快照仍用于渠道图标展示。
列表另支持 `query`、`has_questions`、`has_execution_error`、`latest_status`、`limit`（1–200）、`offset`。
状态枚举为 `running` / `waiting` / `completed` / `stopped` / `error` / `unknown` / `not_started`。
Events 支持 `after_sequence`、`limit`（1–500，默认 100）及 `event_type`、`turn_id`、`run_id`、`call_id`。

401 / 403 表示认证或权限失败；404 表示会话不存在；History 的 409 表示正文投影冲突；
422 表示范围 / 筛选 / 分页无效；503 表示查询繁忙或超时。查询不执行模型、工具、MCP 检测或压缩。
聚合使用 SQL，不逐会话加载完整历史；最多两个并发重查询，等待上限 0.1 秒、执行预算 8 秒，超限明确失败而非返回假完整计数。
最近提问先在时间及会话筛选范围内按会话聚合最小事件序号，再按所选输入时间排序取 10 条，最后读取正文；不先取 10 条再去重，也不读取全部提问后在前端去重。提问总数、趋势、Agent 分布和活跃用户仍统计范围内全部真实输入。

## 平台账号资料与降级

概览、列表、详情通过响应 `users` 映射补齐**本次涉及**的账号，不增加通讯录接口。
后端沿用财务模型、电子表格组件“不区分空间查询用户”的方式，调用
`POST /user/get-user-detail-list`，由 System 服务转查 Account 账号中心。
使用 `PLATFORM_OPTION.server.system`（环境变量 `EXPORT_SYSTEM_SERVER_NAME`），请求体为 User ID 数组，
仅转发当前管理员认证，不需要 App、Space 或额外企业参数。
服务地址遵循[平台接入基础](platform-integration.md)：`system-server` 和
`http://system-server` 都按逻辑服务名进入现有服务发现；显式端口、真实域名和网关路径仍直连。
不把所有带 `http://` 的配置都当成 DNS 地址，也不在普通 HTTP 失败后回退注册中心。

2026-09-17 已定位 Test 部署 `http://system-server` 的 `gaierror`：此适配器曾绕过
平台 `BaseAPI` 的服务名归一化。此前从 Space 切换 System 没有解决该遗漏；现与平台客户端
共用规则，无需运维修改 `EXPORT_SYSTEM_SERVER_NAME=http://system-server`。
公网 System 成功不代表容器内服务发现成功，发布后仍应检查最终实例地址和实际回显。
旧前端引用的 `POST /api/user/info/by-user-ids` 在 Test 核验返回业务失败，诊断不依赖该旧路由。
每批最多 100 个不同 ID，整个补齐最多 2 秒、无自动重试。映射仅含 ID、显示名、邮箱、安全头像地址和解析状态。

显示名优先 `userName / username`，缺失时回退昵称、真实 ID；兼容数字形式的旧账号 ID。
会话列表与用户筛选候选只展示 Username 和邮箱两行，不展示头像、昵称或操作按钮。
详情侧栏沿用左标签、右内容的普通事实布局；当前账号使用浅底色的圆角用户图标，渠道账号不显示头像。
详情、当前账号和渠道账号的复制按钮仅在悬停或键盘聚焦时出现，点击复制完整原始 User ID 并短暂显示对勾。
不再展开 ID 或改变容器高度。活跃用户和最近提问只显示 Username。
缺少资料显示“未查到”、接口暂不可用显示“查询失败”，完整说明保留悬停提示；第二行回退原始 ID（单行截断、完整值保留在 title），
不推断账号删除或离职。所有名称、邮箱和 ID 均转义。

账号资料由既有 Resolver 批量补齐，独立返回 `username/nickname/email/avatar_url/resolution`，
保留 `display_name` 的旧消费契约。诊断 `/users` 仍只查询范围内会话涉及的候选，不是企业通讯录。
资料缺失 / 服务不可用仅降级为 ID，已返回会话数据可正常使用；真正 401 / 403 按门禁处理，不伪装成资料缺失。
本地可信身份模式没有平台凭证时，只给当前本地账号已有资料，其他账号显示 ID；
配置了平台凭证时仍批量查询真实资料，不能被本地管理员放行开关短路为“本地用户”。

资料缓存只在进程内短期保存，按部署、调用者及认证上下文隔离，有数量上限；前端退出 / 鉴权失效清空诊断数据。
用户筛选查询当前时间与 Agent 范围内全部会话涉及的去重账号，不受表格当前页限制。输入原始 User ID、Username、Nickname 或 Email 搜索，英文忽略大小写；唯一完整字段值可以回车查询，重名需选择候选，更多候选分批继续读取。没有该范围会话的企业账号不属于候选；可直接输入完整 User ID 查询。
页面路由仅保存模块及会话、事件、Run 等定位 ID；时间、Agent、账号、关键词等筛选只保留在当前页面内存，不写 URL、history.state 或 LocalStorage。浏览器刷新后重新计算默认相对时间；本次访问中的分页、下钻与返回保留同一查询范围。旧地址的动态筛选会被清理。

已保存的 `assistant/message` 即使只有工具调用、没有思考或正文，也展示为助手响应。
同一模型响应的多个 Part 合并成一行，摘要显示调用工具数；`native.event_ids` 保留全部来源事件 ID。
不虚构助手正文，不把工具调用合并掉，页面与导出使用同一投影规则。
定位消息只显示“定位消息”小标签，不增加整块高亮。正文、工具、轨迹和信息栏，以及标题栏的纯展示样式均与对话测试共享。

平台会话页不含企微发送人资料和全企业通讯录姓名搜索、成功率 / 满意度、问题自动分类、历史卡死判定、实时订阅、
对话正文导出、跨环境日志聚合或新的文件授权。测试入口不代表本机服务或全量验收已完成，实际结果以当次交付记录为准。

### 用户名补齐诊断日志（v0.10.2）

在“日志”选择 API，搜索“平台用户名”。发布后重新打开会话列表或概览触发读取；成功缓存最多保留 60 秒，缓存命中不重复记录批量请求日志。

- `diagnostic_users_completed`：实际批量请求成功，包含请求人数、得到姓名的人数；`partial` 表示仍有 ID 没有得到姓名。
- `diagnostic_users_failed`：按 `phase` 区分 `discovery / request / response / decode / normalize`；查看 `profile_service`、`discovery_type`、`discovery_namespace`、`target_origin`、HTTP 状态及安全业务错误码。
- `diagnostic_users_fallback`：整体查询不可用，显示回退为 ID；`deadline_exceeded` 表示整个补齐流程超过 2 秒。

`auth_context` 仅记录 Cookie/Authorization 等认证头是否存在及其类型，不记录值。`target_origin` 只包含协议、主机和端口，不包含路径、查询参数或认证信息；不写入用户 ID、姓名、Cookie、Token、请求/响应正文或异常原文。缺少目标且停在 `discovery` 时优先查服务注册、服务名与 namespace；HTTP 404 优先核对部署路由，401/403 为认证拒绝。日志不会改变已有请求目标、超时预算、缓存或降级行为。

历史验证记录：在 `v0.10.0`、Test MySQL `005`、相同鉴权下，本机公网网关 Local Discovery 链路曾成功返回列表和概览。这仅证明当时本机链路可用；当前已改用 System 入口，发布后仍需核验容器内 System 服务地址，不能沿用该历史记录作为验收。

## 渠道统计

会话概览和列表的视图切换旁增加`rss` 图标及「渠道详情」文字，进入 `#/diagnostics/sessions/channels`。入口仅传递最近 24 小时／7 天／30 天的周期；外层自定义时间回退最近 7 天，不携带 Agent、平台用户、来源、搜索或分页条件。

渠道页逐个选择账户，上方展示账户及企微应用信息、范围内活跃用户／会话／提问数和带分割线的活跃用户名单排名（不显示条形图）。下方按用户或群聊分页搜索，用户页仅汇总私聊，群聊页仅汇总群聊；选择一行后展示对应类型在当前范围的会话，第一条标记「最新」。点击会话复用诊断详情的只读对话与轨迹，返回恢复账户、筛选和选择。

统计以渠道消息账本关联的真实 `user/message` 事件为准：没有 Agent Run 的命令和没有持久化用户事件的消息不计入。活跃用户合并私聊和群聊发送人；已开启用户名查询时按关联企微应用的成员缓存映射到 userid 并去重，否则保留原始发送人 ID。查询过程不调用模型生成摘要，也不刷新企业微信成员资料。群聊未获得名称时展示「群聊 · chat_id」。

用户列表及详情仅纳入 `single/userid` 私聊绑定；群聊列表及详情仅纳入 `group/chatid` 群聊绑定，不再把用户参与的群聊混入私聊。顶部活跃用户及排名继续合并私聊和群聊的发送人，点击排名联动下方用户筛选，保留当前用户／群聊模式及已选群条件。未筛选群聊发言人时，会话详情中的提问数、最后提问和排序按当前范围的会话统计；筛选发言人时改为匹配提问列表。历史会话包含当前时间范围内最近一条，不代表所有时间的历史。原始问题摘要沿用现有 Event Store 投影，最多 320 字。

接口均为管理员只读查询：

- `GET /api/v1/diagnostics/channels/accounts`：安全字段投影，平台会话用户批量解析为 username；不返回 Bot Secret 或应用凭据。
- `GET /api/v1/diagnostics/channels/{account_id}/overview`：范围汇总和活跃用户。
- `GET /api/v1/diagnostics/channels/{account_id}/peers`：`kind=user|group`、`query`、`limit`、`offset` 分页。
- `GET /api/v1/diagnostics/channels/{account_id}/sessions`：按 `kind`、`peer_id` 读取关联会话，支持分页。

各查询沿用诊断的时间范围与查询预算约束。先按账户和时间范围过滤，数据库内聚合与分页，只批量读取当前页每个会话的最新问题事件；不会加载所有会话 History，也不会逐用户调用平台或企业微信接口。切账户、筛选、对象或离页时中止旧请求并忽略迟到结果。

渠道用户／群聊筛选合并为可搜索下拉：`peers?options_only=true` 每页 25 项，最多 3 条 SQL，省略最近会话及事件正文读取；同一身份的原始发送人 ID 与已缓存 userid 合并，搜索可匹配别名和用户名。选择使用 `peer_id` 精确过滤，避免 ID 包含关系误选；不为下拉刷新外部成员资料。

群聊发言人筛选：用户搜索在私聊和群聊之间保持所选身份及搜索词，群聊模式额外增加群筛选。`peers` 的 `sender_id` 在群聊时提前过滤归一发送人，列表统计和最新问题都遵循同一范围；`sessions` 带群聊 `sender_id` 时返回 `mode=questions` 和当前页匹配提问，可点击打开原会话。匹配消息按活动时间与消息 ID 稳定分页，只读取当前页关联用户事件。`include_group_senders=true` 仅扩展轻量用户选项范围，不改变私聊列表口径。

Agent 候选的 `has_channel` 依据渠道账户绑定关系返回，列表与概览复用，前端在 Agent 名称右侧标记渠道。用户候选 `/users` 按时间与 Agent 范围查询，使用 `query` 匹配 ID / Username，`after` 为用户 ID 游标，每批最多解析 100 个去重用户。

### 渠道配置的会话用户

渠道配置保持原始 User ID 输入，点击输入框内的查询按钮才查询；浮层显示查到的 Username 与邮箱，或资料缺失/查询失败说明，不改变弹框高度。修改输入或关闭编辑器时清理查询状态，不自动查询资料，不使用诊断候选作为通讯录。
资料展示仅用于当前账号、已有会话及渠道详情，保存身份仍使用原始 ID。

会话详情在首次进入、刷新和缓存恢复期间显示加载过渡；正文和详情操作等到首次渲染完成后开放，返回始终可用。补齐上下文信息复用已渲染历史，避免重复解析整段长对话。

### 轨迹耗时口径

模型节点的「模型请求」是服务端发起请求到 SDK 完整消费响应的耗时，包含首字节前等待和流式生成；工具节点的「工具执行」是服务端执行该工具的耗时，不含模型生成参数或人工确认等待。两者使用单调时钟计时，起止时间以 UTC 保存于现有消息／工具结果的 `metadata.deepagent_timing`（version=1），不新增事件类型或表结构。`duration_ms` 不受系统时间校准影响。

事件的 `created_at/updated_at` 仅表示入库／更新，不能用作执行耗时，特别是最后一次 Run 收口还可能更新早期消息。旧记录只有供应商响应时间戳时，使用该时间戳至首次入库的估算，可能缺少请求等待并包含入库延迟；旧普通工具使用调用至返回的估算，包含调度。列表及详情统一只显示时长数值，具体口径在悬停提示中说明。缺失或无效计时、待人工确认等情况显示「耗时未知」，不填零、不用当前时间补算。历史数据不回写。并行工具的执行区间会重叠，工具耗时之和不等于整轮耗时。

轨迹工具栏在搜索与导出之间提供「时间／耗时」切换，仅替换列表时间列，保留事件顺序、搜索、选择与详情。默认显示时间；耗时模式分为≤5秒（绿）、5–10秒（青）、10–20秒（琥珀）、>20秒（橙），这是耗时分档而非成功／失败状态。时长不附加名称或「约」前缀，瞬时事件、人工等待和未知计时显示灰色「—」。悬停可查看计时口径和分档；会话视图快照会保存当前显示模式。

## 查询传输兼容（v0.13.8）

Console 的会话、用户候选/资料、渠道统计查询使用原路径的 POST JSON，字段名及校验范围沿用 GET；详情的 include_context 与事件分页条件也放在 Body。无筛选的 History、渠道账户清单仍为 GET。旧 GET 继续兼容，所有路径保留管理员鉴权、查询预算和 no-store。只读预览仅允许精确列出的诊断查询 POST，不放开业务写入。
