# 电子表格助手应用配置：平台接口核验

本文保留原型阶段的接口选型依据和 Test 只读探测数据。正式功能已落地，实际管理与运行契约见[集成配置](../../guides/integrations.md)。

## 原型阶段的接口选型

1. **列出已配置应用**：先从平台取得当前账号可管理的企业，再按企业筛选 DeepAgent 的配置记录。只对有配置记录的空间调用 Space 的 `GET /api/space/app/query-app-info-list/by-space-id`（`space` Header），一次取该空间未回收、未删除的 App 编码和名称；按 `appType=DEEPFOS` 和已配置编码取交集，不逐 App 发请求。空间名称用 System 的 `GET /space/get-space-list?tenantCode=…` 按已授权企业批量补齐，亦可延后补名。名称缓存与授权校验分开。
2. **手输 App 编码**：按 DeepAgent 既有“Space 编码＋三位数字”规则取得待查 Space；由 System 的 `GET /space/get-tenant-code`（`space` Header）核对该空间实际所属企业。先确认该企业在当前账号管理范围，再在该空间的有效 App 列表中精确匹配编码。空间 App 很多时，也可用 `GET /check-exists/space-app?space=…&app=…` 校验未回收，再用 `POST /app-list` 传非空 `appIds` 精确取名称。后者只过滤已删除记录，不能单独用来判定可用。保存、移除、专用 Skill 下载和调试选择走同一个权限门槛。越权或不存在统一提示，不回显其他企业的应用名称。
3. **后续做完整选择器时再拉目录**：System 的 `POST /space-app-list` 返回企业、空间及应用，可传 `tenantCode`。它还包含普通用户可见的 App，且按空间加载并生成跳转链接；关键词并非精确编码查询。仅对已授权企业按需调用，不放到首屏或每次打开调试浮层的链路。Space 的 `POST /app-info` 虽能精确查一个 App，但返回连接配置等字段，本功能不使用。

企业管理范围可复用 System 的 `GET /user/get-user-detail?userId=…`。用户 ID 必须来自已认证的当前账号；按每条企业记录的 `roleList` 校验 `DEFAULT_ADMIN`，不直接信任整份结果已完成过滤。固定平台管理员按平台明确授权范围处理；只通过 DeepAgent 管理员检查或在任意企业为管理员，不等于可以管理所有企业。当前测试账号只覆盖一个企业，正式落地时还需用有管理与无管理权限的跨企业账号验证。普通电子表格用户运行助手时沿用原应用访问权限，无需成为管理员。

电子表格助手运行时只在「当前是集成绑定的 Agent，且有效 App 有配置」时追加应用提示词和专用 Skill。外层 Skill 页继续只列通用包。专用 Skill 归属单个 App，不提供跨应用关联或共享入口；在应用详情上传、下载、预览或删除，移除应用配置同时移除其专用 Skill。原型的两处入口通过同一个弹窗直接加载 Console 的 Skill 详情、资源预览和下载逻辑，模拟接口只提供示例数据。正式实现保持同一套详情 UI，并按 App 限制专用包的查询与下载。普通 Agent 安装包默认不携带环境专属 App 配置。

## Test 实测

同一 Test 身份，每项 5 次，复用 HTTP 连接；耗时含网关及网络，不是服务端单独耗时。

| 接口 | 样本 | 中位数 | 范围 | 响应大小 |
|---|---|---:|---:|---:|
| System `GET /user/get-user-detail` | 1 个企业 | 33 ms | 27–44 ms | 560 B |
| System `GET /space/get-tenant-code` | 1 个空间 | 25 ms | 21–28 ms | 53 B |
| System `GET /space/get-space-list` | 1 个企业，138 个空间 | 107 ms | 97–154 ms | 11,483 B |
| Space `GET /api/space/app/query-app-info-list/by-space-id` | 同一空间 7 个有效 App | 24 ms | 20–39 ms | 577 B |
| System `GET /check-exists/space-app` | 1 个 App | 27 ms | 26–66 ms | 72 B |
| Space `POST /app-list` | 同一空间 2 个 App | 23 ms | 22–24 ms | 165 B |
| Space `POST /app-list` | 同一空间 1 个 App | 24 ms | 23–26 ms | 105 B |
| System `POST /space-app-list` | 1 个企业、138 个空间、321 个 App | 314 ms | 295–325 ms | 117,387 B |
| System `POST /space-app-list?tenantCode=…` | 上述同一个企业 | 302 ms | 289–321 ms | 117,387 B |

Test 网关实际可用的目录路径是 `/deepfos-server/system-server/space-app-list`。旧 `/role-info/space-app-list` 写法返回业务错误；Account 的两个 `/s/user/…` 接口在本次网关探测中返回 401，不作为一期的网关依赖。已测的一期轻量路径不需要找开发补接口；如果要在大量空间下做实时全量搜索，再确认是否已有按企业分页、只返回编码和名称的轻量接口。

源码定位：`deepfos-platform/system-server` 中的 `SpUserController#getUserDetail`、`SpaceManageController#getTenantCode`、`SpaceAppController#getSpaceAndAppList`；`space-server` 中的 `SpAppInfoController#queryAppInfoBySpaceId`、`SpaceAppController#getAppList` 和各方言 `AppInfoMapper.xml`、`SpaceAppMapper.xml`。
