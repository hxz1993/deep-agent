# DeepAgent 发布 Agent 实施验收

代码在 Test 工作区，基线为 `96757b44`（0.17.3）。本地协议、回放界面、模型对照和四条客户端链路均已跑过。CodeBuddy A2A 的附件补答通过本机验收适配器在同一客户端轮次完成，原生直连的跨轮补答存在客户端限制。

## 已验证的行为

1. A2A 和 MCP 共用一个发布输出定义。普通正文、业务 JSON、正文加业务 JSON 都可完成任务。严格结构化的 Agent 也能先提交待补充状态，带实际问题、可选说明文字和本轮登记的文件。统一输出走现有校验与有限重试。
2. MCP 发起和续接统一用 `SendMessage`，续接在新消息中带原 Task ID，使用新的 Message ID，无需追问 ID。同一个 Task 可从 A2A 发起、经 MCP 补答。完成后带原 Context ID 发新请求会创建新 Task。任务列表按调用身份和应用范围隔离，包含稳定标题、简介、可选历史、产物和分页。时间阈值包含恰好相等的任务。
3. 生成五份文件只登记一份时，只能取回该文件，已测试实际内容。另用待补充与完成各登记一次同一上传文件的用例，验证原始附件可交付、任务产物去重、A2A 和 MCP 带原鉴权均可读取。集成用例还覆盖未授权、失效、内联、下载和中断。
4. 任务详情采用轮次时间线，起点为 Task ID，关联 Turn 可定位到原会话事件，Context ID 与内部 Session ID 放在下方。浏览器实测空态的任务详情标题与表头均为 36 px。发布会话回放和轨迹以 A2A Output 或 MCP Output 展示状态和折叠 JSON，文件卡在下方。轨迹的「输出」使用任务状态，发布结果的内部提交类型不出现在工具列表中。普通正文、业务 JSON、消息渠道和 Deferred/UI 交互通过定向回归。

## GPT 与 DeepSeek 同题对照

每个模型 10 组，每组固定同一业务输入、模型和业务约束，比较原输出与统一发布输出。样本包括预算、应付、故障复盘、现金流、发布门槛、库存、指标比例和三种缺信息场景。供应商请求实际发出。对照只测模型和校验链，文件上传与下载另由 API 和 FileStore 集成测试验证。

| 模型 | 原输出首轮通过 | 新输出首轮通过 | 新输出最终状态正确 | 原输出 → 新输出模型请求数 |
| --- | ---: | ---: | ---: | ---: |
| GPT-6.1 Terra | 10/10 | 10/10 | 10/10 | 10 → 10 |
| DeepSeek Flash | 10/10 | 8/10 | 10/10 | 10 → 13 |

- 两种模型都保留了应付场景的四个核对值 21800、54500、10900、21800。组合输出的完成率场景同时交付正文和 JSON，结论均为 60%、70%、增加 10 个百分点。
- 首版在 DeepSeek 故障复盘中发现正文写在输出定义外，`reply.text` 只留摘要。加入全文必须放进 `reply.text` 的指令和校验后，最终复测在该字段交出了完整复盘，包含 E1–E5、待确认项和下一步实验。
- DeepSeek 的库存题需要两次请求，冲突口径题需要三次请求。口径题最终只索要正式批准的口径，仍附了一段原题未要求的临时处理说明。样本可以验证这 20 组的关键事实和完成情况，无法据此推断所有任务的措辞、篇幅与重试率。

本地样本与截图见仓库 `output/Report [DeepAgent 发布 Agent 实施验收]/`。配对 JSON 包含题目、前后回复及请求次数，文件名为 `gpt-6.1-terra-final-pairs.json` 和 `deepseek-flash-final-pairs.json`。三张以 `fixture-` 开头的截图来自真实 Console 加隔离集成数据。

四条附件场景的轨迹均记录了 `draft1.txt` 至 `draft4.txt` 和 `report.csv` 五份生成文件。调用端只取回 `report.csv`，含 2026-11 的目标 100、实际 120、差额 20，48 字节。四份下载的 SHA-256 均为 `ba30962ff618147ceca93692fd5e82a5f53fdb55839d8b7ac6cdb94b566f4a8f`。真实截图、关键回包和下载文件在同名 `output/` 目录。8002 的上游连接用原有隔离验收配置和凭据临时指向 8000，完成后复原连接地址。

CodeBuddy A2A 原生 `A2ASendMessage` 只传 Context ID，输入附件用 URL。直接转发时观察到 CodeBuddy 自动发出 `CancelTask`，待补充任务随后无法继续。验收适配器仅绑定本机回环及本次样例发布，提供 Card 目录及平台鉴权，转发时把已知 CSV 的 URL 转为 `raw`，对指定补答补齐原 Task ID，并使用同步 `SendMessage` 让追问和补答在同一客户端轮完成。随后真实调用 `GetTask` 并由 CodeBuddy 下载文件。生产 A2A 的入参与任务状态仍按原协议处理。

CodeBuddy 的原生工具展示收到的正文和文件。业务 JSON 可在原始 A2A 回包的 `parts[].data` 中核对，当前工具输出里没有独立展示该字段。复测了在本机适配器转发的正文部分追加 JSON 的办法，原生工具展示仍未读到这段 JSON。CodeBuddy 的直连跨轮补答、原生业务 JSON 展示保留为客户端互通事项。
