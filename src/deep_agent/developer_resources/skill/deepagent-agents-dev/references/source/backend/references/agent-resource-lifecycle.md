# Agent与Skill资源清理

用于用户已授权清理某项目的测试Agent、旧Skill或联调资源。仅更新本机Codex技能、修改代码或发布客户端，都不包含删除线上配置的授权。读取目标/info、OpenAPI及当前资源；本页的接口快照不能替代目标环境事实。

## 确定范围

- 列出完整Agent与Skill集合，区分正式、测试、上传包和source=builtin。名称只作线索，正式身份以客户端/渠道实际引用、Agent完整配置和项目交接交叉确认。
- “只留正式一套”限用户指定项目，不扩展成删除其它业务或平台内置Skill。不要为凑数量删除公共能力。
- 记录保留的Agent、output-config、模型/MCP/UI/Skill引用和正式Skill完整原包，作为删除后的不变基准。正式Skill code可能已在切换中更新，从线上引用回读，不凭旧目录名推断。

## 备份与会话影响

删除Agent会连带清理关联会话及事件，不只是删配置。用管理员诊断接口取得完整关联集合、所有者和运行状态，逐页核对总数；不只看普通用户列表或默认时间范围。若需保留测试证据，先私有备份Agent/output-config、相关Skill原包及会话History/完整Events，并限制文件权限600、目录700。

用户指定保留的正式会话、未结束运行、渠道绑定或未核实执行不混入清理。备份不等于自动授予删除权限；不确定归属或范围时保留该项，继续其它已明确授权的清理。

## 执行与回读

1. 按当前OpenAPI调用DELETE /api/v1/agents/{id}。当前实现关联会话时返回409，detail.code=delete_confirmation_required，并含impact和confirmation_token；这表示尚未删除。
2. 将服务端impact与已授权、已备份的子记录集合核对。范围完全相符时才按接口要求带confirmation_token再次DELETE；它是绑定当前影响范围的协议令牌，不替代用户授权。遇到新会话、范围变化或渠道引用冲突，重新核对，不伪造令牌或直接改库绕过。
3. 测试Agent移除后，重新读取所有Agent引用，再DELETE /api/v1/skills/{code}删除已无引用的旧上传Skill。被引用时409应停止该项；内置Skill不删。Skill删除可能清理原包和各Pod运行副本，先保留所需原包。
4. 每次写入记录结果；超时或断连先GET核实是否已删除，不盲目重试整个批次。剩余资源完整回读，确认正式Agent、完整output-config、Skill原包及非目标绑定与基准一致，正式会话仍可读取。

结果说明实际删除数量、保留的正式配置与内置项、备份位置和未清理原因。原始配置、会话及令牌不进Git/NPM或本技能；不得把本次清理后的名称、ID、数量当作下一次操作的固定名单。
