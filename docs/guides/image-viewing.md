# 查看图片与 PDF 原页

`view_image`（查看图片）属于“文件”运行工具，不需要单独能力包。当前主模型必须支持图片输入。存在会话文件、可用 Skill 图片/PDF、Web授权或Python产物能力时可用；不要求启用文档解析、OCR或Python才能查看已有文件。

公开签名为`view_image(items: list[ViewImageItem]) -> ToolReturn`。每项包含必填`resource`和可选`pages: list[int] | None`；`items`和显式`pages`都不能为空。页码只接受正整数，布尔值或小数会被拒绝。同次调用的相同来源及页码按首次出现顺序去重，不合并内容相同的不同来源。无Web授权时，公开Schema和服务端均不接受URL来源。

```json
{"items":[
  {"resource":{"type":"attachment","file_id":"授权文件ID"},"pages":[1,6]},
  {"resource":{"type":"skill","skill_code":"example","path":"assets/chart.png"}},
  {"resource":{"type":"url","url":"https://example.com/photo.jpg"}}
]}
```

支持PNG、JPEG、WebP、GIF首帧及PDF。以实际内容识别，不仅按后缀或MIME；SVG、密码PDF、XFA动态表单、损坏文件等明确失败。PDF查看整页渲染，包括矢量图、扫描图与布局，不以提取内嵌图片替代。页码从1开始，为物理页码；省略只查看第1页。图片不传`pages`，不提供DPI、密码、Header或强制下载参数。

附件必须属于当前会话或可信工具生成文件；不能猜测他人的File ID。Skill资源必须已选择、已索引并通过路径、版本和Hash核对，脚本与ENV不能借此读取。URL来源必须有`builtin:web`授权，沿用公网下载器的逐跳SSRF与代理检查，不发送平台鉴权或Cookie。

## 文件生成与连续查看

PTC中没有此函数。Python、Skill或PTC先生成并上传文件，返回File ID，再由外层`view_image`查看。查看页图不上传平台，不生成下载产物或虚构File ID。

工具将有界来源信息和原生图片交给当前主模型；“已提供”不表示模型已经正确识别或业务核验通过。同一Run多次查看的图片累积进入后续请求。下一用户轮只加载轻量来源，需要原图时再次查看；不改变用户直接上传图片的历史处理规则。

面向客户端的工具结果投影、SSE、数据库和轨迹导出只保存来源、页码、尺寸、Hash和状态，不保存查看图片字节或Base64；持久化生成独立副本，不改变活跃SDK消息中的原生图片。旧`web_image_view`、`ImageUrl`和`web-image-reference`记录保留回读，新请求不再披露旧工具。

逐图结果中的`sha256`对应实际交给模型的规范化图片；PDF页图、旋转或缩放后的图片Hash不等于原文件Hash。原文件身份仍由来源File ID、Skill路径或URL表示。

Console按来源和页码展示成功及失败项。附件图片沿用会话授权预览，生成文件下载使用当前会话的普通或诊断授权入口；PDF显示原文件及所查看页码。Skill PDF可下载Skill原包后查看，不新增页面截图接口。历史只保留来源，网络图和Skill资源的预览读取当前文件，不能作为当时图片的快照。

## 固定保护限制

MB按1024×1024字节计算，无新增配置项：

| 项目 | 限制 |
| --- | --- |
| 单次输入 / 图片或PDF页 | 8项 / 合计8张，重复来源页码按首次顺序去重 |
| 原始图片 | 20MB、6400万像素 |
| 授权PDF / 公网下载 / 单次来源总量 | 200MB / 20MB / 200MB |
| 规范化图片 | 最长边3072、最多600万像素、单张4MB、单次16MB |
| 当前上下文及待加入图片 | 合计20张、32MB，另受原有模型上下文预算约束 |
| 整次调用 / 单来源渲染 | 60秒 / 20秒（含等待） |
| 渲染并发 | 每API Worker最多2个子进程，满载时有界等待 |

图片按EXIF旋转，保持比例、不裁剪。16位灰度PNG按固定灰阶范围转换，转换时保留透明样本。PDF以200DPI为起点，在分配位图前限制尺寸。优先PNG，过大转JPEG质量90，透明区域使用白底，再按比例缩小。缩放不能恢复模糊细节；关键内容仍不清晰应明确说明。

全局项数和总量超限明确拒绝，不静默丢项；个别来源/页面失败可返回其他成功项及部分成功状态，全部失败为工具失败。读取既有文件不因后来降低上传配置而拒绝，但仍受本工具保护限制。

## 服务端依赖交接

Agent服务端新增`pypdfium2==5.14.0`，Python/Skill执行镜像依赖不变。不要启动时自动安装，也不要求Poppler。部署前重建匹配基础镜像，确认目标架构wheel及其PDFium运行文件，并保留包内许可证及第三方声明。

PDFium不支持并发线程调用，渲染采用受控子进程，按来源串行处理选页；异常、超时、取消均终止并回收进程及临时目录。[PDFium线程与内存管理说明](https://pypdfium2.readthedocs.io/en/stable/python_api.html)、[固定版本发布资料](https://pypi.org/project/pypdfium2/5.14.0/)。

Linux子进程在导入渲染库前设置512MB地址空间上限。macOS不宣称具有等价硬内存隔离，只验证字节、像素、超时及进程清理；本机Docker守护进程不可用时，Linux硬内存验收应明确列为未执行。
