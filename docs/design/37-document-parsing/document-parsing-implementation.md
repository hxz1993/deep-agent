> 2026-10-09：产品仅保留 Paddle/GLM，MinerU配置读取为未配置且请求实现已删除。本文后面的三家验收数据是2026-10-01/02历史观察，不代表现行可用供应商。

2026-10-02。新增一个显式关联的内置工具分组“文档解析”`builtin:document`，只有 `read_document` 一个工具。当前基线为 v0.12.8；本轮升级 v0.12.9，不新增环境变量、数据库结构、长期缓存或独立 MCP。

## 使用入口与运行链路

管理员在“全局配置 → 常规 → 工具设置 → 文档解析”选择 PaddleOCR 或 GLM-OCR，填写自己的 Key。默认编辑选择 PaddleOCR，初始未配置不能解析；只保存当前一家，其他供应商草稿在关闭弹窗后丢弃。GET 只返回掩码和设置状态，编辑未改 Key 时保留后端原值。保存只校验结构，“测试连接”明确提示收费并真实解析、核对一页已知样例。

Agent 显式关联分组后才提供工具，既有 Agent 不自动启用。当前供应商能力表同时驱动配置说明、工具目录、上传格式和模型工具描述。PDF 与 Office 格式按实际接入服务分别开放；显式上传白名单、大小和数量限制继续执行。运行前冻结配置，新 Run 使用最新配置，已运行的请求不受切换影响。

链路为：授权附件或 Skill 文件 → 读取文件字节 → 当前供应商适配器 → 完整原生结果的私有 Run 缓存 → 共用 Token 分页 → 模型。Paddle 使用 AI Studio OCR jobs 的 VL-1.6；GLM 使用官方 `layout_parsing`。不调用普通聊天接口模拟 OCR，不增加供应商回退或快慢档。

## 参数与结果

完整说明及 JSON 示例见[使用指南](../../guides/document-parsing.md)。工具参数为：

```text
read_document(resource, page_start=None, page_end=None,
              limit=None, offset=1, char_offset=0)
```

`resource` 兼容现有附件与授权 Skill 引用，也接收当前 Run 返回的 `document_id`。页范围只控制本次展示，首次始终解析完整文件。没有隐式游标；重复原文件引用命中缓存，省略位置则从头读。

| 情况 | 返回方式 | 下一次调用 |
| --- | --- | --- |
| 完整结果放得下 | 返回全部页面、结构概览、`has_more=false` | 不需要续读 |
| 多页结果放不下 | 返回能装下的页面与完整 `next_read` | 原样调用 `read_document(**next_read)` |
| 单页特别大 | 同一页带 `char_offset/char_end` 分段，`complete=false` | 保持页位置并复制 `next_read` 的字符偏移，不能自己跳到下一页 |
| 供应商缺页或无可靠页码 | 标明 `partial` 或覆盖未知 | 缓存读完不代表源文件解析完整 |

模型窗口小于256000或未知时24000估算Token，达到256000时48000；正文和序列化包装共同计入。复用读取工具的 `ReadingBudget`、估算器和分页器，没有新行数、页数、字符限额；跳过通用大结果的二次外置，整体请求仍接受现有上下文检查与压缩。

保留原生 Markdown、HTML 表格和供应商页面顺序，不纠错金额、日期、重复内容或租赁业务。概览只描述页面覆盖，不新增模型摘要。每次命中缓存仍检查来源授权；并发同源文件合并一次解析。已确认上传的任务在本 Run 可恢复查询或下载；未知提交不会自动重提。结束、异常、取消或挂起结束清理缓存与 HTTP 资源，不能承诺远端任务停止计费。

## 接口与诊断

复用现有 `global_setting`，记录名 `document_parsing`，保持管理员权限：

- `GET /api/v1/global-settings/document-parsing`
- `PUT /api/v1/global-settings/document-parsing`
- `POST /api/v1/global-settings/document-parsing/test`

日志关联 Session、Run 和工具调用，记录平台、接口方法与路径、模型、安全参数、文件Hash与字节数、任务标识、阶段耗时、状态和错误码、页面覆盖、缓存命中及返回Token。不输出 Key、正文、Base64、完整响应或签名URL。

## 真实文档效果与未完成项

[三供应商回归报告](evaluation/lease-contract-parsers/product-runtime-20261002/production-regression-report.md)提供全部样本、原图事实、调用次数、测速及失败记录。

- Paddle与GLM完成六份PDF（每家192页）、两张图片；46组真实或历史产物的24K/48K分页重建逐字符无损。
- 同一个本地DeepSeek模型使用租赁Demo原提示词与Schema主动调用工具。66份当前阶段轨迹逐字符读全；保留另1份首轮模型跳页失败证据，加强正式续读说明后复测通过。
- 六合同选定事实Paddle87/87、GLM86/87；费用表66格GLM66/66、Paddle62/66。局部命中率不是全文或财务填报准确率。GLM漏识别月租30216.88；条件收费重复建模、前月付款日等仍需业务审核。
- 31页独立端到端观测为Paddle0.921秒、GLM20.381秒，6页为0.782秒、6.539秒。Paddle明显受云缓存影响，不能读作首次OCR性能。六PDF初轮云生成耗时没有可靠记录，不用恢复耗时补造排名。
- MinerU12个原任务提交上传成功，首轮均900秒超时；同任务第二轮8个超时、4个GET403，未取得本轮结果。没有盲目重新提交或自动切换供应商。历史31/6/55页原生ZIPHash匹配，另行离线重放通过，但不能替代本轮云端验收。
- MinerU Office任务尚未返回；旧DOC/PPT/XLS没有授权的答案明确样例，保持未验证标记。没有修改租赁Demo或生成真实付款计划。

因此产品接口和回归通过；Paddle/GLM具备本轮真实文件结果，金额填报仍需复核，MinerU当前云端可用性尚未验收通过。
