# 管理员用量统计

Console「会话 → 用量 → 日志」中的用量页仅供管理员访问。它读取仍保留在 `chat_session_events` 中的真实模型响应，不是费用账单，也不实施额度限制。删除会话会同时删除可统计的历史用量。网络搜索及图片生成的独立 API 消费不纳入本页。

## 口径

- 一次 Pydantic AI `ModelResponse` 计一次模型请求；同一响应拆成多条轨迹事件，只在一条事件的 `usage.calls[]` 中承载，查询再按会话和请求标识去重。
- `input_tokens`、`output_tokens` 使用单请求 `RequestUsage`；总量为两者相加。缓存读取／写入包含在各自的 SDK Usage 中，不额外叠加总量；`RunUsage` 累计量不能当成单次消费。
- `purpose` 分为 `chat`、`title`、`compaction`。标题失败、取消或被用户改名时，已取得的模型用量仍保存在原有 fallback 标题事件；压缩失败或取消不抹去已有摘要调用。
- 用户归属取会话的平台用户 ID；渠道会话不按企微发言人重归属。日期取承载事件的 `created_at`，按查询指定时区分组，时间筛选为左闭右开。
- 字段未报告记为 `null`，明确报告零记为 `0`；部分数据仅汇总已知值并提示缺口。旧历史未回填或不能验证的响应不伪造用量。

## 数据结构和迁移

Alembic `007` 仅在 `chat_session_events` 增加可空 `usage_model_id` 和 `usage`（兼容数据库的 TextJSON），以及 `created_at, usage_model_id` 索引。`usage` 为 `{"version":1,"calls":[...]}`；每个调用包含 `request_id`、`kind`、`purpose`、模型／Provider ID 与名称快照、输入／输出／缓存字段及完整性状态。模型 ID 不加外键，删除配置后仍可从历史快照展示。

历史回填独立执行，不在启动时扫描：

```bash
PYTHONPATH=src .venv/bin/python -m maintenance.usage_backfill --config ~/.config/deep-agent/sqlite.env
PYTHONPATH=src .venv/bin/python -m maintenance.usage_backfill --config ~/.config/deep-agent/sqlite.env --apply
```

第一条只预检，第二条只回填可验证的旧聊天响应；标题与压缩无法拆分的历史不猜算。迁移降级时若存在非空 `usage` 会拒绝，以免静默丢失数据。

## 接口

均要求 Console 管理员，路径前缀 `/api/v1/diagnostics/usage`。公共筛选参数为 `start`、`end`（UTC ISO 时间，最多 31 天）、`timezone`（IANA 时区）、可选 `agent_id`。

| 接口 | 作用 |
| --- | --- |
| `GET /` | 指标、按日趋势、分组序列、用途分布及不完整数 |
| `GET /details` | `group_by=model/user/agent`，支持 `sort`、`descending`、`limit`、`offset`；先全量聚合再分页 |
| `GET /sessions` | `group_by`、`key`、`offset`；查看分组贡献会话并跳转现有管理员详情 |
| `GET /export` | 同明细筛选与排序，`scope=all/page`；仅导出汇总 CSV，无正文、Payload 或凭据 |

## 页面交互

- 默认最近 7 天；与会话页共用最近 1／7／30 天及自定义时间控件。时间或 Agent 改变后自动查询，查询按钮用于刷新。
- 右上角 Agent／模型／用户同时控制趋势与明细，默认 Agent。日期只作为全局时间范围和趋势横轴；没有日期、用途明细页签或明细搜索。
- 左侧趋势支持 Token／请求和折线／堆叠柱状图。图例展示前四项与其他，点击强调当前项、淡化其余曲线和图例，再点一次恢复；不隐藏数据或改变坐标范围，也不重置下方列表滚动位置。
- 右侧集中展示累计、日均、单次平均 Token、峰值日期四个指标卡，以及聊天／压缩／标题、输入／输出／模型请求六项文字统计。
- 下半区为共用边框的可拖动工作台，初始左右约 60:40。拖动范围复用渠道详情限制；左右方向键和 Home／End 也可调整。左右各自滚动，桌面页不会被加载内容撑长；窄屏或低高度窗口保留页面滚动，但工作台仍限制高度。
- 左表每页 10 条，表头固定为明细、Token、请求、单次平均、用量占比；名称单行显示。模型用 Provider 图标，渠道绑定 Agent 用渠道图标，用户用用户图标。选中行展示贡献会话，默认选首行。
- 右侧标题与左侧图标一致。会话显示 Token、短 ID、时间和请求数，ID 分隔点悬停变为复制按钮。初始 10 条，通过小号“加载更多”文字按钮点击追加，滚动本身不触发请求；加载完毕隐藏按钮。滚动条位于面板外沿，与指标保留间距。
- 导出按当前时间、Agent、维度和排序生成汇总 CSV，可选全部或当前页；包含身份、Token、请求、单次平均、用量占比及缺失请求数，不含会话正文或 Payload。

所有汇总从同一事件事实计算，不另建 Usage 表或 Redis 计数器。记录完整时，单次平均按 Token／模型请求次数计算；部分请求用量缺失时，仅以输入、输出 Token 都有记录的请求计算平均值，显示 `*` 并说明覆盖次数。全部请求用量不完整时仍显示未知，不能把缺失当作零，也不能用包含部分用量的总计除以完整请求数。显式报告的零用量属于完整记录。

汇总、趋势、明细和贡献会话的只读统计新增 `complete_requests`、`complete_tokens`，分别表示输入、输出 Token 字段均有记录的请求数和这些请求的 Token 合计；“完整”仅指字段齐备，不表示响应成功结束或最终计费已经结算。不改写事件或新增持久化字段。CSV 的单次平均采用相同口径，已有缺失请求列用于识别覆盖范围。用量占比仍以当前筛选范围的已报告总 Token 为分母。模型流在供应商发送最终用量前中断时可能没有用量；保留未知，不用估算值冒充供应商计费数据。

## 查询传输兼容（v0.13.8）

Console 查询与导出使用同路径 POST，动态筛选及分页条件位于 JSON Body；旧 GET 保留兼容，权限、查询预算和 no-store 不变。浏览器地址只保留模块及资源定位信息，筛选保存在页面内存，刷新浏览器后重新计算默认相对时间；本次分页、下钻及返回保留原查询范围。
