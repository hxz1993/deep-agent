# Skill 执行环境变量：历史评审草案（未采用）

状态：2026-10-30历史评审存档，**未采用、未实施**。原型保留用于对照，不是后续实施计划。
用户后续决定由 Skill 包自带 `.env`，脚本自行解析；0.15.0只统一原路径执行、模块和文件发布。
不新增独立变量存储、环境变量管理接口、运行时注入或加密主密钥。当前规则以
[Skill指南](../../guides/skills.md)和本课题[入口](README.md)为准。以下保留当时讨论，不作为产品承诺。

## 1. 范围与入口

- 在现有 Skill 详情右上角增加中性按钮“环境变量”，放在“编辑”前，显示已配置条数。不新增一级页面或 Agent 级覆盖配置。
- 仅当前含可执行 Python 脚本的 Skill 展示入口；内置 Skill 有 Python 脚本时同样可配置，不改内置包只读规则。无脚本及只有JS/Shell脚本的Skill不增加无效入口。
- 每个部署环境、每个 Skill 共用一套变量。引用该 Skill 的 Agent 使用同一套服务身份；这不是每位聊天用户的个人 OAuth 授权。多身份需求另行设计，第一版不增加覆盖优先级。
- 管理员维护；关联／运行权限仍沿用当前规则，不因配置变量新增工具权限。

## 2. 弹窗交互

- 顶部显示 Skill 名称、多个 Agent 共用时的影响数量；主区域按变量名、变量值、敏感值、删除四列排列。可新增／编辑／删除，取消及Esc不保存。
- 普通值回显；敏感值只显示“已设置，留空不修改”，不通过GET返回旧值、不提供查看原值按钮。新增行默认敏感。
- 保存时，旧敏感行留空代表保留原值；新增敏感行必须填写。真正删除通过删除行后保存完成，不把空输入误判为清除密钥。
- 普通变量允许空字符串；环境变量名区分大小写，禁止空名、重复名、非法名。改名明确按删除旧名／创建新名处理；旧敏感值保留操作必须绑定原条目标识，不能借改名读取或复制任意密钥。
- 保护执行器变量，如PATH、HOME、TMPDIR、PYTHON*、LD_*、DYLD_*、代理及平台内部控制变量；不能通过Skill配置改变运行边界。
- 建议固定32个变量、变量名128字符、单值16KB、单Skill总值64KB，前后端同规则，实施前作为评审项确认。不新加用户可调配置。
- 普通值与敏感值切换：旧敏感值转普通值必须输入新值，不将已保存的密钥解密回显。
- 加载失败禁止误以为空配置覆盖；保存失败保留草稿；保存成功后回读失败单独提示已保存但未刷新，不能自动重复提交。

## 3. 存储与接口

- 优先复用现有global_settings，一行JSON对应一个Skill，使用保留命名空间 `skill_environment:<code>`。不新增表、列或迁移；不写入Skill manifest、资源索引、原ZIP或运行副本中的.env。
- JSON包含格式版本、条目标识、变量名、敏感标记和值。普通值明文存储；敏感值采用服务端认证加密。配置可沿用现有原子事务／独占屏障，并增加内容修订摘要，防止多个管理页面覆盖彼此的修改。
- 当前未确认可直接复用的通用密钥加密组件，不将界面掩码冒充加密。落地前核定现有依赖能否提供认证加密；部署主密钥由运维单独配置，不能与数据库一同保存或放入包中。若需新增依赖／部署项，单独说明，不静默升级镜像。缺少主密钥时敏感配置保存／执行明确失败。
- 拟增管理员GET／PUT `/api/v1/skills/{code}/environment`。GET返回revision、条目ID、名称、敏感标记、是否已设置；仅非敏感条目返回value。
- PUT一次原子替换配置，旧敏感条目使用显式keep操作保留，新值使用value，删除以列表省略或显式操作统一实现。请求携带revision，冲突返回409；不把密钥值用于错误回显。
- 执行读取走内部服务接口；模型工具Schema不增加env、token、secret参数。禁止客户端在聊天请求里任意传环境变量。

## 4. Python执行链路

调用 execute_skill_script
→ 核对当前Agent关联、Skill、脚本索引和.py路径
→ 从服务端读取该Skill当前变量一次
→ 校验并在内存解密敏感值
→ 与后端必要基础环境合并
→ 仅传给本次Python子进程／容器
→ 按现有结果协议返回，释放此次执行的配置引用

- 脚本仍用os.getenv读取；不要求每个Skill携带env_run.py，也不更换Python运行后端或开放Shell／Node。
- 每次脚本执行前读取一次；配置保存后其他Worker下一次执行生效。已开始的执行保持其启动时的值，不修改进程全局os.environ，不增加启动永久缓存。
- PTC调用execute_skill_script走同一入口。不同Skill及并发调用各自独立；变量不注入Monty，不混给另一个Skill，不自动注入通用execute_python。
- 环境映射作为执行后端私有参数传递，不放进公开ExecuteRequest／工具入参、会话事件或PTC Calls诊断。未来沙盒对接沿用内部映射，由后端适配供应商env接口。
- 原有资源授权、Python依赖、超时、内存、输入输出、网络及文件限制保持。配置密钥不代表CLI可用，也不增加新的认证协议。

## 5. 凭据、历史与导出

- 配置值不进入提示词、模型工具参数、SSE、History、轨迹、压缩上下文及诊断。接口异常和审计日志不包含新旧值。
- Skill单个导出、全部导出、Agent整包、Skill复制／跨环境安装均不携带环境变量值。配置备份／初始化导入也默认排除该命名空间，不能因为复用global_settings把凭据带出。
- 安装包可用现有参考文档声明需要的变量名，第一版不增加必填manifest字段或自动联网测试。
- 同编码替换／重新加载保留当前环境变量配置，并提示管理员审核新版脚本；更新提示不把变量写回包。删除Skill时在同一配置事务删除独立配置，避免以后同编码重装继承旧密钥；内置包不能删除，维持原规则。
- 配置仅通过服务端注入，不主动落入历史；脚本自身可以读取密钥，所以不能承诺恶意脚本任意编码后输出仍绝不泄漏。执行输出／日志／异常在持久化或发给模型前，对已知敏感原值进行脱敏并加回归；脚本规范禁止输出凭据。此限制必须如实说明。
- 用户自行把真实.env写进原始ZIP属于另一问题：不自动读取其凭据，也不承诺导出时净化任意包内容。本方案保证的是新增独立配置不写入包；资产白名单与现有安装规则先保持不变。

## 6. 实施与回归顺序

1. 确认原型及上述共同身份／加密主密钥的部署约定，冻结范围后再实施。
2. 做配置服务、权限、认证加密和原子保存；验证普通值、敏感值保留／更新／删除、改名、重复名、禁用变量、并发和失败回滚。
3. 扩展执行后端私有参数；真实Python子进程验证os.getenv、父进程环境不变、并发不同Skill隔离、PTC内部调用、取消与异常清理、下一次执行热生效。
4. 覆盖已保存敏感值的GET、错误信息、日志、HTTP／SSE／History、PTC诊断、输出脱敏和故意打印的情况；不得把完整env对象写入事实。
5. 回归Skill安装／替换／重载／删除、Agent关联与复制、原包哈希、单个／集合／Agent导出、配置备份恢复和旧包兼容，确认不带变量或误删除其他配置。
6. Console检验加载失败、取消、保存、冲突、回读失败、多Agent提示、长变量、空配置、键盘、明暗主题；产品代码定稿后跑相关后端、执行、导出备份组和Console全量。
7. 使用隔离Skill与临时凭据验证本地8000，不改原Agent、原Skill、会话或平台业务数据。三种数据库只测试受影响配置事务，不引入DDL。
