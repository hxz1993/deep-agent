# A2A 鉴权与数据访问

归属 [45 号课题](README.md)。以下为首期设计，凭据链路仍待环境联调。

## 服务端授权链

```text
接入凭据 → 可信调用主体 → 发布授权 → 执行身份与 App／Space
           → 任务操作权限 → 下游数据权限 → 产物访问权限
```

| 检查点 | 服务端决策 |
| --- | --- |
| 发布与配置 | 具备发布管理权限的管理员选择 Agent、设置应用范围并管理启停。 |
| Agent Card | Card 声明协议版本、认证要求和可公开的能力摘要。发现入口统一按平台规则鉴权。详细权限、内部 Agent ID、凭据、历史和客户数据均不出现在 Card。 |
| 提交 | 先从可信网关或验证通过的凭据解析调用主体、环境和租户，再校验发布权限、目标 App／Space、入参和文件。外部请求中的 `user_id`、身份 Header 和模型生成的参数均不可用作身份凭证。 |
| 执行 | 受控构建现有 Runner 的身份和会话范围。按平台核验后的调用身份检查 App／Space、MCP 及数据权限。配置者的权限只用于管理发布。 |
| 查询、订阅、取消与取件 | 每次入口重新核验主体、发布权限及任务和产物归属。外部 Context ID、Task ID 和 file ID 都只是标识符。跨入口访问仍需同等主体与权限；无权和不存在的任务在对外错误中保持不可区分。 |
| 凭据与审计 | 凭据随请求提供。Agent Card、示例、任务事件、SDK 错误和 CLI 参数日志均不回显原值。审计保留主体、委托关系、目标 App、能力、任务／Run、动作和结果。 |

当前 [request_identity](../../../src/deep_agent/api/v1/request_identity.py) 读取由可信网关传入的身份。外部协议入口需重新验证身份信任链，由受信边界重建运行时身份，防止调用方直接注入这些内部 Header。

## 运行身份

每次提交都在一个 App 下执行。服务端使用固定应用或请求中的 `app`，校验其与 `space` 的关系，以平台 Token 或 API Key 解析可信身份，再检查发布范围和主体对目标应用的权限。业务程序可以用平台签发给服务账号的受限凭据。A2A Card 由服务端按统一接入规则生成。

`agent_publications.scope` 是 JSON 对象，首期只支持 `apps`。

| 模式 | 示例 |
| --- | --- |
| 固定应用 | `{"apps":{"mode":"fixed","items":[{"app_id":"finops001","space_id":"finops"}]}}` |
| 调用方指定 · 全部应用（默认） | `{"apps":{"mode":"all","items":[]}}` |
| 调用方指定 · 指定应用 | `{"apps":{"mode":"selected","items":[{"app_id":"finops001","space_id":"finops"}]}}` |

固定应用必须有且只有一项，服务端始终使用发布配置里的 App 和 Space。调用方指定时，客户端须传 App ID。全部应用允许凭据有权访问的应用，指定应用还要求 App 位于非空清单内。保存显式清单时核对 App 与 Space 的平台关系，调用时验证凭据对目标应用的权限。将来可以给 `scope` 增加其他范围维度。

提交后延迟执行的任务还需考虑凭据过期。Worker 使用可重新获取的授权上下文或凭据引用。缺少有效续期方式时将任务标为需重新授权或失败，状态由首期协议范围决定。凭据原文不写入任务库。

MCP 绑定 App 方案归入[42 号企业集成课题](../42-enterprise-auth-adapters/README.md)，它在确认运行身份后限定某个下游 MCP 的访问目标。A2A 任务入口自身的 App／Space 和会话上下文独立记录。

## 接入、文件与撤销

- **四个入口同权。** A2A API、Python SDK 与 CLI 按同一调用主体访问任务。MCP 通过可信身份映射调用同一服务，不能以网关共享账号绕过实际调用者授权。接入页支持复制地址和无密钥示例，凭据由运行环境或企业凭据管理提供。
- **输入附件。** 首期优先复用授权上传引用。校验 owner、租户、允许类型、大小及目标任务范围。若以后接收远端 URL，由受限下载服务按允许来源处理，不向第三方 URL 转发 DeepFOS 认证信息。
- **产物交付。** 任务公开发布文件元数据和受控引用。下载校验主体、任务、对象和有效期，再取 FileStore 字节。下载可在命令行环境完成。签名短链如纳入首期，需要单独确认有效期及撤销传播；默认建议使用可重新检查权限的下载方式。
- **变更与停用。** 停用关闭对外发现和新任务。已受理任务沿受理时的 Agent、执行身份和 App／Space 运行，查询、继续和取件重新校验当前权限。若更换 Agent，新任务使用新的 Context。同一发布下不同 App 的任务使用不同 Context。历史保留与下载窗口按部署策略确认。出站连接密钥轮换后，已创建的远端任务仍需以有权的调用主体回读。

## 出站连接授权

管理员录入远端 Agent Card URL、鉴权方式、凭据引用、允许调用的本地 Agent／角色、超时、配额和文件分享策略。测试连接用于核对目标、版本、认证和能力。由服务端确认可访问目的地址、跳转和最终接收凭据的接口，并按连接限定凭据范围。

运行时由已授权的本地 Agent 选择连接，服务器使用对应凭据。任务归属包含租户、调用主体、连接和远端 Task ID，避免不同服务的 ID 混淆。发送本地文件前检查用户许可和连接分享策略，收到远端文件后核对来源与格式。普通日志和模型输入仅看可公开的结果与引用。

## 安全验收与待确认

1. 同租户不同用户、不同租户、不同 App 三组对照，覆盖任务查询、订阅、取消、下载及猜测 ID。覆盖调用方传身份字段与过期凭据。
2. 同一主体通过不同入口调用，权限决策、执行身份和审计记录一致。测试下载不依赖浏览器 Cookie，并覆盖角色调整和发布撤销。
3. 待联调现网 Token 和 Key、同一主体跨入口访问、进行中任务撤销、产物保留与下载有效期。
