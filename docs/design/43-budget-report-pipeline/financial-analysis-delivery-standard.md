## 核心结论与适用范围

把财务 BP 已有的口径、脚本、报告样例和核验经验，整理成可安装、可复算、可验收、可维护的业务能力包。
标准化的主体是实施流程、输入输出、验收和责任；Skill 是承载业务规则与执行资产的一种形式。

适用于已有一定业务数据和分析方法，需要迁移到 Agent、接入真实查询并生成交付文件的项目。
数据模型尚未建立、预算未维护或必要接口不存在时，先识别并补齐对应工作；安装 Skill 不会产生缺失的业务数据或运行权限。

与[课题主线](README.md)的关系：本页回答“一个项目怎样实施和交付”；报告工作台回答“用户怎样保存要求、持续修改、复跑和采用结果”。实施规范可以先落地，不以新建通用 Mission／报告任务平台为前提。

## 三层职责与复用范围

| **层次** | **内容** | **责任与复用** |
| --- | --- | --- |
| 平台底座 | 模型、Agent、MCP 授权、程序编排、脚本执行、文件交付及轨迹 | 平台提供通用能力，管理员配置可用性和权限 |
| 通用实施资产 | 输入协议、计算框架、校验分级、报告模板、文件回读及验收方法 | 实施方维护，可跨项目复用并按差异适配 |
| 客户业务资产 | 指标定义、实际／预算查询坐标、组织范围、单位、剔除规则、报告要求及核准版本 | 财务与数据负责人确认，按客户维护和验收 |

原项目拆为财务模型取数、辅助接口取数、经营分析报告三个 Skill；这是业务职责划分的案例，不要求所有项目固定拆为三个包。
辅助接口承担应收等特定查询的安排属于原项目的数据设计，新项目应逐项决定指标的权威来源。

## 实施流程与阶段产物

```text
业务范围与报告样例
→ 指标口径确认
→ 真实数据与查询映射
→ 程序计算和校验
→ Agent 组织分析说明
→ 模板渲染、发布与文件回读
→ 财务验收、版本固化与维护交接
```

| **阶段** | **必须完成的工作** | **阶段产物** | **主要确认方** |
| --- | --- | --- | --- |
| 场景定界 | 确认对象、期间、指标、比较需求、明细深度、交付位置和数据是否存在 | 范围与数据缺口清单 | 客户业务负责人 |
| 口径梳理 | 确认公式、单位、实际／预算版本、聚合、剔除、默认值和例外 | 指标字典与已批准规则 | 客户财务负责人 |
| 数据适配 | 核实模型／维度／返回字段；按指标建立查询配方，确认辅助接口与分页 | 查询映射、输入输出契约和核验样本 | 实施方、客户数据负责人 |
| 计算与报告 | 固化算法、缺项表达、校验分级、报告内容及模板；显式接收本次查询结果 | Skill、脚本、模板、报告样例 | 实施方，业务方评审 |
| 联调验证 | 检查授权、分页、异步结果、大小限制、发布回执和实际文件 | 技术联调记录与问题清单 | 实施方、平台管理员 |
| 业务验收 | 同批数据独立复算、回源勾稽，并审阅分析解释与适用边界 | 财务验收记录、覆盖范围与未决项 | 客户财务负责人 |
| 固化交接 | 固定规则版本、安装包、样例、责任和变更流程 | 可复用交付包及维护说明 | 双方项目负责人 |

条件完整且唯一时使用经过验证的默认规则；本次明确要求可按已支持范围覆盖。条件有歧义、冲突或规则超出已验范围时先澄清。
指标定义、币种或单位变化后重新核对公式与换算；一次聊天中的临时口径不直接成为全局默认值。

## 执行链路和建议统一的契约

原项目的关键改造，是将个人电脑上的会话文件、绝对路径和本地依赖，改成显式的本次数据输入：

```text
用户问题 → 已确认口径与查询计划 → 已授权工具查询
→ PTC／程序变量保留查询结果 → 包内脚本计算、校验、渲染
→ 正式发布报告文件 → 回读文件并核对交付回执
```

完整明细由程序交给后续工具，减少模型重新抄写长 JSON 的格式错误、漏行和截断。
PTC 仅改善编排与数据交接；原查询的分页、截断、权限及工具输入输出限制仍然有效。

后续可把下列五类契约做成可填写模板。这里是应明确的内容，不是本轮新增 API 或固定 JSON Schema：

| **契约** | **至少包含** | **关键边界** |
| --- | --- | --- |
| 分析请求 | 对象、期间、指标、比较口径、默认／本次覆盖、报告要求和规则版本 | 缺关键条件时不能自行猜测 |
| 数据输入 | 原始返回、来源入口与参数、字段映射、单位、范围、数据时点、完整性及截断状态 | 空值、零、无数据和查询失败分别表达 |
| 计算与校验结果 | 指标、分子分母、汇总、差额、容差、校验状态及证据引用 | 确定性计算可用同批输入独立复算 |
| 报告内容 | 已确认事实、分析解释、图表／区块、来源、缺项和限制 | 未证实的业务成因不能写成确定事实；渲染区块受模板支持范围约束 |
| 交付回执 | 实际文件引用、文件摘要、发布状态、访问范围和失败原因 | 文件生成、上传成功、业务发布和用户可下载分别核对 |

## 从案例沉淀的实施要求

1. **查询坐标按指标定义。**实际、预算、面积与租赁指标可能使用不同坐标；查询不到不能直接判断为“没有预算”。返回字段与维度名称的差异，按元数据和已确认别名适配。
2. **汇总按财务定义计算。**平均与期末出租率区分；金额、比率和单价使用确认后的分子分母汇总，不直接平均项目比率；面积单位不同时先换算。
3. **业务范围分别约定。**金额汇总、项目排名、应收和真实项目覆盖可能不同；未归属节点或非业务组织的剔除保留依据，不能只按名称猜测。
4. **数值计算与文字解释分工。**公式、聚合、勾稽和模板渲染由程序执行；Agent 负责理解要求、选择已授权工具、补查和组织说明。Skill 内脚本仍需版本管理和维护。
5. **交付与诊断分开输出。**常规返回完整报告与必要摘要，调试时按需提供完整诊断；不把完整 HTML 和全量调试数据反复回传给模型，也不靠删除指标规避容量限制。
6. **规则版本与业务批准分别记录。**包内快照、文件哈希只证明交付内容，不能证明目标环境已经使用该规则，或财务已批准该口径。
7. **因果解释需要证据。**数据可以分解哪个项目贡献变化；把变化归因于退租、价格或合同条款，仍需相应业务证据。

## 分层验收和交付门槛

| **验收层次** | **验证什么** | **不能替代什么** |
| --- | --- | --- |
| 技术闭环 | 查询结果能传给脚本；实际文件可发布、回读，回执与内容相符 | 不替代公式或业务验收 |
| 同批数据复算 | 使用同一份原始返回，独立计算并核对指标、分解和写入 | 不证明权威数据来源本身完整正确 |
| 回源业务核对 | 父子级汇总、逐月与累计、分子分母、应收账龄与明细等关系 | 不证明所有新期间／组织都在已验范围 |
| 报告与用户验收 | 范围、公式、图表、解释、限制及文件权限满足约定 | 不自动推广为其他客户验收结论 |

原稿记载原项目有 14 条核对关系，可作为参考清单；新项目重新确认适用条目、容差和异常处理，不固定照搬数量。
源数据刷新后核对本次数据快照与计算关系，不要求新报告金额等于历史截图；固定输入复算则应达到约定精度一致。

| **情况** | **处理原则** |
| --- | --- |
| 来源失败、真实截断、组织范围冲突、核心指标缺失、完整输入的关键勾稽不平 | 阻止对应完整报告交付，补取或修复后再核对 |
| 可选比较项缺失、合理舍入、属性对照异常、部分复核证据不足 | 在业务允许的范围内保留可靠内容并披露，不能标为全部通过 |
| 只有重点项目或 Top N 明细 | 明确覆盖范围和占比；不能将样本当全量执行等式核对 |

完整资产报告仍需满足事先确认的核心财务数据等前提，披露机制不能绕过关键前提。
验收记录必须写出实际覆盖的对象、期间、指标、规则版本、数据时点和未完成项。

## 标准交付包与维护责任

| **资产** | **必须包含** |
| --- | --- |
| 场景说明 | 典型问题、使用人、对象／期间、默认指标、交付形式和适用边界 |
| 口径与映射 | 指标字典、模型／维度映射、实际／预算查询配方、单位与聚合规则 |
| 数据接口契约 | 工具入口、参数、返回结构、分页／异步、异常处理和外部脚本依赖 |
| 可安装能力包 | Skill、计算与渲染脚本、模板、依赖及版本清单 |
| 验收资产 | 脱敏固定输入、独立复算、勾稽规则、异常样本和业务验收记录 |
| 报告样例 | 客户认可的标准报告和可对外分享的脱敏样例 |
| 维护说明 | 安装／回退、业务与技术负责人、变更审批和问题处理方式 |

财务负责人批准口径；数据负责人处理源数据、组织及接口问题；实施方维护映射、脚本和模板；平台管理员维护运行能力、授权及交付通道。
新客户复用输入协议、框架、模板和验收方法，模型、科目、组织、版本及过滤规则逐项核实；原始客户材料不直接分发。

首次建立与后续复用分开估算。平台能力齐全时，业务适配可主要通过安装／更新 Skill 完成；业务脚本新增运行依赖时仍需单独核对镜像，不能假设普通代码发布会安装依赖。
