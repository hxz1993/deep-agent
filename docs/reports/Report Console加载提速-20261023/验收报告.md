# Console 加载提速与本地验收

验收基线：`test` 分支，`v0.14.5 / b20cd38`；数据库 Revision `013`。用户最终要求停止追加测速，升级至 `v0.14.6`，提交推送并打 Tag。未执行线上部署；线上加载速度须另行核验。

## 改动范围

| 项目 | 最终行为 |
| --- | --- |
| 一级页面 | 工作台、配置、诊断首次进入才初始化，共享初始化 Promise；快速切页只激活最后选择的页面。 |
| 配置脚本 | 22 个经典脚本并行发起下载，`async=false` 保持依赖执行顺序；模板失败可重试，部分脚本执行失败要求页面重载。 |
| 配置请求 | 按当前标签加载；Agent 列表先展示，可选渠道信息随后补充。编辑器所需目录全部成功后才应用，失败不会当作空关联保存。 |
| 全局设置 | 搜索及解析配置延后至通用设置，运行设置延后至运维，模型目录延后至模型页。延迟响应不覆盖编辑草稿或其他页面。 |
| 字符集 | 运维页只取轻量摘要，点击“检查字符集”才执行完整 SQL；显示检查时间、进行中、结果和错误，未检查不显示为正常。 |
| 用户资料 | 首次展开才读取轻量数据库版本，首屏不请求。 |
| 动画 | 初始只取默认姿态，其他姿态按需加载；加载失败沿用原图标回退。 |
| 静态资源 | HTML 入口与错误 `no-store`；8 MiB 内 UI 资源 `private, no-cache`，每次按实际内容 SHA256 ETag 校验，未变 304。下载、大文件和 Range 保留框架原生响应。 |

唯一新增接口选项为管理员 `GET /api/v1/database-info?include_charset=false`：返回原响应结构，`charset: null`，只查询 Revision，不执行字符集 SQL。省略参数或传 `true` 保持原完整检查，权限及错误处理不变。

未修改业务默认值、配置保存格式、权限规则、聊天执行、工具发现与调用、SSE／History／Live、数据库结构与迁移或依赖。产品版本按最后授权升至 `0.14.6`。未加入跨用户或长期业务缓存，未写 Cloud、Alpha 或真实 BOM 配置。

## 测速方法与结果

使用同一批本地 SQLite 数据、Chromium、1406×1344 视口和带网关前缀的只读代理。固定网络延迟 100 ms、下行 10 Mbps、上行 2 Mbps。修改前静态文件取自固定基线副本；修改后使用冻结源码。两组均访问同一后端数据。

原计划每页 10 次冷缓存、10 次热缓存，前后共 120 次真实导航。冷加载前清空浏览器缓存，热加载使用真实 reload。主要指标是当前页面可操作：配置 Agent 卡片可用、工作台 Agent 选择器就绪、诊断统计加载完成；不把全部后台请求收齐当作首屏完成。请求与字节数统一额外观察可操作后 1.5 秒。

修改前 60 次基线测量已完成，中位数如下：

| 页面 | 冷加载可操作 | 热加载可操作 |
| --- | ---: | ---: |
| 配置 | 7.63 s | 7.27 s |
| 工作台 | 4.49 s | 4.12 s |
| 诊断 | 4.54 s | 4.16 s |

中间版本取得 23 个修改后样本，随后修复了通用设置请求交错问题，这组样本不作为最终效果对比。冻结最终源码后先完成全量回归，用户再要求停止追加测速、直接发布，因此最终修改后 60 次与测试环境前后性能对比均未执行，不报告最终加速百分比。

测试环境仅做了只读连通及权限核验：服务 `0.14.1`、Revision `012`，管理员读取正常；旧服务会忽略 `include_charset=false` 并仍返回完整检查。这不是新版后端验证，不能据此判断新版轻量 SQL 优化的线上效果。没有连接该共享数据库执行迁移或写入。

## 回归结果

以下结果均来自实际执行，定向与全量不重复累加：

- Python 最终全量：3,168 次执行，去重后 3,132 项，其中 **3,118 通过、14 跳过、0 失败、0 错误**；存在 36 次既有重复发现。耗时 1,024.27 秒，已启用真实 MySQL／PostgreSQL 的输出配置、配置导入、逻辑引用、渠道事务和迁移专项。
- 14 项跳过原因为未配置的 Nacos／Discovery／AKSK／RAM 外部环境、macOS 不适用的 Linux／RLIMIT_AS 检查，以及 SQLite 不适用的行锁用例；不能视为这些环境已验证。
- Console 最终全量：**956 通过，0 失败、0 跳过**，含四类未保存编辑页拒绝离开时明确返回失败的回归。

- 真实浏览器：30 项 UI 检查通过，覆盖按页首次加载、首次跨页测试、编辑器目录延迟、全部配置标签、运维手动检查、首次并发导航、快速切页、前进后退、通用设置请求交错、401／403／503 门禁及部分脚本执行失败后重载。
- 真实浏览器缓存：6 项检查通过。热加载观察到 304；相同 URL、长度和纳秒修改时间下替换传递依赖、CSS 与模板，重载仍得到新内容；入口及错误不缓存；404 后创建资源能正常读取。
- 定向后端：52 项通过，覆盖缓存正文与校验、条件请求、文件边界、下载及原生 Range 行为、数据库摘要参数、原默认行为、鉴权和错误。
- 真实数据库专项：SQLite、MySQL 8.4、PostgreSQL 16 各 1 项通过。独立数据库从迁移建立到 `013`；记录实际 SQL，轻量请求只查询 Revision，完整请求沿用原检查，MySQL 覆盖业务文本列字符集判定。

定向用例也会包含在全量中，不重复累加为总通过数。数据库专项在隔离容器及临时库执行，不能把跳过记为真实数据库通过。

首次 Python 全量有一项取消流程超时：取消已在 37 ms 内生效、模型和工具均未执行，随后 SQLite 终态写入等待超过用例 3 秒边界。该用例不经过本轮静态缓存或数据库摘要入口，Runner、数据库及取消测试源码未修改。取消整组独立重跑 18 项通过，保留原断言后第二轮全量也通过。未凭单次日志断言具体锁持有者，首次错误证据保留，不隐去失败。另在复核中修正了本轮切页取消返回值问题，新增断言修复前能失败、修复后 Console 全量通过；之后只改版本与文档。
