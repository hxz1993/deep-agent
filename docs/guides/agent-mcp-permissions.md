# DeepAgent 与 MCP 权限及会话隔离说明

DeepAgent 管理会话、附件和可调用的工具；DeepFOS MCP 使用接入时确定的平台身份调用业务接口，最终由平台接口校验相应权限。使用 Agent 或 MCP 本身不会自动获得管理员权限。

本文主要说明个人平台账号通过 DeepAgent 内置集成使用 DeepFOS MCP 的场景。直接接入 MCP、应用 Key 和渠道接入的身份差异见第三节。这里的 MCP 指 DeepFOS 自研 MCP 服务，不代表所有第三方 MCP 的权限行为。

## 一、DeepAgent：隔离会话并延续用户访问上下文

DeepAgent 负责管理对话、附件和工具执行过程。接入内置 MCP 时，继续使用当前请求的用户身份和业务上下文访问平台。

| 方面 | 处理方式 |
| --- | --- |
| 身份识别 | 使用平台接入层验证后传入的用户身份，确定当前请求属于哪个用户。 |
| 工具范围 | Agent 只装配其配置中已关联的工具包与 Skill；工具可调用不等于获得该工具所访问数据的权限。 |
| 会话隔离 | 会话记录用户及 Agent 归属。普通会话访问检查归属，多个用户使用同一个 Agent 时，各自的聊天历史分别管理。 |
| 文件读取 | 内置文件读取工具仅读取当前会话可用的附件及当前 Agent 已关联的 Skill 文件；文件访问同时遵循对应存储服务的权限检查。 |
| MCP 内置集成 | 将当前用户的认证信息及应用、空间上下文传递给 MCP，使后续平台调用延续本次请求的身份和业务范围。 |
| 管理访问 | 普通会话访问与管理员诊断分开；管理接口通过管理员授权检查后使用。 |
| Python 执行 | Python 执行能力需要单独配置。当前子进程执行后端使用独立进程和临时工作目录，并控制超时、并发和输出大小，执行结束后清理。此类运行隔离不等同于容器或虚拟机级强隔离。 |

### 常见场景

- **多人使用同一个分析助手：**各自创建和访问自己的会话，普通用户不能仅凭另一个会话的 ID 读取其内容。
- **上传报表进行分析：**用户上传报表后，可在该会话继续分析；另一个用户不能通过随意填写文件 ID，让文件读取工具读取这份附件。
- **从业务应用发起分析：**用户在某个应用内向 Agent 提问，Agent 调用内置 MCP 时继续携带该用户及应用信息，由平台接口执行相应权限检查。
- **执行一次 Python 计算：**计算在独立子进程中完成，结束后清理临时执行环境；需要保留的业务结果通过正常结果或文件流程交付。

## 二、MCP：沿用当前账号的平台接口权限

DeepFOS MCP 承接平台工具调用。在继承当前用户身份的接入方式下，每次调用延续该用户的认证信息及应用、空间上下文。使用固定凭据或应用 Key 时，则以对应凭据的有效身份和授权范围为准，不能默认等同于聊天界面上的用户。

| 方面 | 处理方式 |
| --- | --- |
| 账号身份 | 使用本次请求携带的平台认证信息调用接口，不根据模型生成的姓名或用户描述判断身份。 |
| 平台接口权限 | 通过平台接口完成业务操作，沿用相应接口对当前账号的权限检查。例如元素搜索、目录与对象查询、维度成员查询、财务模型查询等，均使用当前账号身份发起调用。 |
| 应用与空间 | 调用使用本次请求或接入配置确定的应用、空间信息；这些信息用于定位业务范围，本身不授予访问权限。 |
| 修改与执行 | 创建、修改、删除及脚本执行等操作，除平台接口权限外，还受到 MCP 副作用开关控制；该开关默认关闭，实际是否开启由部署配置决定；开启后仍须通过平台接口权限检查。 |
| 查询缓存 | 财务模型相关元数据缓存按身份凭据摘要和业务范围区分，避免不同身份直接共用缓存；这不代表权限变更后所有已缓存信息会立即失效。 |

### 常见场景

- **查询业务对象：**用户询问“当前应用有哪些财务模型”，MCP 使用当前账号调用平台接口，再根据接口返回内容组织回答。
- **访问未授权接口或对象：**平台接口拒绝当前账号访问时，MCP 返回相应失败信息，不会自动换用管理员身份重试。
- **切换应用查询：**用户在另一个应用中发起请求时，按该次请求的应用上下文查询，不沿用上一次请求的应用信息。
- **提出修改要求：**只读使用场景下，即使用户要求修改或删除数据，副作用开关关闭时也不会执行相应操作。
- **认证信息失效：**平台接口要求重新认证时，需要恢复有效身份后再继续访问。


## 三、不同接入方式使用谁的权限

| 接入方式 | 身份与权限边界 |
| --- | --- |
| 平台用户通过内置集成调用 | 延续可信平台接入层传入的用户身份与请求上下文，由平台业务接口校验权限。 |
| 直接接入 DeepFOS MCP | 使用该接入实际提供或配置的有效凭据；若多人共用一套固定凭据，下游看到的是该凭据对应的身份，不能声称自动按每位聊天用户隔离。 |
| 使用应用 Key | 按 Key 对应的平台身份及授权范围访问；不会因为聊天正文中声明了某个用户，就切换为该用户权限。 |
| 企微、飞书、钉钉等渠道 | 渠道发送者 ID 与平台用户身份分开。会话按渠道配置的平台账号归属，业务访问按渠道配置的有效平台凭据执行；不能自动理解为每位渠道成员各自的平台权限。群聊也不等于群内每位成员拥有独立、私密的会话。 |
| 第三方 MCP | 是否继承用户上下文、是否使用固定凭据，以及服务端如何鉴权，取决于该 MCP 的配置与实现，需单独确认。 |

例如，若企业希望不同员工只能查询各自授权的数据，应使用能够准确传递个人身份的接入方式；不能通过共用高权限凭据来实现个人权限隔离。

## 四、部署与使用前提

- **身份来源可信。** 生产部署应由可信平台网关验证身份，再转发给 DeepAgent。普通业务接口不能仅因请求携带一个用户 ID 就视为完成身份认证；应防止外部绕过网关伪造身份头直接访问服务。
- **会话隔离与业务数据权限分别控制。** 会话归属限制谁可以访问聊天历史；模型、报表等业务数据是否可见，仍由实际调用的平台接口决定。管理员诊断具有经授权的跨用户访问能力，因此会话隔离不表示管理员也无法查看。
- **配置与数据权限分别控制。** 给 Agent 关联工具只是允许它尝试调用该工具，不授予额外平台权限。副作用开关是额外执行限制，不是逐次人工审批，也不替代平台权限。
- **文件范围按入口区分。** 本文的附件限制针对 DeepAgent 内置文件读取链路；第三方 MCP 或其他执行工具有各自的文件与网络访问边界，不能据此推导为所有工具均无法访问外部资源。
