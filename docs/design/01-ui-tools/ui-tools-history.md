# UI 工具设计历史

> 状态：历史决策记录，不作为当前接口规范

## 最终结论

DeepAgent UI 工具最终只保留两种来源：

- `builtin`：代码内置、只读、不可删除，但需要 Agent 通过 `ui:<name>` 显式选择。
- `manual`：管理员在 Console 创建和维护，同样由 Agent 显式选择。

当前内置工具为 `builtin__confirm` 和 `builtin__choice`。两者不是全局默认能力，
未选择时不会进入模型工具列表。

## 曾评估的方案

早期同时比较过：

1. MCP 暴露约定 Tool 或 Resource，DeepAgent 自动发现 UI manifest。
2. 独立 UI 工具配置 API，由管理员显式维护。
3. 请求体动态携带 UI 工具。
4. 通过 MCP annotation 标识前端工具。
5. 长期 Widget Registry。

其中 MCP 自动发现方案曾进一步设计版本协议、manifest、命名空间、同步接口、缓存和
冲突优先级，也尝试把发现放进保存、手工刷新或 Agent 运行链路。

## 为什么关闭 MCP 自动发现

- UI 渲染契约和 MCP 执行工具生命周期不同，耦合后故障边界不清楚。
- 自动发现会把远端可用性、同步状态和 Agent 运行绑定在一起。
- 空结果、失败、重试和删除语义复杂，容易产生陈旧定义。
- 平台发现工具可能意外暴露给模型。
- 管理员很难判断某个 UI 工具来自代码、数据库还是远端 MCP。

因此后续迁移删除了 MCP 来源的 UI 工具和相关同步配置，运行时不再执行 UI manifest
发现。需要新增 UI 工具时，使用代码内置或管理 API，不恢复后台自动同步。

## 保留下来的原则

- 工具名称稳定，历史事件按当时名称保存。
- Agent 可见性由 capability 明确控制。
- 参数 Schema 和结果 Schema 都是工具契约的一部分。
- Deferred 结果必须通过后端恢复运行，前端不能直接伪造模型结果。
- 内置定义只读，手工定义可维护；同名冲突必须被阻止。
