# 附件上传限制

管理员在「全局配置 → 常规 → 附件上传」编辑单文件大小和单次文件数量。大小为 1～200 MB，数量为 1～20 个，均为整数；1 MB 按 1024 × 1024 字节计算。不带附件的消息仍可发送。

配置保存在现有 `global_settings` 表的一行：Key 为 `attachment_upload`，`version: 1`，JSON 为 `{"max_size_mb":20,"max_count":10}`。读取不到记录或缺少对应字段时，分别使用 20 MB、10 个；查询和启动不补行。原大小和数量环境变量不再生效。

管理员 GET／PUT `/api/v1/global-settings/attachment-upload`：GET 的 `value` 为原保存值（无记录时为 null），`effective_value` 为实际生效值，并返回有效的 `allowed_mimes`、`kinds`、`labels`。PUT 请求为 `{"value":{"max_size_mb":50,"max_count":10}}`，一次原子保存两个字段，保存后应回读。存储失败或无效配置不会伪装成未配置。

每次新增上传、文件发布批次或数量校验读取一次配置，操作内复用，不需要重启，也不保存到会话事件。已有授权文件不会因上限后来调低而失效，读取仍受固定 200 MB 安全上界及解析器／Python 自身更严格的资源限制；新增 Python 产物、文档证据和下载中心新内容按当前上传限额检查。将已有 File ID 登记到下载中心不重复上传。

允许类型只展示、不在此编辑：沿用 `DEEP_AGENT_UPLOAD_ALLOWED_MIMES`、内置白名单及已配置文档解析服务的扩展规则。平台文件服务、渠道和解析服务可能有额外大小或类型限制；热配置不放宽这些独立限制。

Console 未配置时摘要显示 20 MB／10 个，输入框留空并以 20／10 作占位。空项保存时使用对应默认值；恢复默认仅修改草稿。运维页仅保留允许类型。工作台每次上传交互前刷新能力，并合并同批次请求；加载失败阻止此次上传，不用过期值放行。
