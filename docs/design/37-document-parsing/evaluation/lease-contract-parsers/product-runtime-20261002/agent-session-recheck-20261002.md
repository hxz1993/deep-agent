## 真实 Agent 测试范围

复用本地「乳鸽测试」Agent 的模型、提示词和 Skill，通过生产 `chat_stream → build_runner_for_agent → AgentRunner.run_stream` 执行。使用稳定库的私有 SQLite 快照保存测试事件，文档供应商只在测试上下文中覆盖；附件仍通过生产 FileStore 与来源授权读取。请求级 capabilities 只启用 `builtin:document`，避免无关 MCP/UI 工具干扰，本轮不验证这些无关工具。

先使用原问题直接跑 Agent；再通过 FastAPI 路由、真实依赖解析和 ASGI HTTP/SSE 执行，并明确要求按 `next_read` 读至 `has_more=false`。后者是进程内 HTTP 协议测试，没有在用户的 8000 服务上切换供应商，也没有用浏览器发起两家解析。四次均实际提交原文件，未回放历史产物；供应商自身可能命中缓存，尤其 Paddle 首次查询即 done，耗时不能作为冷解析基准。

## Console 与等待控制的改动建议及风险

| 项目 | 已确认原因 | 合理的改动范围／风险 |
|---|---|---|
| 等待像卡住 | Console 显示工具运行中，但不展示供应商排队阶段；每次恢复查询又有 900 秒等待 | 展示排队／解析／下载阶段；同一 Run、同一文件和任务使用累计等待上限。避免模型反复延长等待；保留原任务 ID、不重提交。不自动切换供应商 |
| 最初只见一个工具 | `read_file` 的 ModelRetry 发出 `tool_call_removed`，Console 按现有规则移除；有效工具行按 ID 独立保存 | 属于失败重试隐藏规则；当前页面已显示多次文档与 Python 工具，并非渲染只保留一个。如要保留失败重试提示，应单独调整展示语义，不能把它误记为成功结果 |
| 运行中不能切会话 | `chat.js` 明确阻止主动 POST SSE 期间切换／新建／切 Agent | 分离当前查看会话与后台流所属会话，以固定 session／agent／run 处理事件、停止和收尾。直接移除 guard 会串消息、用量和轨迹，甚至取消错误会话 |
| 切换时终止旧 SSE | 后端 POST SSE 断开会取消 request-owned Run | 切换查看时保留原 POST 在后台；返回原会话复用 run-status／live／history。观察已有 Run 的 GET live 断开可只停止观察。刷新页面的断连语义需要另外界定 |
| 尚未读完却声称全文读完 | 原问题 Paddle 两次读取后直接回答，后续页仍未取完 | 工具／系统说明强调解析页覆盖和本轮读取完成不同，未续读完只能说明已读范围；不能仅因源结果状态 complete 声称已读全部。页面覆盖也不是 OCR 质量保证 |

改动不需要新增数据库结构、环境变量或供应商自动切换。应覆盖运行中切换、切回、并行查看、停止按钮归属、迟到帧隔离、后台完成、取消与断线等回归；仅删除切换 guard 不可交付。
