## 1. 验收口径

- P0：数据、安装兼容、运行终态、权限、不可逆副作用或已承诺默认行为；有失败不发布。
- P1：正式配置/展示/错误回显/性能和各受支持接入；本次范围内必须完成，确有外部条件则逐项说明，不笼统写“基本通过”。
- 既有回归按受影响范围运行，不为文档修改跑生产写测试；开始实施后按阶段从最小单元扩展到真实边界。
- 单元模拟证明确定性规则；真实 Provider 证明其请求/响应行为；真实 API、数据库独立回读和浏览器证明产品闭环。三类结果分别记录。
- 不能把 200、Schema 编译、ZIP 解开、页面显示保存成功、Tag 推送或模型一句“完成了”当作对应功能验收。
- 不改断言迁就实现；确认缺陷后修实现，再重跑相关用例。
- 每个用例报告：ID、代码 SHA、依赖、DB Revision/方言、输入夹具、请求/事件 ID、实际结果、独立回读、通过/失败/未执行及原因。

### 2.2 新旧服务和包

- `OLD` 冻结本次改造前 `552b7b2` 及其实际依赖/安装代码，隔离目录和数据库运行；不得切换、回退或污染当前工作区。
- `NEW` 为实施后候选 SHA，数据库 012；不要把“改过的新解析器模拟旧版”当 OLD。
- `P-OLD-CUBE` 和 `P-OLD-TABLE` 使用仓库真实旧 builtin ZIP，记录原 SHA256，不重打包来配合新实现。
- `P-NEW-OFF` 必须由 NEW 正式导出接口产生；另有 `P-NEW-OFF-DRAFT`（关闭但数据库有定义）。
- `P-NEW-ON` 由 NEW 开启 Agent 正式导出；`P-EXT` 额外包含未知安全字段/文件，其他已认识内容与基包相同。
- `P-BAD` 缺必需文件、已知字段错误、开关/定义矛盾、篡改摘要、危险 ZIP，分别构造而不是混成一个无法归因的包。
- 每次完整安装均做预检→显式新建/覆盖→安装→独立 API/SQL 回读→必要的新聊天验证；失败后比对目标和共享资源摘要。

### 2.3 数据库与外部环境

- SQLite 临时库完成快速迁移/原子性/故障注入；MySQL、PostgreSQL 使用可丢弃隔离库验证真实方言。
- 不首次在共享 Test/Cloud 执行 012；不得在普通服务启动时误连共享库自动升级。
- 日常保留的本地稳定库、会话和附件不可重建或清空。临时目录/库/截图标 `TMP to delete`，结束后清理。
- 真实 Provider 使用已授权测试配置，不输出凭据，不用客户合同。记录具体 model/provider 路由；没有真实可用环境的项明确未执行。
- 浏览器自动化用 try/finally 清理 context/browser/server，不能只关 page；用户主动打开的原型/业务页不当作测试残留关闭。
