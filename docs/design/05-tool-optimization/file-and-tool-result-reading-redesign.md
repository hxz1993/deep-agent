# 两个读取工具的返回量调整

> 2026-10-01；已确认本轮实施范围。最终验证结果以本轮交付记录为准。
> 原设计中的不透明cursor、首次大结果正文及历史去重不属于本轮。
> 不新增环境变量、数据库结构、格式档位、搜索工具或配置入口。

## 结论与实际范围

本轮只调整`read_file`、`read_tool_result`的返回量和共用Token分页实现。
工具名称、内容来源、读取顺序、授权、缓存、过滤和续读语义保持原样。
默认读取不再被文本1000行、Office200项或结果400行提前停止；
显式`limit`继续表示最多多少源项，与Token预算共同约束结果。

| 当前模型配置窗口 | 两工具的单次返回预算 |
| --- | ---: |
| 小于256000 Token | 24000估算Token |
| 至少256000 Token | 48000估算Token |
| 未知或未填写 | 24000估算Token |

直接根据窗口分档，不扣最大输出、不取20%。普通工具结果的外置阈值、2000字符预览和保存链路不改，
读取结果继续跳过二次外置。整轮请求仍由现有上下文检查与压缩兜底。

## 2. 调整前的问题与保留的边界

1. **项数提前卡住。** 400行每行20字符只返回约8000字符；200个短段落也会很快停止。扩大某一个上限不能消除另外一个瓶颈。
2. **字符与Token混用。** 同样50000字符的中文、英文和JSON有不同Token成本。文件读取又豁免普通外置，未使用同一模型预算。
3. **普通结果外置后还需额外调用。** 先得到2000字符预览，模型常需立即回读第一批，增加一轮。单纯扩大预览又会与回读重复。
4. **续读参数复杂。** 文件offset从1开始，结果offset从0开始且指筛选序列；结果还带char_offset、from_end、end_offset、pattern、context_lines。模型必须复制多个字段。
5. **页未必装满。** 当前切分器遇到下一项装不下且本批已有内容时立即停止，只在空批遇到超长项时拆分。这有保护结构的价值，但可能浪费大量容量。
6. **缓存不等于省上下文。** 字节与解析缓存减少I/O；每批内容仍进入模型历史。不同分页不是重复内容，不能为了省Token随意删除。
7. **现有搜索未证明任务收益。** read_file没有搜索；read_tool_result只有字面子串和邻行。大型单行JSON命中字段时可能返回整条巨长行。现有测试证明位置/续读正确，不能证明真实任务质量或调用次数改善。
8. **不存在已接入的文件读取去重保障。** deep_agent_file_key只有定义和测试引用，未查到运行时调用；即便接入，其不同范围key也不等于语义去重。

小批次不减少完整阅读后的正文总量，却增加工具包装、推理往返，以及下一轮再次携带历史的累计输入。例如全文20K Token拆成10批各2K，在每批后都请求模型、且不压缩的简化场景，正文累计输入约110K；一次20K则只需一次带入。这个示例不是最终上下文大小，也不是计费账单；缓存、实际请求顺序与压缩会影响实测。

## 4. 每个工具的具体规则

| 项目 | `read_file` | `read_tool_result` |
| --- | --- | --- |
| 默认读取 | 从当前位置在Token预算内尽量读取 | 从当前位置在同一Token预算内尽量读取；尾读保持尾窗顺序 |
| 源单位 | 文本物理行、DOCX逻辑块、XLSX工作表行 | 外置可读结果的行；JSONL仍按记录行 |
| `offset` | 1-based，意义不变 | 0-based筛选序列位置，意义不变 |
| 显式`limit` | 最大源项数，删除4000/1000人工上限 | 最大源行数，删除2000人工上限 |
| 省略`limit` | 不指定项数限制；结果`limit`仍为整数 | 不指定项数限制；结果`limit`仍为整数 |
| 内容大小 | 取消50000字符返回上限，正文和包装一起估算Token | 同左，包含原始行号和续读参数 |
| 切分 | 优先保留完整行/块/行；单项太大时Unicode字符拆分 | 同左，完整记录能留到下一页时不拆开 |
| 续读 | `next_offset/next_char_offset`不变 | `next_read/previous_read`不变 |
| 搜索 | 保持无搜索 | 保留字面`pattern`、邻文合并与原始行号 |
| 其他边界 | 来源授权、sheet选择、下载与解析缓存、安全限制不变 | handle授权、保存链路、读取缓存、错误与取消不变 |

`truncated_by`仍使用`limit`、`output_size`、`item_size`，不增加新原因枚举或cursor。
下一项放不下时保持完整项留待下一页；单项超长时必须返回非空片段并持续推进。
部分项续读仍使用同一源项位置和`char_offset`，不能用`returned_count`推导下一位置。
尾窗内先用`next_read`正向读完，再用首次返回的`previous_read`选择更早窗口。

## 5. 共用实现与预算核验

两个读取工具共用`files/reading_budget.py`的预算选择器和Token分页器。
在既有请求装配时传入当前模型窗口与既有`TokenEstimator`；不建立第二套模型估算规则。
分页按增长探测和区间收敛选择有界前缀，不为每一行反复估算整份文件；
返回前再次核验完整序列化包装不超过预算。
同时检查估算器的规范JSON与SDK实际序列化文本，避免原生分词器因字段顺序产生边界差异。
巨长首项按字符前缀探测；巨长后续项和尾窗项先做有界探测，避免候选页反复序列化整条长项。
Token分页放在工作线程执行，取消仍向上层传播，线程只处理本页局部数据。

文件的可读内容、顺序和原始位置不改变，不因预算调整添加重复表头或省略标记。
多工具返回累积后，下一次模型请求继续走已有整体上下文检查及压缩。
Run内字节与解析缓存减少I/O，不把不同页正文当作可删除的重复内容。
Office展开量、XLSX单元格/正文安全预算和下载字节上限独立保留。
