# PTC / Monty 执行诊断 · v0.11.2

> 2026-09-24；C12-MONTY；实现状态：测试分支完成。数据库 V7 / Alembic 007 不变。

## 目标与边界

仅增强 PTC `run_code`。轨迹仍只显示一条外层 PTC，现有概览、代码、输入、结果页和其他工具的执行、返回保持原样。内部调用按真实开始顺序显示；循环中多次调用逐次记录，并行调用不被误当成串行。上方显示彩色调用耗时条，下方显示选中步骤详情；不根据代码文本猜测业务依赖关系。

## 数据流

1. 每次外层 `run_code` 建立独立 Collector，通过 ContextVar 传到内部文件/MCP工具包装，按外层 Tool Call ID、Run ID 和会话 ID 关联。内部以官方 CodeMode 的调用 ID 为主键，合并官方调用参数、返回与包装层起止时间。纯计算允许零内部步骤。
2. 使用单调时钟计算外层总耗时、每步耗时和开始偏移；“外部调用覆盖”是内部调用时间区间的并集，不是耗时求和，也不是 CPU 时间。失败、拒绝和取消保留已完成步骤；诊断自身异常只标记记录不完整，不改变业务返回。
3. 成功和失败随外层 ToolReturnPart 的 `metadata.ptc_diagnostics` 保存；取消时复用既有终态消息补全，为未返回的 PTC 附上诊断且不重复创建已持久化返回。强杀进程无法保证收尾，不补造结果。
4. SSE、管理员/本人 Event API 和轨迹导出沿用现有通路，只在允许的 metadata 投影中增加 `ptc_diagnostics`。新记录不重复保存旧 `nested_calls`；UI 仍能读取旧记录的 `nested_calls`。
5. 模型仅接收原工具业务结果。诊断不进入后续模型请求、历史恢复后的请求或上下文压缩；历史指纹也跳过诊断 metadata，避免不必要的深拷贝。内部工具之间的数据传递不截断，截断只作用于落库副本。

## 诊断契约

`ptc_diagnostics.version = 1`。文档含 `session_id`、`run_id`、外层 `call_id`、`started_at`、`summary`、`completeness`、`truncation` 和 `steps`。`summary` 含状态、总耗时、外部调用覆盖时长、内部调用数和失败数。每步保存内部调用 ID、工具名、状态、相对开始时间、耗时，以及分别标记状态的输入、结果和错误摘要。缺少数据用空值表达，不估造原始大小。未知版本在 UI 提示暂不支持，并保留其他页签。

| 限额 | 值 |
| --- | --- |
| 每步输入、输出摘要 | 各最多 8 KiB |
| 单个字符串 | 最多 2 KiB |
| 每层数组/对象 | 最多 20 项；深度最多 6 层 |
| 一次 PTC 新增诊断 JSON | 最多 128 KiB UTF-8 |
| 内部工具调用次数 | 沿用 CodeMode 的 100 次上限 |

先给每步 ID、名称、状态和计时预留预算，再公平分配摘要。有限遍历不对巨大原值做深拷贝、整串序列化或哈希；文件正文、Base64、凭据、二进制不进入诊断。摘要显式区分未采集、截断、脱敏和空结果；总预算落库前再校验。

## Console 展示

只对 PTC 显示 `Calls` 页签，默认页签不变。顶部是一行紧凑统计：总耗时、外部调用覆盖、调用数、失败数。其下按真实起止偏移显示彩色调用耗时条，不显示时间轴或名称左侧标注线；步骤区超过限定高度时内部滚动。下方以两行显示当前调用、状态、耗时及 ID，并用轻量切换按钮打开 `Input / Result / Code`，失败时增加 `Error`；一次只渲染当前页签。默认显示 20 步，点击小文字「加载更多」再显示 20 步。`Code` 引用原 PTC 调用代码，不重复持久化；优先使用可靠行号标记，否则按函数名标记文本匹配位置，未匹配时不编造行号。侧栏沿用用户拖拽宽度，最大 720px，长 JSON 在详情内部滚动。

旧 `nested_calls` 能展示已有状态、耗时和摘要，缺失显示“—”。完全无诊断的历史 PTC 显示“此记录未采集执行详情”。其他轨迹的布局与操作不变。

## 验证与人工验收

真实 Monty 运行覆盖纯计算、串行、并行、循环、多次外层 PTC、重置、参数错误、内部工具失败、拒绝、取消和资源超限；验证实时/历史回读、重复终态、权限与导出脱敏，以及真实模型序列化、历史续聊、压缩三条隔离链路。前端验证 320/480/720px、长列表、长工具名、旧格式和错误状态。验收会话用合成工具而非线上 MCP，保留在现有本地 SQLite：完整流程、部分失败、取消与长列表、历史兼容、图片与 JSON；最后一条使用真实 `load_file_data` 读取本地保留的 PNG 附件，在 PTC 内转换并中转 Base64 给合成接收工具，分别展示小 JSON 与大 JSON。单独标明历史夹具，不修改用户旧会话。

没有新增表、列或迁移；数据库继续 V7 / 007。Provider、思考强度与图片生成不在本次范围内。

本地微基准（Python 3.12 / Node.js，仅衡量摘要和 HTML 生成，不代表完整模型调用）：1 MB 字符串加 10,000 项数组的摘要中位 0.011 ms，原审计摘要中位 1.507 ms；小 JSON 分别为 0.005 ms 与 0.003 ms。100 步诊断序列化约 43.9 KiB；100 步 `Calls` HTML 生成中位 0.087 ms、P95 0.153 ms。浏览器端仍须通过实际 320/480/720px 检查布局与滚动。
