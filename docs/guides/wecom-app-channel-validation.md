## 日志验证

真实 Uvicorn HTTP 请求验证了 `webhook_received`、`webhook_rejected`、`webhook_completed` 三阶段共享 request_id。请求中的合成 Query 标记未出现在访问日志中；请求参数仍交由路由正常处理。

后续合法消息按 request_id、channel_run_id、session_id、agent_run_id 追踪验签、解密、队列、媒体下载/转换/上传、Agent 执行与发送结果。日志不记录签名 Query、密钥、原始 XML、消息正文或文件内容。公网网关的日志格式须独立脱敏。

## Alpha 联调验收

1. 从正式公网域名打开 Console，核对生成的 `/webhooks/agent/channel/{id}` 地址，以及网关原样转发 GET/POST、Query 与 Body；不需要新增基址环境变量。
2. 创建企微应用渠道，保存后复制完整 URL；在企微后台验证 GET echostr。
3. 发一条文本，按关联 ID 核对入口、Run、Events、模型用量及实际应用回复。
4. 分别发送图片、语音；文件需确认企微应用是否实际投递该类型。人工构造的文件回调通过不代表平台一定提供入口。
5. 重复投递同一消息，确认不重复提问、计量或回复；错误签名、禁用渠道和其他渠道类型不得执行 Agent。
6. 核对 Console 续问不冒充渠道发送者，成员姓名仍使用原始 ID。

尚未完成真实公网企微联调，也没有真实 MySQL/PostgreSQL 迁移证据。内存队列不承诺进程重启后的消息恢复。回复为最终文本分段，非机器人流式卡片。
